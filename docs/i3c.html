firmware/i3c_target.pe An I3C SDR target: 7E/W always ACKed; ENTDAA arbitration with PID, BCR, DCR in open drain and the dynamic address with its parity; RSTDAA, ENEC, DISEC; private write with T parity; private read with T = 1 between words and T = 0 after the last, ended early by the controller's Sr. 185 of 512
firmware/i3c_ctrl.pe An I3C SDR controller run by host commands: ENTDAA from a first address (records PID, BCR, DCR, address), broadcast CCC with or without a data byte, private write and read after S 7E/W Sr; the read ends at T = 0 or after n words by Sr. 212 of 512

This protocol was not part of the design when the RTL was written. Both files use only existing instructions (low/high/rel, shout/shout.od, shin, waitp/waitp.to, tset/tsetr/twait, the CRC unit as a parity counter, ld/st, host FIFO); the RTL is unchanged. One hart each. Checked in simulation only, not on a board.

The MIPI I3C Basic specification was not read: MIPI hands it out through a request form. The rules below come from secondary sources (see Sources): chapter 37 of a Microchip PIC18 data sheet whose I3C target module follows the specification, and the Linux I3C subsystem. SCL is lowered to 500 kHz (SDR allows 12.5 MHz), and the SCL and SDA timing limits of the specification are not checked.

Rule Source Firmware
START, Sr, STOP as in I2C; tolerated inside a header or a word Microchip 37.2.4.1 target rxb: SDA falling while SCL high is Sr, rising is STOP, checked again on SCL after SDA changed

Data word: 8 bits and T; on a write T is odd parity (XOR of the data bits with 1) Microchip 37.2.4.3.1 both: the CRC unit with x + 1 counts the parity
On a read T is End-of-Data: 1 more data (the target sends on only if SDA is still high at the next SCL fall), 0 last word; SDA low there is the controller's Sr Microchip 37.2.4.3.1 target prd: T = 1 driven high, then SDA let go while SCL is high; controller pab pulls SDA low while SCL is high after n words
ENTDAA (07h): targets without an address send PID[47:0], BCR, DCR in open drain, the lowest wins; a target that lets go for a 1 and reads 0 has lost; the winner takes 7 address bits and a parity bit, ACKs when it is right; DAA is open drain except Sr + 7E/R Microchip 37.2.6.2 target bcr .. lost; controller daa
The address parity bit is ~XOR(addr[6:0]) Linux i3c-master-cdns.c both
Broadcast CCC: S/Sr, 7E/W, CCC and T, optional data and T; ENEC 00h, DISEC 01h, RSTDAA 06h, ENTDAA 07h Microchip 37.2.7, Table 37-11; Linux ccc.h target: EVT |= data (ENEC), EVT &= ~data (DISEC)

Not implemented: direct CCCs (GETPID, SETNEWDA, ...), IBI, Hot-Join, HDR modes, I2C static address mode, SETMWL/SETMRL limits, error types TE0..TE6 beyond the write parity.

Pins

Both files use P6 = SCL and P7 = SDA. The target releases SCL; it drives SDA low for ACK and ENTDAA zeros, push-pull for read data and T. The controller drives SCL push-pull and SDA as listed above.

Host interface

Target data memory: 0x00 PID (6 bytes, bits 47..40 first), 0x06 BCR, 0x07 DCR (host); 0x08 dynamic address (0: none), 0x09 EVT, 0x0A bytes of the last private write (at 0xA0), 0x0B parity errors, 0x0C private writes, 0x0D private reads, 0x0E bytes to send on a private read (at 0xC0; 0: NACK), 0x0F last CCC, 0x10 in an ENTDAA frame.

Controller host commands (FIFO), answer in brackets: 01h a ENTDAA from address a on [number of devices; PID, BCR, DCR, address at 0xA0 + 9k]; 02h c broadcast CCC [0 ACK, 1 no ACK of 7E]; 03h c d broadcast CCC with a data byte [same]; 04h a n d.. private write [0, 1 no ACK of 7E, 2 no ACK of a]; 05h a n private read of at most n words [status, words read; data at 0xA0]. 0x00 HALF sets the SCL half period in ticks (0: 25, 500 kHz).

Tests

test/test_i3c.py (cocotb). A controller model and a target model written from the sources above, on a wired SDA where every model pulls low or lets go (and may drive high in push-pull phases); every change of SCL, SDA and the chip's SDA enable is recorded. Controls

Each change was made in a copy and run with I3C_TARGET_FW or I3C_CTRL_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
The target does not stop when it loses (jnz lost removed) test_i3c_target the chip takes 08h ahead of the model with the lower PID+BCR+DCR (the bus carries the AND of both IDs)
The target does not check T on private writes test_i3c_target the write with a wrong T stores 3 words and counts no parity error
The controller sends even parity in T test_i3c_ctrl the target models report a wrong T on the first CCC
The controller never ends a read by Sr test_i3c_ctrl the read of 4 words from the model with 10 returns all 10

Limits

  • SCL lowered to 500 kHz (controller), and the target is checked at that rate; the specification's SDR timing (12.5 MHz, tHIGH 24 ns in push-pull) is far beyond a 40 ns tick.
  • Broadcast CCCs only, no direct CCC, no IBI or Hot-Join; the target never starts a transfer.
  • The target's write buffer is 32 bytes; a longer write is accepted and dropped.
  • The controller takes all parameters of a command before the START, at most 32 data bytes.
  • The development found two edge cases worth knowing: the target first took an SDA change 50 ns after SCL fell for a START (its two looks at SCL and SDA are 2 ticks apart; it now looks at SCL again), and the controller model first raised SDA for Sr in the same instant SCL fell, which the target models read as a STOP; it now waits 50 ns.
  • Simulation only: no board, no gate-level run.
