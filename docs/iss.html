tools/peiss/ is an instruction set simulator (ISS) of the core, written from docs/architecture.md and the encodings of tools/peasm.py. test/test_iss_diff.py runs random programs on the RTL and on the model at the same time and compares the whole architectural state at every clock edge (lockstep). Functional coverage decides when the random testing is done, and deliberately broken copies of the RTL (and one broken model) show that the comparison catches errors.

File Role
tools/peiss/isa.py Decode table and the meaning of every instruction
tools/peiss/machine.py Clock-level machine: two harts, synchronizers, FIFOs, memories, pins
tools/peiss/gen.py Random programs that always halt; python3 -m peiss.gen --check N
tools/peiss/env.py Stimulus for runs of the model alone
tools/peiss/cov.py Coverage bins and goals
test/test_iss_diff.py cocotb: random lockstep test, uart.pe and crc.pe in lockstep
test/iss_mutants.py Control runs: mutated RTL copies in a temporary folder, one wrong model

Model

Time

The model steps once per rising clock edge, as the RTL does. Hart 0 owns the first edge after a soft reset and the harts then alternate, so each hart gets one tick (two clocks) per instruction. Everything an instruction reads is the state before the edge; its results are visible from the next edge on, so a store by one hart is seen by a load of the other hart one clock later ("visible to a load of either hart in the next tick"). Protocol pins and ui[7:3] pass two synchronizer flip-flops, so an instruction at edge k sees the level the pin had between edges k - 3 and k - 2.

Since branch int5 the program memory has 1024 words in two segments of 512: the model's PC and return address have 10 bits, the next word and the near branches, djnz and jtab stay in the segment of the PC (isa._seg), and the rows ljmp, lcall, ldx and stx (opcode 0xF) are in the decode table. The model holds the whole 1 KB of the core's shared SRAM (Machine.shm; dmem and fb are its two zero-filled windows), and a stx into pages 2 and 3 follows the frame buffer rule. The generator (gen.py) puts hart 1 at .org 512 in one seed of three, places some subroutines and ljmp blocks in the other segment and uses ldx/stx on random bytes; the test bench fills the rest of the SRAM first, as it has no reset.

Since branch int5 (part A) the chip has two cores. peiss.Chip steps two Machines (one per core, each with its program, shared SRAM and host FIFOs) on the same edges and adds what they share: the pads (the wired AND of four harts, one set of pad registers), the general outputs and the launcher reference (a write of core 0 wins in the same clock), the synchronizers, and two peer FIFOs for rxp/txp (the rows of the host FIFO instructions with bit 2 set): each core sees the counts from before the edge and the other core's push of the same edge lands after both executed, as in pe_fifo. test/test_iss_chip.py runs it in lockstep with the RTL: two random programs per seed (gen.generate(..., peer=True) adds rxp.nb/txp.nb and short loops of gpo and pelsel writes, so that both cores write them in one clock; both programs share the pin roles), the host feeding and reading both cores' FIFOs over SPI, and every edge compares all four harts, both register files, the pads, the shared registers, the six FIFO counts, the synchronizers and the bus.

Since branch int5 part D1 the model has the eight delay line registers of dly.md (Machine.dly, one set for both cores in Chip) and the rows dlyw, dlyr and dlyr.cal: a write lands at the end of its edge, a read of the same edge sees the old byte, core 0's write of a register wins over core 1's in the same clock, a soft reset clears them, and dlyr.cal reads the constant Machine.dly_cal (0x99: in range, 25 taps per clock, the value of the RTL simulation at 770 ps per tap). The model has no delay: it keeps the registers only, so the programs of the lockstep write them with the enable bit 0 (gen.py b_dly, in two-core programs only; the programs for one core are the same text as before, and the three rows stay unreached in test_iss_diff, like rxp and txp). test_iss_chip compares the registers in every clock and fails unless both cores write one register in the same clock with the default seeds.

Since branch int5 the data memory and the frame buffer are one SRAM per core (src/pe_shm.v): a load reads it at the edge that ends its cycle and its byte reaches the register at the next edge, in the other hart's cycle. The model keeps that byte in Machine.late for one edge and writes it after the other hart's instruction, so the register file matches the RTL at every edge; the loading hart cannot see the difference (its next instruction is two clocks away). The model has no host or line-unit access to the SRAM, so it has no steals: the differential test checks that the RTL's sticky steal flag stayed 0 in every seed.

Since branch int6 each hart has the fractional tick generator of tickgen.md: Machine.tg holds one tickgen_model.TickGen per hart (the clock-exact model the generator's own tests compare with the RTL), stepped at every edge with run = the hart's run bit and not halted, and with the write or take of the hart's instruction of that edge; the rows are tfn, tfk, tfm, twait.f and twait.f.nb (group tick). Machine.set_tg_state and tg_state let the differential tests inject the RTL's generator state at the start of a seed and compare all nine registers of both generators (four in test_iss_chip) at every edge. The random programs use the rows only when asked (gen.generate(..., tick=True): test_iss_random_tick, test_iss_chip_random_tick), so the programs of the other seeds are the same text as before.

A stalled instruction (twait, twait.f, waitp, waitp2, rxb, txb, erxw) changes nothing except the timer and the tick generator, which count in every tick the hart runs, stalled or not. The model is exact to the clock: stalls, the timer, FIFO handshakes with the host and the pin bus all match the RTL edge by edge, which is how they are compared.

State

Per hart: r0 to r7, PC (9 bits), return address, Z, C, halted, late, timer, period, timer frozen, CRC, polynomial, timer prescale and the tick count inside a timer unit, the hart's own pin outputs and output enables. Shared: data memory (128 bytes) and frame buffer (128 bytes) as plain memory, input and output FIFO (4 bytes each), general outputs, the launcher's reference pin and polarity, the two synchronizer stages of the protocol pins and of ui[7:3]. The pads are the wired AND of the two harts' drives (docs/dual_role.md): enabled when either hart enables a pin, low when either drives it low. The external bus is the one of test/tb.v: a pin the chip drives shows the chip's level, else the level the test drives, else the pull-up (1).

Instructions

Each row of the decode table holds the name, mask, match, operand fields, the semantic function and the assembly format. Only words the assembler can emit decode; anything else raises IllegalInstruction. A semantic function either completes the instruction or returns a stall cause, and must not change state when it stalls.

The timer rule comes from the doc sentence "each twait ends exactly P ticks after the previous one": with the count read in each tick and then decremented, tset P in tick t loads P, and the twait in tick t + P reads P - (P - 1) = 1. So a period has ended when the count is 1 or less, and a count of 0 means it ended at least one tick earlier: the twait is late, as the doc says, exactly when the code between two twaits takes P ticks or more. waitp.to uses the same "timer has ended" test.

Choices where the documents say nothing (all agree with the RTL, which the lockstep test checks):

  1. ldi, djnz, tget*, ld, the pin instructions other than shin, and the CRC instructions keep Z and C.
  2. Every ALU result sets Z (mov too); and, or, xor, mov and test keep C.
  3. rel clears the output bit as well as the enable: the assembler encodes it as the open-drain form of high, and an open-drain write always leaves the output bit 0.
  4. A blocking rxb/txb also sets Z=0 when it moves the byte.
  5. The timer counts only in ticks the hart runs (run bit set, not halted), including the tick of a halt and the tick in which waitp.frz matches.
  6. When the pin matches in the same tick the timer ends, waitp.to takes the match.
  7. Soft reset clears PCs (hart 1 to START1), return addresses, flags, halted, late, timer, period, freeze, CRC, polynomial, pin outputs and enables, general outputs, the launcher reference and both FIFOs; r0 to r7, the data memory and the frame buffer keep their contents. No instruction runs in the soft reset cycle.
  8. A host byte offered to a full input FIFO is dropped; a pop and a push in the same clock both see the FIFO as it was before the clock.

Scope and limits

  • Not modeled: the capture block, the Ethernet transmitter and receiver, and the predictive launcher. capon, erxon, etx, plaunch and plaunchr raise NotModeled; capoff, erxw, erxl and pelsel are modeled with those blocks idle. The two firmware files that use them (net.pe, spi_device_pel.pe) cannot run in the model.
  • The host SPI protocol is not modeled. The model takes host events where they meet the core: the run bits and soft reset of CTRL, a byte offered to the input FIFO, a pop of the output FIFO. In the lockstep test these come from the RTL's host block, so the model alone cannot predict when a host byte arrives; env.py replaces the host by fixed rates.
  • Program memory is a plain array. The SRAM prefetch of the RTL is invisible by design (docs "Memory choice"), and the lockstep test shows it: every hart executes the word at its PC in the right clock, also after a pause of the run bits and after a soft reset.
  • The test bench loads most programs straight into the SRAM model (backdoor) to save simulation time; the first seed and every 20th use PROG_W over SPI, and the firmware tests always do.

Random programs

gen.generate(seed) builds assembly text for one or both harts (two thirds of the seeds run both) from blocks: straight runs of random instructions, forward conditional skips, djnz loops (some with 256 passes, some nested, some with a twait per pass), timer blocks with one to three twaits, waitp.to and waitp.frz blocks, calls of subroutines placed after the halt, operand pairs at the flag corners (equal, sum 256, 0x80, 0, 1) and polling loops of rxb.nb, txb.nb and the shared "hot" bytes. Values come half from {0, 1, 2, 0x7F, 0x80, 0x81, 0xFE, 0xFF} and half at random. Addresses of ld/st lean towards four hot bytes, so the two harts meet on them, and towards the edges of the address map regions (15 % of absolute, 30 % of register addresses).

Every program ends:

  • Control flow only goes forward, except a djnz back to its own label with a counter the loop body never writes. Subroutines hold no call and end in ret.
  • Every twait and waitp.to follows a tset or tsetr of at most 40 ticks in the same block, with no tset, tsetr or .frz in between.
  • The pins are split per seed into chip pins and test pins. low, high, rel, shout and woe only touch chip pins; waitp without .to only waits on test pins, which the test toggles all the time. rxb and txb end because the host keeps sending and reading.

python3 -m peiss.gen --check 1000 (from tools/) runs 1000 seeds in the model alone: all halt, 499 clocks on average and 6,532 at most, in 2.4 s.

Differential test

At every rising clock edge the test reads the RTL after the edge and the model steps once with the inputs the RTL saw before it. Compared at every edge:

  • for both harts: PC, return address, Z, C, halted, late, timer, period, frozen, CRC, polynomial, timer prescale and unit count (psc, pre), r0 to r7 (u_core.u_hart0/1, u_core.u_rf.flat), and the hart's own pin outputs and enables (u_core.out0_q, oe0_q, out1_q, oe1_q)
  • the slot (which hart owns the next edge), pin outputs and enables (uio_out, uio_oe), general outputs, the launcher reference, both FIFO counts, both synchronizer outputs and the pin bus of tb.v
  • the data memory and the frame buffer, words 0 to 63 and 256 to 319 of the shared SRAM model (u_shm.u_sram.u_sram.i_SRAM_1P_behavioral_bm_bist.memory, branch int5; before, u_data.flat and u_capture.u_mem.flat): the stored byte after every store of the model, all 256 bytes after a store only the RTL made, and all at the end of the seed, with the steal flag (steal_s) 0
  • the byte at the head of the output FIFO at every host pop; at the end, the bytes the host received over MISO must be the bytes the model's FIFO gave, in order.

Inputs taken from the RTL at every edge: CTRL run bits and soft reset (u_host.run, u_host.soft_rst), a byte the host SPI offers to the input FIFO (u_host.byte_valid in the FIFO_W state with u_host.rx_byte), a host pop (out_pop), and the levels the test drives (ext_out, ext_oe, ui_in). At the start of each seed the model takes the RTL state as it stands with both harts stopped (memories, registers, synchronizers), so seeds can follow each other without a hard reset.

RTL only. The test reads internal signals by name, as test_spi.py does for the slot, so it is skipped with GATES=yes. The comparison of the core at gate level is the job of the equivalence check in formal/.

Per seed the host task, over the real SPI link, offers bursts of one to four bytes (some into a full FIFO), reads the output FIFO when uo[1] says it holds data (one byte, or the STATUS count), stops the harts for up to 300 clocks and lets them run again (3 % of its actions), and soft resets the running harts once (1.5 %). The test toggles each test pin with a per-seed probability (1 to 20 % per clock) and ui[7:3] now and then.

Run (from test/, in a Python environment with test/requirements.txt installed):

make COCOTB_TEST_MODULES=test_iss_diff FST=-none ISS_SEEDS=0-199          # random seeds
make COCOTB_TEST_MODULES=test_iss_diff FST=-none ISS_SEEDS=0-0 ISS_COV_GOAL=1   # until covered
make COCOTB_TEST_MODULES=test_iss_diff FST=-none COCOTB_TESTCASE=test_iss_firmware_uart
python3 iss_mutants.py --seeds 0-79 --jobs 3                                # controls

ISS_OUT (default sim_build/iss) receives summary_<first>_<last>.json with the coverage counts and, on a mismatch, fail_seed<N>.txt with the differing fields, the last 48 instructions of the model and the program. For parallel runs give each its own SIM_BUILD and COCOTB_RESULTS_FILE.

Coverage

cov.py counts, for every instruction the model runs in the lockstep test:

  • every instruction of the decode table except the five not modeled (64 rows, with each suffix form such as shout.lsb.od or waitp.to.frz its own row)
  • the flag results each flag-writing instruction can give: all four (Z, C) pairs for add, addi, shl, shr; three for sub, cmp, cmpi (equal operands never borrow, so Z=1 with C=1 cannot happen); Z = 0 and 1 for those that keep C (mov, and, or, xor, test, shin, .nb FIFO forms, waitp.to); Z = 0 for blocking rxb and txb, Z = 1 for erxw (no frame without the receiver)
  • taken and not taken for jz, jnz, jc, jnc, djnz
  • each stall cause (twait, waitp, rxb, txb); twait late, on time at once, on time after a stall; waitp.to ending by a match and by the timer after stalling; .frz matches; tset 0, tset 1, tsetr; timer reads while counting and while frozen
  • crc and crc.lsb with every bit count 1 to 8
  • ld and st, absolute and register address, in each region they can reach, and each at the edges of the regions: 0x00, 0x1F, 0x20, 0x7F (last absolute address), 0x9F, 0xA0, 0xFF
  • push-pull, open-drain release and open-drain drive low
  • host bytes taken and dropped at a full FIFO, a pause of the run bits, a soft reset while running (these two counted by the bench)
  • two harts: a store by one and a load of the same byte by the other in the next clock (and load then store, store then store), txb by both in neighbouring clocks, the same for rxb, pin writes and CRC instructions, one hart stalled while the other completes, both stalled, a call while the other hart is inside a subroutine.

Firmware in lockstep

test_iss_firmware_uart runs firmware/uart.pe on both harts: the host sends "Hi!", which hart 0 sends on P0 at 100 clocks per bit, and the test sends "OK" on P1, which hart 1 passes to the host. RTL and model run in lockstep; the pin bus logs of both are equal edge for edge, the host gets "OK" and the RTL's P0 decodes to "Hi!". Then the model runs alone with its own host timing (a byte every 97 clocks while there is room): its P0 frames carry the same bytes with the same transitions at the same offsets inside every frame (6, 8 and 6 transitions for 0x48, 0x69, 0x21), and every transition lies a whole number of bit times (100 clocks) after its start edge, so each bit is exactly 100 clocks. test_iss_firmware_crc runs firmware/crc.pe in lockstep for CRC-16/CCITT-FALSE (register 0x29B1) and CRC-16/USB (register 0x4B37, inverted 0xB4C8) of "123456789", the catalogue check values. Both tests load the firmware with PROG_W over SPI.

Controls

test/iss_mutants.py copies src/ into a temporary folder, changes one line, and runs the random lockstep test (seeds 0 to 79, stop at the first mismatch) against the copy. The last control keeps the real RTL and gives the model a wrong meaning. Every control must FAIL; all do (python3 iss_mutants.py --seeds 0-79 --jobs 1, 1 min 42 s in all):

On adv the list has six more controls for the new hardware (pin_high_wins, pin_shared_oe, adc_no_cin, par_7bit, jtab_no_plus1, tpre_ignored), and shout_od follows the per-hart register names; the adv results are in "The adv extensions in the model" below.

dm_map_a0 first escaped: 80 seeds passed. Coverage then only had a bin per address region, and no ld/st touched the edge byte 0xA0. The region edges became coverage goals and the generator now picks them often (see Random programs); the same mutant then failed at seed 37. In a first control run that included the firmware tests, djnz_predec and twait_end also failed in test_iss_firmware_uart (hart 1, the receive loop of uart.pe).

Findings: documents against RTL

No difference in behaviour was found between the model, written from the documents, and the RTL: every seed and both firmware runs agree at every clock. Where the documents are silent the RTL does what the model's choices above say. Differences in the text:

The adv extensions in the model

The adv branch added per-hart pin registers (the pins are the wired AND of both harts), a timer prescaler per hart (tpre), adc, sbc, cpc, rlc, rrc, par and the table jump jtab (docs/architecture.md, Extended instructions). In the model:

Change Model
Pin registers per hart Hart.out, Hart.oe; low, high, rel, shout, wrp, woe write the running hart's own pair; Machine.pin_out and pin_oe are pad registers that follow the wired AND of the two (high only when some hart drives high and none low), with the two staged moves of the pad timing rule (docs/dual_role.md, branch int3): release -> high sets the output bit one clock before the enable, high -> release clears the enable one clock before the output bit
tpre n Hart.psc = n, Hart.pre = 0. The count drops only when pre is at the last tick of the unit (Hart.ptick), and twait/waitp.to end only there; pre counts in every tick the hart runs and restarts at tset, tsetr, tpre
adc, sbc, cpc C in; C out is the carry, or the borrow for sbc/cpc; Z from the 8-bit result; cpc writes nothing
rlc, rrc rotate through C
par ra,rb Z = (ra AND rb) is 0, C = its parity; nothing written
jtab rs PC = PC + 1 + rs modulo 512

The generator emits the new instructions in its random runs and flag corners, a jump table block (an index of 0 to N-1 into N jmp entries), a prescaled timer block (tpre 0 to 3 mostly, 4 to 7 now and then, so waits stay at most 128 times longer) and a block that drives one chip pin for a while; both harts use the same chip pins, so their drives meet on one pin. Coverage adds the flag results of the new instructions, C in 0 and 1 for each instruction that reads it, the first and a later jtab entry, tpre with every n, a twait on time and late and a waitp.to timeout while prescaled, a timer read while prescaled, and the nine pairs (release, low, high) of the writing hart's drive of a pin against the other hart's drive of the same pin: 260 goal bins in all.

Change Model

Adding an instruction

For each new instruction:

  1. Add a row to _rows() in tools/peiss/isa.py with the mask and match of its encoding in peasm.py, the operand fields and a semantic function. New hart state goes into Hart (and Hart.state(), STATE_FIELDS), new shared state into Machine.
  2. Let gen.py emit it (a filler entry, or a block if it needs set-up) and add its flag results to FLAG_GOALS in cov.py if it writes flags.
  3. If it adds RTL state, add the signal to Probe in test/test_iss_diff.py so it is compared.
  4. Run python3 -m peiss.gen --check 1000, then the lockstep test until the coverage goal is met, then iss_mutants.py with a mutant of the new instruction.
