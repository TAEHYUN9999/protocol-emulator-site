The chip records what happens on the eight protocol pins P0 to P7 (uio[7:0]) without any firmware: the host configures and arms it over the host SPI link, and reads the record back. It is the tool for taking down an unknown protocol before writing a firmware for it, and for checking a firmware's pins from inside the chip.

Default mode Deep mode
Memory SRAM macro u_capmem (512 x 16), words 0 to 31 (branch int5; before it the 64 x 16 flip-flop frame buffer, words 0 to 31) u_capmem, all 512 words
Entries 32 512
Trigger (pattern, edge) yes yes
Pre-trigger ring no 0 to 448 entries before the trigger, in steps of 64
Paused while the Ethernet transmitter is busy yes no
Read with CAP_R word address 0 to 31 (see Default capture in the SRAM) CAP_R with bit 7 of the first address byte set

The default mode is the capture of the earlier versions: a host that sends the old two-byte CAP_CFG gets the old entries, entry for entry, and reads them with the old CAP_R. Since branch int5 they are kept in the capture SRAM instead of the frame buffer; the three differences are listed below.

Default capture in the SRAM (branch int5)

The default capture can write an entry in any clock, so it cannot share a single-port SRAM with the harts' ld/st the way it shared the flip-flop frame buffer. It now records into u_capmem words 0 to 31, like a deep capture without pre-trigger, and the frame buffer keeps only frame data. CAP_R keeps its meaning through a 32-bit view (capview in pe_capture.v): bit w is set when a default capture writes entry w and cleared when anything writes frame buffer word w (ETH_W, a hart's st, a receiver); arming a deep capture clears all 32. CAP_R of word w reads the capture SRAM while bit w is set and the frame buffer otherwise, so a host sees the same words as before in every sequence that does not mix the three cases below. The host gives the SRAM the word address one clock ahead, as for the deep entries (cap_draddr in pe_host_spi.v), and keeps the view bit of that word with it (cap_vq).

What differs from the earlier versions:

  1. A hart's ld at 0x20 to 0x5F reads the frame buffer, not the entries. No firmware of the repository uses capon/capoff (0 of 129 files), and none reads entries with ld.
  2. ETH_TX (or etx) after a default capture sends the frame buffer as the host or the firmware wrote it, not the entries.
  3. A default capture and a deep capture now share the SRAM: a default capture overwrites deep entries 0 to 31, and arming a deep capture ends the view of the default entries (CAP_R then reads the frame buffer words, which the default capture no longer overwrites).

As for the deep entries, a CAP_R read in the same clock as a capture write gets the written word, so read the entries after the capture has stopped.

Entries

The capture stores an entry only when a watched pin changes (the pin mask), so 512 entries can cover a long stretch of a slow protocol and still resolve the fast edges. Each entry is one 16-bit word:

Bits Meaning
15..8 the eight pins after the change (all eight, also the ones not watched)
7..0 dt: prescaler ticks since the previous entry, not counting a tick in the clock of an entry

A tick is 2^n clocks (prescale n = 0 to 15, 20 ns to 655 us at 50 MHz); the prescaler restarts at arm, so the same pin pattern after an arm always gives the same dt values. When 256 ticks pass without an entry, a filler entry with dt = 255 is written (its pins are the current pins, so for the watched pins it is not a change). A change in the same clock as that 256th tick is one entry with dt = 255.

The time from one entry to the next is dt x 2^n + 1 clocks: exact at prescale 0, and within 2^n - 1 clocks of the true time at prescale n (the tick grid is fixed from the arm, an entry can fall anywhere between two ticks). The pins pass a two-flip-flop synchronizer first, so every entry is two clocks late; the spacing is not affected.

To rebuild the waveform: the oldest entry read is time 0; add dt x 2^n + 1 for each later entry; keep the entries whose watched pins differ from the previous entry. test/test_capture_deep.py (entry_times, rebuild) does exactly this.

Trigger

The capture waits, armed, for the trigger. The trigger is the first clock in which

  • the pins match the pattern, (pins & tmask) == (tval & tmask), and
  • with an edge selected: the edge pin makes that edge (rising, falling or either) in that clock; with no edge selected: a watched pin changes in that clock.

That clock writes the trigger entry, and the capture records until the memory is full (32 or 512 entries), or until CAP_STOP. With tmask = 0 and no edge, the trigger is the first watched change, which is the old behaviour. Examples:

Trigger tmask tval edge byte
any watched change (default) 0x00 - 0x00
UART start bit on P0 0x00 - 0x10 (falling, pin 0)
I2C START, SCL = P0, SDA = P1: SDA falls while SCL is high 0x01 0x01 0x11 (falling, pin 1)
SPI chip select P5 goes low 0x00 - 0x15
four-bit bus P0..P3 equals 0xB at a change 0x0F 0x0B 0x00

The edge pin does not have to be watched: an edge on it alone writes the trigger entry (the watched pins in it are unchanged). The pattern and edge are read live, mask and prescale too; deep mode and the pre-trigger size are taken at arm.

Pre-trigger (deep mode)

With pre = k (1 to 7), the capture records from the arm on, changes and fillers alike, and keeps the newest 64 k entries in a ring (writing number w goes to SRAM word w mod 512; the oldest is dropped when the ring is full). At the trigger the ring stops dropping; the trigger entry and the entries after it are added until the memory holds 512 entries. The trigger index (STATUS bytes 9, 10) is the number of entries kept before it: 64 k once at least that many came, fewer if the trigger came early. With pre = 0 nothing is recorded before the trigger and the trigger entry is entry 0 with dt = 0, as in the default mode.

Host commands

Command Bytes Notes
0x30 CAP_CFG pin mask, {pre[2:0], deep, prescale[3:0]}, then optionally tmask, tval, {0, 0, 0, falling, rising, edge pin[2:0]} The second byte clears tmask and the edge, so a two-byte CAP_CFG means no trigger, as before. Bytes after the fifth are ignored.
0x31 CAP_ARM none Also capon from a hart. Ignored while the Ethernet receiver owns the frame buffer.
0x33 CAP_STOP none Also capoff. Keeps the entries, the count and the trigger index.
0x32 CAP_R default: word address (0 to 63), then hi, lo pairs Unchanged: capture entries in words 0 to 31, the frame buffer in 0 to 63; bit 6 is ignored.
0x32 CAP_R deep: 0x80 \| entry[8], entry[7:0], then hi, lo pairs Entry 0 is the oldest one kept, so entries come out in time order; the auto increment wraps from 511 to 0.
0x03 STATUS bytes 7 to 10 added 7: {triggered, deep, 0 x4, count[9:8]}, 8: count[7:0], 9: {0 x7, trigger index[8]}, 10: trigger index[7:0]. Bytes 0 to 6 are unchanged (byte 0 bits 1..0 = capture state: 0 idle, 1 armed and waiting for the trigger (recording already with pre-trigger), 2 recording after the trigger; byte 4 bits 5..0 = count mod 64). Bytes 11 to 15 read 0x50; the 16 bytes repeat.

A typical deep capture with a trigger, as test/test_capture_deep.py does it:

30 03 30 01 01 11      CAP_CFG: watch P0, P1; deep, pre 64 (0x30 = pre 1, deep); trigger SDA falling while SCL high
31                     CAP_ARM
                       ... poll STATUS byte 0 until the state is 0, or send 33 (CAP_STOP)
03 + 11 x 00           STATUS: bytes 7 to 10 give the count and the trigger index
32 80 00 + 2n x 00     CAP_R deep from entry 0: n entries, hi then lo byte each

Read the deep memory after the capture has stopped (STATUS state 0), or while it waits for the trigger without pre-trigger. While it records, the capture owns the SRAM port and a read in the same clock as a write gets the written word; fillers keep coming during a recording even when the pins are quiet.

Compatibility

What an existing host sees:

  • CAP_CFG with two bytes, CAP_ARM, CAP_STOP: as before (a prescale byte above 15 now selects deep mode or pre-trigger; the existing scripts send 0 to 8).
  • CAP_R with an address byte below 0x80: as before, but for the three cases of Default capture in the SRAM. An address byte of 0x80 or more used to read word address & 0x3F; it now starts a deep read. The repository's scripts use 0 to 61.
  • STATUS: bytes 0 to 6 as before; byte 7 was 0x50 and is now the deep capture byte, and the bytes repeat every 16 instead of every 8. The repository's scripts read at most 7 bytes.

The 21 earlier cocotb modules pass unchanged on this RTL: 144 of 144 tests (with the new module, 22 modules and 152 tests, all pass).

Hardware

  • src/pe_capture.v: the capture, both modes: the trigger compare, the ring pointer (base, the SRAM word of entry 0), the read address (base + entry) and, since int5, capview (32 flip-flops) for the default entries.
  • src/project.v: u_capmem, a second instance of the SRAM wrapper pe_progmem (RM_IHPSG13_1P_512x16_c2_bm_bist). The capture writes it, only the host reads it; the harts' ld window 0x20 to 0x9F is the frame buffer.
  • src/pe_host_spi.v: the extra CAP_CFG bytes (the STATUS byte counter is reused as the CAP_CFG byte index), the two-byte CAP_R address (one flag), STATUS bytes 7 to 10. The host state machine still has 32 states, so its binary encoding and the gate-level equivalence lemma on it (formal/run_equiv_gl.sh) stay as they are.
  • src/config.json: u_capmem.u_sram at (349.2, 40) up to branch int4 and at (686.4, 40) since int5 (the core's shared SRAM u_shm took k = 5), orientation FS, a multiple of 5 x 67.44 um right of the program memory, so the Metal4 power stripes pass through its power columns at the same local x as through u_prog.u_sram (checked from the LEF: four stripes each for VDD!, VDDARRAY! and VSS!, 0.02 um to the column edges, 0.28 um to the Metal4 OBS beside them).
  • The FPGA build and the XSim bench replace the macro by name with a block RAM model (fpga/common/RM_IHPSG13_1P_512x16_c2_bm_bist_fpga.v), so the second instance becomes a second block RAM without further changes. Self test section 16 (fpga/gen_script.py) runs a deep capture triggered on the chip's own UART start bit and checks the STATUS bytes and the dt of the entries. In the FPGA system simulation (fpga/sim/tb_fpga.v, Icarus, block RAM model) sections 1 to 16 pass twice; with the falling-edge test inverted in pe_capture.v it fails in section 16. On the board it passed with the int3 RTL (bit ec1fa2bd, 2026-11-12): sections 1 to 16, 279 passes, 0 fails (verification.md, section 9).

Area, from a Yosys synthesis of the whole design with the IHP typical library (macros left out; the flow's numbers after placement are larger by the buffers it adds): 298,702 um2 of cells before, 303,412 um2 after, +4,710 um2 (+1.6 %), of which 57 flip-flops (capture and host interface). The macro adds 236.8 x 191.34 = 45,309 um2. Together about +50,000 um2, +4.1 percentage points of the 8x4 core area (1,208,173 um2).

Verification

  • test/test_capture_deep.py, 8 tests: 40 random UART bytes with idle gaps (253 entries, fillers included); an I2C write with a START trigger and a 64-entry pre-trigger after 84 non-trigger changes; the pre-trigger boundary at 63, 64 and 65 earlier changes and with no pre-trigger; a 448-entry pre-trigger after 600 changes that wraps the SRAM and fills all 512 entries, read also across the end; 600 changes without trigger (stops at 512); fillers at gaps of 255 to 1,000 clocks and the time error at prescale 3; pattern, rising, falling, either edge, edge with pattern, an edge on an unwatched pin, and the pattern trigger in default mode; the old capture test after a deep capture, the frame buffer left alone, the STATUS layout and soft reset. Each capture is judged against a spec model of the entry rules (model_capture), against the driven waveform rebuilt from the entries, and, for UART and I2C, by decoding the protocol from the rebuilt waveform.
  • Planted bugs, each a one-line change in a copy of the RTL, each must fail the module. All six fail:
Change Tests that fail
pe_capture.v: drop compares count with {pre_q, 6'd1} (the ring keeps 65) 3 (I2C, boundary, wrap)
pe_capture.v: rising edge tested as falling (!epin && elast) 4
pe_host_spi.v: cap_draddr without the look-ahead in S_CR_ADDR 1 (the read from entry 510)
pe_capture.v: deep capture ends at 511 entries (9'd510) 2
pe_capture.v: mem_addr reads at draddr without base 3
pe_host_spi.v: CAP_CFG byte 2 does not clear the trigger mask and edge 1 (default mode)

The six are lines cap_* of test/controls.sh (test/controls.sh 4 cap_), each with one test that it fails; on the integrated RTL (branch int1, and again on int2 with the USB line unit; revisions) all six fail again (2026-11-11).

  • Branch int5 (default capture in the SRAM), 2026-11-12: test_capture_deep 9 of 9 with the new test_default_capture_view (entries 0 to 2 through CAP_R with word 3 still the frame buffer, a hart's ld of the frame buffer bytes, ETH_W and st ending the view of one word each, a new default capture, and a deep arm ending every view), test.py 19 of 19. Four more planted bugs in test/controls.sh, so test/controls.sh 3 cap_ runs ten, and all ten fail: cap_view_never (CAP_R always reads the frame buffer: test.test_event_capture), cap_view_kept_on_deep_arm and cap_view_kept_on_fb_write (test_default_capture_view), cap_view_no_lookahead (the default-mode word address one clock late: test_default_mode_unchanged); cap_draddr_no_lookahead was rewritten for the new address expression and still fails its test.

  • formal/run_formal_capture.sh: the capture against a reference model written from this page, with both modes, the trigger, the pre-trigger size and Ethernet busy as free inputs. The model checks the state, the count, the trigger flag and index, one symbolic flip-flop word (entries and frame buffer; a deep capture must leave it alone) and the SRAM port: write number w goes to word w mod 512, and a read of entry e addresses the word of write number base + e. Unbounded proof (ABC dprove) in 358 s; reachability traces of 34 clocks (32-entry fill), 69 clocks (ring drop, trigger at index 64) and 514 clocks (512-entry fill); 15 planted bugs caught (formal/logs/capture_20261111). Branch int5: the model's flip-flop word now takes only host writes, the SRAM port must carry the writes of both modes, and the capview bit of the symbolic word must follow the three rules above (and a word in view must read SRAM word = entry, that is base = 0). Unbounded proof in 18 s, the same three traces (34, 69, 514 clocks), and 19 planted bugs caught: the 13 earlier ones that still apply, the old "default write lands in the frame buffer" bug (now it sets capview in deep mode) and five new ones on the SRAM write enable and capview (formal/logs/int5_b0_20261112/capture.log). On the area-reduced RTL (2ad37f2, src 7ba97c50): unbounded proof in 16 s, the three traces (34, 70 and 514 clocks; the ring trace one clock longer than before) and the 19 planted bugs caught (formal/logs/capture_20261119_010048); the script now runs dffunmap before the AIG, because the reduced pe_capture has flip-flops with a synchronous reset, which Yosys folds into $_SDFF_ cells that write_aiger does not take.

The first deep capture in the FPGA simulation measured something about a firmware: firmware/uart.pe sent its start bit 102 clocks long and every later bit 100 (dt 101, then 99), because the ldi r1, 8 between the start bit's twait and the first shout added one tick (2 clocks) that the later bits, paced by twait alone, did not have. At 500 kbaud that is 2 % on one bit, well inside what a UART receiver takes. Branch mem512 has since fixed uart.pe (commit 803fe67: every edge one tick after a period boundary), and on the integrated design section 16 checks the start bit too (dt 99): sections 1 to 16 pass twice in the FPGA system simulation, and with the uart.pe from before the fix it fails in section 16 (got 65, want 63).
