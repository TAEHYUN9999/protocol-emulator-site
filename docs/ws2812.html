File Role Words
firmware/ws2812.pe Drives a chain of WS2812B addressable LEDs from one pin: the host sends the colour bytes, the chip stores them, sends them with the one-wire pulse-width code and latches them. 36 of 512

This protocol was not part of the design when the RTL was written. It uses only existing instructions (twait grid, shout, ld/st to the frame buffer, host FIFO). It was added on the RTL of commit a2aad45 without changing it; the 512-word program memory added later (f08b33c) kept the instruction format, so the program assembles to the same words and its tests pass on the current RTL too. Checked in simulation only, not on a board.

Pins

Pin Use
uio[0] (P0) DIN of the first LED, driven low between frames

Before the firmware's first instruction the pin is an input. A pull-down on DIN keeps the first LED from seeing a high level at power-up.

Line code

From the WS2812B-V5 datasheet (Worldsemi), data transfer time:

Datasheet Firmware (SLOT = 8 ticks = 320 ns)
T0H, 0 code high 220 to 380 ns 320 ns
T1H, 1 code high 580 ns to 1 us 640 ns
T0L, 0 code low 580 ns to 1 us 960 ns
T1L, 1 code low 580 ns to 1 us 640 ns
RES, frame end more than 280 us 300 us

Each bit is four slots on the twait grid: high, the bit (shout, MSB first), low, low. The next byte is loaded from the frame buffer during the fourth slot, so the bytes follow each other without a gap. With one 40 ns tick, 8 ticks is the only slot width that meets all four windows (the test sweeps 5 to 10). Each LED keeps the first 24 bits it receives, G7 to G0, R7 to R0, B7 to B0, and passes the rest on.

Host interface

Direction Bytes
Host to chip (FIFO) n (1 to 128), then n colour bytes, first LED first, G R B per LED. n = 0 is ignored.
Chip to host n, after the latch time has passed

The bytes go to the frame buffer (0x20 + i) before the first bit is sent, so the line timing does not depend on how fast the host writes the FIFO. 128 bytes are 42 LEDs plus 2 bytes. A frame of 128 bytes takes 1.31 ms plus the 300 us latch.

Data memory 0x00 (SLOT, host DATA_W before the run): ticks per slot, 0 = 8. Below 6 ticks the byte step does not fit in the fourth slot and the STATUS late flag of hart 0 is set.

Tests

test/test_ws2812.py (cocotb). The receiver model is written from the datasheet table above, not from the firmware: every high pulse must fall in the T0H or T1H window, every low after it in T0L or T1L, and a low of more than 280 us ends the frame. An LED chain model then gives each LED its 24 bits. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_ws2812
Test What Result (2026-11-10)
test_ws2812_frames 4 LEDs, three frames (primary colours and white, all off, random), every pulse in its window, colours, answer, late flag PASS: highs 320 / 640 ns, lows 640 / 960 ns, 0 errors
test_ws2812_full_buffer 128 bytes: 42 LEDs right and the last 16 bits passed on PASS
test_ws2812_slot_sweep SLOT 5 to 10: late flag, datasheet windows, bits PASS: only 8 meets the datasheet; late only at 5

Controls: the same test with the firmware changed to LSB first fails on the random frame (colours differ; the first two frames are 0x00 / 0xFF bytes and do not show bit order), and without the fourth slot it fails with 47 lows of 320 ns.

Rerun of the whole module on commit b4edcc2 (2026-11-12 00:26, Icarus Verilog 11.0, cocotb 2.0.1, RTL, two simulations sharing the machine): test_ws2812 TESTS=3 PASS=3 FAIL=0 SKIP=0, 45 s wall; every test listed above passed.
