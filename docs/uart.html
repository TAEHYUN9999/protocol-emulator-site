Start both harts together (CTRL 0x01 with value 3): the transmitter clears READY in its first instruction and waits for the receiver to set it.

Pins

Pin Use
uio[0] (P0) TX, driven high when idle
uio[1] (P1) RX

The pin numbers are .equ TX and .equ RX. They cannot be run-time settings, because a pin number is a field of the low/high/shout/shin/waitp instructions.

Settings (data memory, host DATA_W before the run)

Address Name Meaning Value 0 means
0x00, 0x01 BITH, BITL Bit time in ticks (one tick = 2 clocks = 40 ns at 50 MHz), 16 bits, high byte first. Range 8 to 43690. 50 ticks (.equ BIT, 500 kbaud)
0x02 NBITS Data bits, 5 to 8 8
0x03 PAR 0 none, 1 odd, 2 even none
0x04 STOP Stop bits sent, 1 or 2 1
0x05 AUTO 1: measure the bit time first (see Autobaud) off
0x06 READY Written by the firmware: 1 once the bit time is final
0x07 OVR Written by the firmware: received characters dropped because the FIFO to the host was full. Cleared at start, stops at 255.
0x08 Firmware scratch

With all eight bytes 0 the firmware behaves like uart.pe (50 ticks, 8N1). The receiver writes the values it uses back to 0x00 to 0x04 (defaults filled in, or the measured bit time), so DATA_R shows them. Examples of bit times: 115200 baud = 217 ticks, 1 Mbaud = 25 ticks.

Host interface (FIFO)

Host to TX: every byte written with FIFO_W (0x20) is sent as one frame; bits above NBITS are ignored. When the next byte is already in the FIFO at the stop bit, its start bit follows the last stop bit directly; otherwise the line stays idle until a byte comes.

RX to host (FIFO_R, 0x21):

Bytes Meaning
c (not 0xFF) Character c, no error
0xFF 0xFF Character 0xFF (only possible with 8 data bits)
0xFF 0x01 c Framing error: the first stop bit was low
0xFF 0x02 c Parity error
0xFF 0x03 c Framing and parity error
0xFF 0x04 0x00 Break: start, data, parity and first stop bit all low

This is the same idea as PARMRK in POSIX terminals: an escape byte that is doubled when it is data. A plain character costs one FIFO byte. After a framing error or a break the receiver waits until the line is high before it looks for the next start edge. 0xFF 0xFF and the error reports are never split: their second and third bytes wait for room in the FIFO.

Frame timing

Transmitter: every edge of a frame is an exact multiple of the bit time after the start edge (the test checks each edge to the picosecond).

Receiver: it waits for the falling edge of the start bit, then samples each bit in its middle: the first sample comes B + B/2 ticks after the tick in which the start edge is seen (a timer wait of B + B/2 - 5 plus 5 fixed instructions), the next ones every B ticks. It checks only the first stop bit, whatever STOP says, so it accepts frames with one or two stop bits. Data bits are shifted into the CRC register with the polynomial 1 << (NBITS + 7), which right-aligns them in one crc.lsb instruction for every data length, and the parity is accumulated with an xor per bit.

Autobaud

With AUTO = 1 the receiver waits for a training character whose data bits 0 to 3 are 1, 0, 1, 0 (for example 0x55, 'U', in any of the formats). It measures the time from the start edge to the falling edge of data bit 3 (four bit times) with the frozen timer, so B = (elapsed + 3) / 4 rounded, then writes B to BITH/BITL, sets READY and uses B for both directions. The training character is consumed (not sent to the host). The line must then stay high for two bit times (the stop bit counts) before the next character; the test leaves two idle bit times after the stop bit. Bytes the host writes before READY wait in the FIFO and are sent at the measured speed.

Overrun Counted at 0x07, tested (6 characters into a 4-byte FIFO: 4 delivered, OVR = 2)
Full duplex Supported, both harts at once
Fastest full-duplex bit time 8 ticks (320 ns, 3.125 Mbaud), measured for 8N1, 8E1, 8O2, 7E1, 5N1, 5O2 with 4 frames back to back in each direction, 2 phases of the sender. At 7 ticks the receiver fails (its first-sample timer wait, B + B/2 - 5 = 5 ticks, is shorter than the 5 or 6 instructions it runs in that wait; hart 1 late flag set) while the transmitter's frames are still right and the hart 0 late flag stays clear.
0xFF, or a parity error report, followed back to back by a character Works down to 8 ticks (measured, 8N1 / 8E1 and 8E1 / 7O2)
Receiver rate tolerance At 50 ticks, 8E1 (stop bit sampled 10.5 bit times after the start edge), 4 sender phases: sender bit time -4 % to +5 % passes, -5 % and +6 % fail. A receiver sampling exactly in the middle passes from -4.5 % to +5 % for this frame, so the sample points are centred.
Slowest bit time 43690 ticks set (B + B/2 is computed in 16 bits), 16383 ticks with autobaud (four bit times must fit the 16-bit timer); both tested
Data bits above 8 Not supported: the alignment polynomial 1 << (NBITS + 7) does not fit 16 bits and the data path is one byte
Data bits 1 to 4 Not supported (not tested)
Sending a break or a deliberate parity / framing error Not supported: every byte value from the host is data; the host-to-TX stream has no escape code
Bit time below 8 ticks Not supported (see the fastest bit time)
Fractional bit time Not supported: whole ticks (40 ns steps). 115200 baud is 217.01 ticks, so 217 is 0.005 % off
Characters arriving while a 0xFF 0xFF or error report waits for FIFO space Lost and not counted in OVR (the report bytes after the first wait for room so a report is never split)
RTS/CTS flow control, RS-485 direction pin, 9-bit / address mode, LIN Not supported: not requested, and both harts are already in use
Pins at run time Not possible: pin numbers are instruction fields

Tests

test/test_uart.py (cocotb). The line model is written from the asynchronous frame definition (start bit, data LSB first, optional even or odd parity, stop bits, sample in the middle, a stop bit sampled low is a framing error, a break is a whole frame low), not from the firmware; only the report format above is taken from this document. The model also checks that every edge of a transmitted frame sits on a multiple of the bit time. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_uart
Test What
test_uart_formats 9 settings (8N1 defaults, 8E1, 8O2, 7E1, 7O2, 6N2, 6E1, 5O1, 5N2; 20 to 300 ticks), full duplex, 0x00 / 0xFF / all-ones values
test_uart_errors Framing, parity, both, break (long low), zero data with a low stop bit, 0xFF, recovery after each; 8E1, 7O2, 8N1
test_uart_overrun OVR count
test_uart_autobaud 6 sender bit times including 25.5 and 61.25 ticks, measured value, full duplex at the measured speed, TX bytes held until READY
test_uart_rate_tolerance Sender -7 % to +7 %, 4 phases
test_uart_max_speed Bit time sweep 14 down to the first failure, 6 formats
test_uart_report_speed 0xFF and a parity error followed back to back
test_uart_slowest 43690 ticks set, 16383 ticks autobaud

Results are printed as UART ... lines. UART_FW selects another firmware file (for planted-bug checks).
