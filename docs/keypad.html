File Role Words
firmware/keypad.pe Hart 0 scans a 4x4 key matrix on all eight pins: each row in turn driven low (open drain, the other rows released), the columns read after a settle time; a whole-matrix debounce; scans in which two rows share two or more columns (the ghost of three keys on a rectangle) are dropped; key presses and releases are reported to the host in row and column order. 103 of 512

No RTL change: woe (one row low with pin_out = 0), rdp, tset/tsetr/twait, ld/st, txb.nb. Checked in simulation only, not on a board.

Sources

There is no standard for a keypad matrix; the test model is the circuit itself: 16 switches between four row lines and four column lines, no diodes, a pull-up on every line. Two well-known properties of such a matrix are checked:

  • With one row driven low and the others released, a pressed switch pulls its column low; a released row lets current pass from a column to another column through two pressed switches in that row, so three pressed corners of a rectangle make the fourth read as pressed (ghosting). Two pressed keys never make a ghost.
  • Mechanical contacts bounce for a few milliseconds when they close or open; the reading has to stay the same for a while before it counts.

Pins

Pin Use
P0..P3 rows 0 to 3: released, or driven low one at a time
P4..P7 columns 0 to 3: inputs, pull-ups outside (or the pad pull-ups)

Key number = 4 x row + column.

Scan, debounce and reports

One scan: for row 0 to 3, the row goes low, SETL ticks later (250, 10 us) the port is read and the row released, then ROWH:ROWL ticks (25,000, 1 ms) pass. A scan is therefore about 4.1 ms.

A scan whose four row readings have two rows with two or more columns in common is ambiguous and is dropped (GHST + 1); it neither starts nor ends a debounce. Otherwise the reading is compared with the one being debounced: a difference restarts the count, the same reading DEB times (5) in a row after the change makes it the stable matrix (STAB), and every key whose bit changed is reported: key for a press, 0x80 + key for a release, in row order, columns 0 to 3 within a row. With the defaults a key is reported about 20 to 24 ms after its contacts settle (20.8 ms measured).

Data memory Use
0x00 EVN events sent
0x01 EVL events lost because the host FIFO was full (the stable matrix is still right in STAB)
0x02 GHST scans dropped as ambiguous
0x03 SCN scans, mod 256
0x10-0x13 the last reading, rows 0 to 3, bits 0 to 3 = columns
0x14-0x17 the reading being debounced
0x18-0x1B STAB the stable matrix

Tests

test/test_keypad.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_keypad

The keypad model recomputes the level of every row and column line whenever the chip changes its pin drive or a switch changes: a line is pulled low when a path of pressed switches joins it to a row the chip drives low (rows the chip does not drive are passed through, which is what makes the ghost). Bounce is a burst of random closes and opens of 1/20 to 1/5 of the bounce time each.

Limits

  • A real rectangle of four pressed keys is also dropped (it cannot be told from three plus a ghost); diodes in the matrix would make every combination readable, and the ghost check could then be left out.
  • One key event per change of the stable matrix; no auto-repeat, no key buffer beyond the 4-byte host FIFO.
  • Simulation only: no board, no gate-level run.
