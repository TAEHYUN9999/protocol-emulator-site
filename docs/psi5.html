File Role Words
firmware/psi5.pe Hart 0 is a PSI5 sensor on the logic side of a transceiver: Manchester frames (two start bits, 10 data bits LSB first, even parity or CRC3) at 125 or 189 kbit/s, asynchronous (a frame per period) or synchronous (after each sync pulse, up to three time slots), slot data changed by the host. Hart 1 is a PSI5 receiver channel: reads the frames, checks the start bit and the parity or CRC, numbers the slots after each sync pulse and reports the data. Both on the DATA pin are a loopback. 286 of 512 (hart 0 153, hart 1 122, 11 shared)

No RTL change: existing instructions only (twait grid, shout/shout.lsb for exact halves, shin.lsb, rdp, waitp.to, the CRC unit as CRC3 or parity, ld/st, host FIFO). Checked in simulation only, not on a board.

Sources

The PSI5 technical specification is published by the PSI5 consortium, but each download sits behind a web form, which was not submitted: the specification was not read. The rules come from two sensor data sheets that follow it:

Source Used for
NXP MMA51xxL data sheet, Rev 5.0 (01/2017), PSI5 V1.3: 4.2, 4.3.1, 4.3.2, 4.3.3, Table 8, Table 9, parameters #122/#123 data by current modulation; a logic 0 is an increase of current in the middle of the bit, a logic 1 a decrease; two start bits 0, 0, then the data word LSB first; even parity over the message (Figure 31: 1E7h, P = 1); CRC x^3 + x + 1, seed 111, data LSB first augmented with three 0s, start bits not used; Table 8 CRC values; bit time 7.6..8.4 us and 4.9875..5.5125 us; data codes
ams-OSRAM AS5173 data sheet DS001146 v1-01 (2025), 8.1, 11.6, Tables 8, 24, 36 the same frame, sent C2 C1 C0; at least one bit time between frames; P10P-500/3L at 125 kbit/s: slots at 44..59, 181.3..210 and 328.9..372.8 us after the sync pulse, a 13-bit frame 100.4..107.6 us; data codes 1E7h Sensor Ready, 1E8h Busy, 1F4h Defect

The CRC unit computes the augmented seed-111 CRC as a direct CRC from 010 (checked for all ten data values of Table 8 in the test model).

Pins

Pin Use
P0 DATA: the sensor's current as a logic level (high = modulation current), driven by hart 0, read by hart 1; low at rest
P1 SYNC: the ECU's sync pulse as a logic level (high while the supply is raised), an input to both harts

The current loop and the voltage sync pulse are the transceiver's job (for example the ST L9663 gives the Manchester data on a logic pin and takes the sync trigger on another). The chip does not make the sync pulse: in the tests the bench does.

Timing

Data memory 0x00: bit 0 synchronous, bit 1 CRC (else parity), bit 2 189 kbit/s (else 125). Each half bit is H ticks: 100 (4.00 us, 125 kbit/s) or 66 (2.64 us, 189.4 kbit/s). The sensor computes the check bits first, then sends the frame on a grid of H: every level change comes one tick after a boundary, so every half is exact (the first half of the first start bit, low like the idle line, is the only exception). Synchronous: slot 1 starts a set time after the sensor sees the SYNC rise (data memory 0x04, 0x05 ticks, default 1,275 = 51 us); slots 2 and 3 start a set time after the end of the frame before (0x06, 0x07 and 0x08, 0x09, defaults 1,000 and 1,275 ticks), which with 13-bit frames at 125 kbit/s puts them at 195 and 350 us. Asynchronous: a gap of 0x01, 0x02 ticks after each frame (default 3,650: a frame every 252.8 us at 125 kbit/s with parity).

Receiver: it polls DATA and SYNC every few ticks; a SYNC rise restarts the slot count, a DATA rise is the middle of the first start bit. From each middle edge it waits 1.5 halves, reads the next bit's first half (0 = low, 1 = high), and waits at most one half for that bit's middle edge (a 1 falls, a 0 rises).

Host interface

Sensor (hart 0): data memory 0x0A..0x0F the 10-bit data of slots 1..3 (lo, hi); host bytes k lo hi change slot k (taken while it waits); 0x03 slots (0 = 1); 0x10 frames sent.

Receiver (hart 1): for each frame slot (0 asynchronous or before a sync, else 1..3 in order), D7..D0, D9 D8 in bits 1..0 with bit 7 = parity or CRC wrong and bit 6 = second start bit not 0. Counters 0x11 frames read, 0x12 with an error, 0x13 cut (a middle edge missing).

Tests

test/test_psi5.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_psi5

The models are written from the two data sheets, not from the firmware: the CRC3 (the augmented form of MMA51xxL, checked against its Table 8), even parity, Manchester halves, a frame decoder of the recorded DATA line, a model sensor with any bit time and frames with planted errors, and sync pulses (16 us high). Only pins, host bytes and data memory addresses come from the firmware header.

Limits

  • Logic level only: no current modulation, no voltage sync pulse generation (the ECU's transceiver does both); the receiver numbers slots by order, not by checking their times.
  • 10-bit data words only (no 8, 16, 20 or 24-bit frames, no daisy-chain addressing, no initialization phase with ID nibbles; the host can send any data codes).
  • Slot times are set as gaps after the frame before, so they move with the frame length (rate, parity or CRC).
  • The PSI5 specification was not read (see Sources); bit time tolerances and slot windows come from the data sheets.
  • Simulation only: no board, no gate-level run.
