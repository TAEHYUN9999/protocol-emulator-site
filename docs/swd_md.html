File Role Words
firmware/swd_md.pe Hart 0 is an SWD host for multi-drop buses: the dormant-to-SWD wake-up with the 128-bit Selection Alert generated by the LFSR of ADIv5.2, the activation code and a line reset; line reset; SWD-to-dormant; TARGETSEL writes (no reply expected); any DP or AP transfer. Hart 1 is a multi-drop SW-DP (DPv2): dormant out of reset, wakes only on the Selection Alert and the SWD activation code, takes TARGETSEL after a line reset (selects itself on TARGETID[27:0] and DLPIDR.TINSTANCE, or stays silent until the next line reset), answers DPIDR, TARGETID and DLPIDR (by SELECT.DPBANKSEL), CTRL/STAT, RDBUFF, ABORT and SELECT, locks out on a protocol error after a line reset, and goes dormant on the SWD-to-dormant sequence. The two harts on the same two pins, with more targets on the same wires, form a multi-drop bus. 508 of 512 (hart 0 209 with the shared LFSR step, hart 1 299)

No RTL change: existing instructions only (twait grid, waitp, shin.lsb/shout.lsb, rel, the CRC unit as a parity counter for headers, data and the LFSR feedback, ld/st with a register address, host FIFO). The general SWD firmwares (swd_host_gen.pe, swd_target_gen.pe, docs/swd.md) are not changed; this file adds SWD protocol version 2. Checked in simulation only, not on a board.

Pins

Pin Host (hart 0) Target (hart 1)
P0 SWCLK, output SWCLK, input
P1 SWDIO, let go in the turnaround, ACK and target data phases SWDIO, driven only for ACK and RDATA

SWDIO needs a pull-up. The target drives the line only when it answers, so other multi-drop targets can sit on the same two wires (the tests add a model target). Each hart writes SWDIO only while it owns it.

Timing

Host: one period of the twait grid is half an SWCLK period (data memory 0x00, default 25 ticks = 500 kHz); the grid is restarted at each command and again after the data bytes of a write. In the Selection Alert the next LFSR state is computed while SWCLK is low (23 ticks), so the half period must be at least 24 ticks.

Target: it follows SWCLK with waitp and reads SWDIO after each rising edge, drives ACK and RDATA after rising edges and lets go after a rising edge. In the dormant state it checks every bit against the LFSR (about 30 ticks per bit), and in the active state it decodes a header within one SWCLK period. Checked at 500 kHz only.

Tests

test/test_swd_md.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_swd_md

The models are written from the sources above, not from the firmware: the wake-up, line reset and dormant sequences as bit lists (the alert from OpenOCD's bytes, checked against the binary value of B5.3.4 and against the LFSR), a host model, and a multi-drop target model that finds the alert with a sliding 128-bit window (not an LFSR), counts 50 ones for a line reset, matches TARGETSEL on TARGETID and TINSTANCE, and answers DPIDR, TARGETID and DLPIDR. A recorder logs SWCLK, SWDIO, the chip's SWDIO enable and the bench's, to find drive clashes and changes of the chip's SWDIO while SWCLK is low. Only pins, host commands and data memory addresses come from the firmware header.

Limits

  • No AP (every AP access gets FAULT), no WDATAERR or sticky flags, no DLCR turnaround other than 1, no EVENTSTAT (bank 4 reads 0); the general target swd_target_gen.pe has a MEM-AP model but no protocol version 2.
  • A line reset is taken after 42 ones (the target may have read 8 of a reset's ones as a header); ADIv5.2 asks the host for 50.
  • A second TARGETSEL before the DPIDR read is taken again (ADIv5.2: UNPREDICTABLE).
  • The dormant state ignores the JTAG-to-dormant sequence and JTAG; this is an SW-DP, not an SWJ-DP.
  • SWCLK checked at 500 kHz only; the host's alert needs a half period of 24 ticks or more.
  • 508 of 512 words: little room for more in the same image.
  • Simulation only: no board, no gate-level run.
