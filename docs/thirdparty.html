Tests against third-party device models

Most judges in test/ were written for this project from the protocol documents. test/test_thirdparty.py puts the firmware against device models that other people wrote and published: the public cocotb extensions for UART, SPI and I2C. The model is the other side of the bus, and what it receives, stores or reads back decides the test. The test itself decodes nothing.

Packages

The versions and licenses are those of the package metadata on PyPI, installed on 2026-11-12 with cocotb 2.0.1 and Python 3.10. No file of these packages is in this repository; they are a dependency of this one module only, listed in test/requirements-thirdparty.txt. The other modules run without them, and without them every test of this module is reported as skipped (with a 3P SKIPPED warning), not as passed.

python3 -m venv .venv3p                                   # in the repository root; not committed
.venv3p/bin/pip install -r test/requirements-thirdparty.txt
cd test
PATH=$PWD/../.venv3p/bin:$PATH make -B COCOTB_TEST_MODULES=test_thirdparty NODUMP=1

How the models are connected

The models write signal.value and wait on edges of cocotb handles. test/tb.v gives the test one wire per protocol line (p0 to p7) to read and two vectors (ext_out, ext_oe) to drive, so the module has one adapter, the class Pin: reads, edges and the name come from the wire, a write drives the test side of that line, and for an open-drain line a written 1 releases it. This adapter and the choice of pins, speeds and bytes are the only code of this project between the firmware and the model. tb.v was not changed.

One class is derived from a model: StretchingMemory(I2cMemory) waits 6 us in handle_write before it calls the original. The model holds SCL low while that method runs, so this makes the unchanged protocol engine of the model stretch the clock.

One run of the whole module on 2026-11-12 (RTL of 966d429, Icarus Verilog 11.0, cocotb 2.0.1): TESTS=14 PASS=14 FAIL=0, 12.67 ms simulated, 52 s wall.

Controls

Each control runs the same session with one planted fault and passes only if the model's result is wrong in the expected way.

Test Planted fault Seen by the model
test_uart_cocotbext_control_slow BIT 55 instead of 50 (10 % slow) UartSink reads 8 of 12 bytes wrong; 8 of 12 bytes from UartSource reach the host wrong
test_uart_cocotbext_control_msb shout instead of shout.lsb in the transmitter UartSink reads every byte bit-reversed
test_spi_master_cocotbext_control_late_mosi MOSI changed one tick after the SCK rise instead of in the low half SpiSlaveLoopback returns 09 7F 38 for 12 FE 70 (one bit late)
test_spi_master_cocotbext_control_cpha none in the firmware; the slave is set to CPHA 1 the host reads 09 7F 38 for 12 FE 70
test_spi_device_cocotbext_control shout.lsb on MISO SpiMaster reads 7BB57DF7 for DEADBEEF (the reset values read the same in both bit orders)
test_i2c_master_cocotbext_control the controller sends LSB first I2cMemory does not ACK (reply EE) and stores nothing
test_i2c_target_cocotbext_control the target's address changed to 0x43 I2cMaster gets no ACK at 0x42 and reads FF FF FF FF

Limits

  • The models check function, not timing. UartSink samples each bit once in its middle and does not check the stop bit; I2cMaster and I2cMemory do not check set-up or hold times; SpiSlaveLoopback cannot tell the bit order (it returns what it got). The timing judges of this project (test_uart.py, test_i2c.py, test_spi.py, the spec-table judges) remain the ones that measure edges.
  • I2cMaster at its 400 kHz setting makes SCL high for 2.5 us and low for 2.5 us (200 kHz on the wire).
  • Only the three packages above were tried. USB, 1-Wire, JTAG and CAN models from other projects are not used here.
  • RTL simulation only; the module reads no RTL hierarchy, so it can run on the netlist, but that was not done.
