firmware/sdnative.pe One hart: an SDHC memory card on the SD bus in 1-bit mode: 48-bit commands with CRC7, the responses R1, R2, R3, R6 and R7, identification (CMD0, CMD8, CMD55 + ACMD41, CMD2, CMD3), CMD7 select, CMD13 status, CMD17 one block on DAT0 with its CRC16. 337 of 512

This protocol was not part of the design when the RTL was written. It uses only existing instructions (shin as a pin test, shout, high/low/rel, the CRC unit for CRC7 and CRC16, ld/st on the data memory and the frame buffer); the RTL is unchanged. Checked in simulation only, not on a board. The SPI mode of SD cards is a separate firmware (docs/sdspi.md).

Section and table numbers are those of the SD Specifications Part 1 Physical Layer Simplified Specification, Version 9.10 (December 2023). The bus timing tables (4.12) are removed from the simplified edition; the response delays come from secondary sources (see the table).

Pins

Constant Default Use
CLK P2 the SD clock from the host
CMD P3 commands from the host; the card drives it only for its responses
DAT P4 DAT0: the card drives it only for a block

Timing

The card polls CLK with shin (four ticks per poll) and takes CMD at each rise. After a command's end bit it checks the CRC7 and decodes the command; ACMD41 and CMD2 consume the first fall after the end bit within one clock period, so their responses start exactly 5 clock periods after the end bit (two periods with CMD released, three with CMD high as P bits). The other commands do the same when their decode fits in one period, otherwise their responses come one period later (NCR 5 or 6, within 2..64). At 400 kHz each period is 62 ticks. After the end bit of the R1 response to CMD17, DAT0 stays high for 8 clocks and the start bit of the block comes on the 9th (the test counts the clocks from the one after the end bit and reports 9).

Host interface

There are no host commands; the host sets the data memory before the card starts.

Address Use
0x00 state: 0 idle, 1 ready, 2 ident, 3 stby, 4 tran
0x05 ACMD41 busy answers before ready (0: 2)
0x06, 0x07 RCA (0: 1234h)
0x08, 0x09, 0x0A counts: responses, commands with a bad CRC or end bit, blocks
0xA1..0xAF the CID bytes 15 to 1 (byte 0, the CRC7, is computed at start-up)
frame buffer 0x20..0x5F the first 64 bytes of block 0 (the rest of every block reads 00h)

Controls

Limits

  • 1-bit mode, single block reads only; the 64-byte window is the only stored data.
  • The response delays come from secondary sources (the timing tables are not in the simplified edition).
  • Clock up to the 400 kHz identification rate checked; the card's polling decides how fast it can go.
  • Simulation only: no board, no gate-level run.
