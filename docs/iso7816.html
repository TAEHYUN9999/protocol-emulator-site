File Role Words
firmware/iso7816.pe Hart 0 makes the card clock CLK (4.17 MHz). Hart 1 is the card (MODE 0: ATR after a reset, T=0 commands with procedure bytes, a 16-byte file) or the terminal (MODE 1: activation, ATR parsing, T=0 commands from the host with all procedure bytes). Both sides do the parity error signal and the character repetition. 438 of 512 (hart 1 starts at word 6)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (high/low/rel, shout.lsb.od, shin.lsb, waitp.to, tset/tsetr/twait, the CRC unit as a parity counter with polynomial x + 1, ld/st, host FIFO); the RTL is unchanged. Checked in simulation only, not on a board.

ISO/IEC 7816-3 itself was not read: it is not freely available. The rules are taken from ETSI TS 102 221 V17.4.0 (2023-02), Smart Cards; UICC-Terminal interface; Physical and logical characteristics, which restates the ISO/IEC 7816-3 character layer and T=0; the ATR timing and structure come from a secondary source (see Sources).

T=0 header CLA INS P1 P2 P3; procedure bytes INS (all data), ~INS (one byte), 60h NULL, 61h xx (GET RESPONSE C0h, Le = xx), 6Ch xx (header again with P3 = xx); SW1 6X/9X then SW2 ETSI 7.2.2.2, 7.2.2.3, Tables 7.1 and 7.2 card: cmd .. cg2; terminal: xhdr .. p61

Not implemented: the inverse convention (TS 3Fh), PPS, TA1 other than 11h (Fi/Di), extra guard time (TC1), the work waiting time from TC2, T=1, clock stop, class B/C voltages, deactivation. The card's ATR must be written by the host.

Pins

Constant Default Use
CLK P0 card clock, push-pull, from hart 0 in both modes
RST P1 card: input; terminal: output, push-pull
IO P2 open drain (the chip pulls low or lets go); the line is high when nobody pulls

In card mode the chip still makes CLK (the terminal model counts it), so the card's etu is exact to the clock.

Host interface

Address Use
0x00 MODE 0 card, 1 terminal
0x01 ATRN card: ATR length to send (bytes at 0xE0, must not be 0); terminal: the ATR length received
0x02 WT terminal: waiting time for each character from the card, in 120000 ticks (0: 180, 9677 etu, at least the default WWT of 9600 etu)
0x03 characters received with a wrong parity (error signalled)
0x04 characters sent again after an error signal
0x05 characters given up after 4 attempts
0xA0 card: the 16-byte file; terminal: data received
0xC0 card: case 4 data and its response; terminal: data to send
0xE0 ATR (card: to send; terminal: as received)

Card commands: B0 READ BINARY (P2 offset, P3 length inside the file, else 6C xx with the right length, or 6B 00 for an offset outside), D6 UPDATE BINARY (the first byte under ~INS, the rest under INS, then a NULL byte and 90 00; a wrong range gives 67 00), 88 (case 4: P3 = 1 to 16 bytes in under INS, their complements kept for GET RESPONSE, answered 61 xx), C0 GET RESPONSE (6C xx for a wrong Le, 69 85 with nothing pending), others 6D 00. A falling RST at any wait for a character restarts the card (warm reset).

Terminal: after the ATR it pushes one byte to the host: the ATR length, + 80h when TCK is wrong, + 40h when the ATR broke off, 0 when no TS came in 40 000 clocks. A host command is D (0 to 32 data bytes to send; 80h: warm reset), CLA INS P1 P2 P3, then D data bytes. The answer is three bytes: bytes received (in 0xA0..), SW1, SW2; SW1 = 0 means no character within WT (SW2 0) or a byte that is no procedure byte (SW2 = that byte).

Tests

test/test_iso7816.py (cocotb). Two models written from ETSI TS 102 221: a terminal (card mode) and a card (terminal mode), both on a recorded I/O line that checks every edge inside every character against n +- 0.2 etu and every start against the 12 etu spacing; the etu is 372 periods of the chip's CLK, measured over 200 edges. Only the host interface above is taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_iso7816

Limits

  • One fixed CLK (4.17 MHz) and etu (372 clocks); no PPS, so no faster Fi/Di.
  • The card answers every header within 13 etu; it never needs the work waiting time. The terminal's waiting time per character is WT x 120000 ticks; the default (9677 etu) is a little longer than the default WWT (9600 etu).
  • The card's file is 16 bytes; case 4 takes up to 16 bytes. The terminal takes up to 32 bytes per command.
  • After a character fails 4 attempts the firmware goes on as if it had been sent (counted in 0x05); ETSI sets no limit.
  • Simulation only: no board, no gate-level run.
