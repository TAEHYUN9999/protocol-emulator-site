File Role Words
firmware/modbus.pe Modbus RTU slave on hart 0: 8E1 characters, the t1.5 and t3.5 rules, CRC-16, functions 03 (read holding registers), 06 (write single register) and 16 (write multiple registers) on 48 registers in the data memory, exception responses 01, 02 and 03, broadcast writes, an RS-485 driver enable pin, diagnostic counters. 240 of 512

This protocol was not part of the design when the RTL was written. It uses only existing instructions (low/high, shout.lsb, shin.lsb, tset/tsetr/twait, waitp.to, the CRC unit, ld/st on the data memory and the frame buffer); the RTL is unchanged. Checked in simulation only, not on a board.

Pins

Constant Default Use
TX P0 transmit data, push-pull, high when idle
RX P1 receive data
DE P2 RS-485 driver enable: high from one bit before the first start bit until the end of the last stop bit

The receiver ignores RX while the slave sends, so a 2-wire RS-485 transceiver with its receiver always enabled (which echoes the response) is fine.

Timing

BIT is the bit time in ticks, HBIT half of it. The two silences are 16-bit tsetr periods given as byte pairs, counted from the middle of the stop bit of the last character received (half a bit before the character ends):

Constant Default (19200 bit/s) Meaning
BIT, HBIT 1302, 651 19201.2 bit/s
T15H, T15L 0x5676 = 22134 t1.5 + half a bit: 16.5 + 0.5 bits
TCWH, TCWL 0x6FE4 = 28644 t3.5 - t1.5: 22 bits
T35H, T35L 0xC65A = 50778 t3.5 + half a bit: 38.5 + 0.5 bits

For 115200 bit/s with the fixed 750 us and 1.750 ms of 2.5.1.1: BIT 217, HBIT 108, t1.5 + half 18858, t3.5 - t1.5 25000, t3.5 + half 43858 (fw_constants() in the test computes these). The silences fit the 16-bit timer from about 14,700 bit/s up (t3.5 + half a bit at most 65535 ticks); 9600 bit/s would need a counted wait and is not supported.

Every edge of a response is a whole number of bits after its first start edge, and the characters follow each other without a gap: txchar is called inside the period before its start bit and returns inside its stop bit (measured, test_modbus_slave).

Data memory

Address Use
0x00 MADDR slave address 1 to 247, written by the host; 0 uses the assembler constant ADDR (1)
0x01 MBUS frames with a right CRC seen on the bus
0x02 MCRC frames with a wrong CRC, or shorter than 4 bytes
0x03 MEXC exception responses sent
0x04 MSLV frames for this slave, broadcasts included
0x05 MCHR frames dropped for a parity or framing error, a gap over t1.5, or more than 128 bytes
0x20 to 0x9F the frame buffer: request, then response (frames of up to 128 bytes)
0xA0 + 2k, 0xA1 + 2k holding register k (0 to 47), high byte first

The host presets the registers with DATA_W before the run and reads them with DATA_R at any time. The counters follow the diagnostic counters of the serial line guide in spirit (bus message, communication error, exception, slave message), but there is no function 08 to read them over the bus.

Tests

test/test_modbus.py (cocotb). The master model is written from the two specifications: characters with even parity, CRC by the steps of 6.2.2, the timer values of 2.5.1.1, the request and response layouts and exception rules of the application protocol. It also checks every response it receives: parity and stop bits, a right CRC, every edge on the bit grid, characters back to back, at least t3.5 after the request, DE high over the whole response. Only the slave's data memory addresses, pins and assembler constants are taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_modbus

Controls

Each change was made in a copy of modbus.pe and run with MODBUS_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Odd parity sent (txchar starts its count of ones at 1) test_modbus_slave the first response: the master model reports a parity error on its first character 0x11
A character after t1.5 does not mark the frame incomplete (ldi r3, 1 in rcw removed) test_modbus_slave the frame with a 900 us gap is counted as a CRC error instead of a dropped frame: counters (26, 3, 13, 25, 1)

Limits

  • Slave only, RTU only (no ASCII mode), even parity only (no odd or no-parity with two stop bits, which 2.5.1 allows by configuration).
  • Functions 03, 06 and 16 on 48 registers; other functions answer 01. No coils, input registers, or diagnostics (function 08).
  • Frames of at most 128 bytes (the frame buffer); a longer one is dropped and counted in MCHR (the specification allows 256). A function 16 that long could not address the 48 registers anyway.
  • Bit rates from about 14,700 bit/s up; the timers are assembler constants, not settings.
  • The frame buffer is shared with the Ethernet blocks and the capture, which must stay idle.
  • Simulation only: no board, no gate-level run.
