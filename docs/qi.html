File Role Words
firmware/qi.pe Hart 0: the Power Receiver's sender (2 kHz differential bi-phase, 11-bit bytes with odd parity, preamble, header, message, checksum). Hart 1: the Power Transmitter's decoder (start bit after at least 4 preamble ONEs, re-timing on every bit boundary, parity, stop bits, the message size from the header, the checksum). 268 of 512 (hart 1 starts at word 69)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (shout, shin as a pin test, waitp, waitp.to, tsetr/twait, the CRC unit as a parity counter, the host FIFO, the data memory); the RTL is unchanged. The pin carries the modulation state at logic level (after the Power Transmitter's demodulator, or before the Power Receiver's modulator); the power transfer and the analog demodulation are outside the chip. Both harts can use the one pin, so the sender talks to the decoder on one chip. Checked in simulation only, not on a board.

Section and table numbers are those of the Qi Wireless Power Transfer System Power Class 0 Specification, Parts 1 and 2: Interface Definitions, Version 1.2.3 (Wireless Power Consortium, February 2017).

Pins

Constant Default Use
PIN P0 the modulation state at logic level (the sender drives it; the decoder reads it)

Timing

The sender changes the pin on a half-bit grid of the timer (6250 ticks, 250 us at 2 kHz); both levels of a bit are worked out before its first wait, so every change comes one instruction after a twait. The decoder counts transitions less than 3/4 bit apart in the preamble (a bit start and a bit middle look the same there); the first gap of more than 3/4 bit after at least 8 such intervals is the start bit, and the transition that ends it is the first bit boundary. From there it samples each bit at 3/4 of the bit time after its boundary (a level different from just after the boundary is a ONE) and waits up to half a bit for the next boundary, so every bit re-times it.

Host interface

Sender (hart 0): FIFO [header, message bytes] (the size from Table 25); the checksum and the preamble are added. Decoder (hart 1): [status, header, message bytes] for each Packet; status 0 ok (bytes follow), 1 parity error, 2 a stop bit missing, 3 checksum, 4 a transition missing (no bytes follow these).

Address Use
0x00, 0x01 half bit time in ticks (0: 6250, 2 kHz)
0x02 preamble ONEs sent (0: 11)
0x03, 0x04, 0x05 counts: Packets sent, Packets received correctly, Packets dropped

Tests

test/test_qi.py (cocotb). The Power Transmitter decoder model and the Power Receiver encoder model are written from the specification sections above. Only the pin, the host bytes, the status codes and the data memory addresses are taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_qi

Controls

Each change was made in a copy of qi.pe and run with QI_FW pointing at it. All fail:

Change Test Caught by
Sender with even parity test_qi_sender the model finds parity errors in the first packet
Sender at 2.2 kHz (half bit 5682 ticks, outside 2 kHz +-4 %) test_qi_sender transitions off the 250 us half-bit grid
Decoder takes a start bit after 2 preamble ONEs instead of 4 test_qi_decoder in the checksum byte of the packet with a parity error, two ONEs and a ZERO are taken as a preamble and a start bit: a stray status 4 is reported where the next packet's status 3 was due

Limits

  • Logic level only: no power signal, no amplitude modulation, no demodulator.
  • The protocol phases and their timeouts are left to the host.
  • Simulation only: no board, no gate-level run.
