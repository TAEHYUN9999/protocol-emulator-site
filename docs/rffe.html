File Role Words
firmware/rffe.pe Hart 0 is an RFFE master run by host commands: SSC, the 13-bit command frame with odd parity, Register Write, Register Read, Register 0 Write, Extended Register Write and Read of 1 to 16 bytes, a lone command frame (SPMI state commands), bus park cycles, read frames checked for parity. Hart 1 is an RFFE slave with 32 registers: its USID and the broadcast SID 0, all five register commands, No Response Frames above 1Fh, parity errors handled as RFFE Table 11 says, USID programming through registers 1Dh to 1Fh, and in SPMI mode the state commands RESET, SLEEP, SHUTDOWN and WAKEUP. The two harts on the same two pins are a loopback. 377 of 512 (hart 0 174, hart 1 203)

No RTL change: existing instructions only (twait grid, high/low/rel, shout, shin, waitp, rdp, the CRC unit as a parity counter, ld/st with a register address, host FIFO). Checked in simulation only, not on a board. SCLK is lowered: the master runs at 500 kHz (962 kHz checked), the slave follows up to 714 kHz; RFFE allows 32 kHz to 26 MHz.

Pins

Pin Use
P0 (M_SCLK, S_SCLK) SCLK, driven by the master (push-pull, idle low)
P1 (M_SDATA, S_SDATA) SDATA, driven by whoever owns it, otherwise held low by a pull-down

RFFE puts the pull-down in the master (5.1); the chip has none, so the board needs one (the bench holds released lines low for these tests). The master drives SDATA from the SSC to its bus park; the slave drives it only for the data frames of a read and its bus park. Each hart touches SDATA only while it owns the line, so both harts can use the same pin (a rel from a hart that does not own the line would drop the other's drive; neither does that).

Timing

Master: one period of the twait grid is half an SCLK period (data memory 0x00, default 25 ticks = 500 kHz). Every SCLK edge comes one tick after a grid boundary, so the high and low times are exactly the half period (50 clocks); SDATA changes one tick after the rising edge, read bits are taken one tick after the falling edge, and at the bus park SDATA is released one tick (2 clocks) after the falling edge. The SSC is SDATA 1 for two grid periods and 0 for two, then the first rising edge. Since branch int3 (revisions) a push-pull high from release is enabled one clock after the instruction (dual_role.md); the SSC rises from the idle bus, which the pull-down holds low, so its 1 lasts one SCLK period less one clock (99 of 100 clocks at 500 kHz, 51 of 52 at 962 kHz), and its 0 a full period. RFFE v1.10 6.2.1 asks for one SCLKint period and gives no tolerance, and leaves the timing between SCLKint and SCLK to the implementation (266); the nearest numeric limit, the SCLK duty cycle of Table 2 (45 to 55 % of the period), allows an edge 5 % of the period off, and the clock is 1 % (500 kHz) or 1.9 % (962 kHz). The grid is restarted with tsetr at the start of each sequence, so an idle bus never makes a twait late. The longest code between two edges is 13 ticks (after a read frame), so the half period can be as short as 13 ticks (962 kHz).

Slave: it follows SCLK with waitp. An SSC is SDATA rising while SCLK is low: data only changes while SCLK is high, and the master raises SCLK a tick before it changes SDATA, so the two synchronised inputs never show a data change as an SSC. It reads bits after it sees the falling edge, drives read bits 5 to 6 clocks after it sees the rising edge (7 for a 1 driven from release, by the pad rule) and lets go 5 to 6 clocks after the falling edge at the end of its bus park. After the command frame of a write it has one SCLK period to decode the command before the next falling edge; this sets its limit: right at 714 kHz, wrong at 833 kHz and 1 MHz.

Parameter Value
Master SCLK 100 clocks = 2 us (500 kHz), high and low 50 each; 52 clocks (962 kHz) at half period 13
Master SSC SDATA 1 for one SCLK period less one clock (pad rule), 0 for one, SCLK low, then the first rise one period later
Master SDATA release at bus park 2 clocks after the falling edge (RFFE: 10 ns at full speed)
Slave drive / release 5 to 7 clocks (7: a 1 from release, pad rule) after the rising edge / 5 to 6 after the falling edge
Slave SCLK right up to 714 kHz

Host interface

Master (hart 0), host commands and answers:

Command Host bytes Answer
Register Write (010 a) 01 sa a d 0
Register Read (011 a) 02 sa a status, data
Register 0 Write (1 d6..d0) 03 sa d 0
Extended Register Write (0000 BC) 04 sa a n d1..dn (n 1..16) 0
Extended Register Read (0010 BC) 05 sa a n status, n bytes
A command frame alone (e.g. SPMI 10h..13h) 06 sa c 0

Status 0: every read frame had odd parity; 1: one had even parity (the bytes are still given). Data memory 0x00: half SCLK period in ticks (0 = 25); 0xA0-0xAF: the bytes of the current command.

Slave (hart 1), data memory:

Address Use
0xC0-0xDF registers 00h to 1Fh (host DATA_W before the run); 1Dh PRODUCT_ID, 1Eh MANUFACTURER_ID[7:0], 1Fh {00, MANUFACTURER_ID[9:8], USID}
0x01 bit 0: SPMI mode (state commands 10h..13h taken; RFFE: reserved, ignored)
0x02 last state command
0x03 sequences taken
0x04 parity errors
0x05 USID programming step (0, 1 after 1Dh, 2 after 1Eh)
0x06 the USID in use (copied from register 1Fh at start and on a change)

Registers 1Dh..1Fh are not written by Register Writes; such writes are the USID programming steps (RFFE 6.8.3 method 1): PRODUCT_ID to 1Dh, MANUFACTURER_ID[7:0] to 1Eh, {00, MANUFACTURER_ID[9:8], new USID} to 1Fh, each addressed to the slave's USID or broadcast, with no other command for the slave in between. An Extended Register Write of three bytes from 1Dh does the same (method 2). Register 0 Write keeps bit 7 of register 0.

Tests

test/test_rffe.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_rffe

The models are written from the sources above, not from the firmware: frame builders with odd parity, a master model (SSC, frames, its bus park, reads with the slave's bus park, any SCLK and change point), a slave model (SSC detection, frames read at falling edges, reads answered at rising edges with its own bus park), and checks on the recorded SCLK, SDATA and chip SDATA enable: SCLK high and low times, every SSC shape, every SDATA change while SCLK is high, every release within 2 clocks of a falling edge (master) or after a falling edge (slave). Only pins, host bytes and data memory addresses come from the firmware header.

Limits

  • SCLK lowered to 1 MHz and below (master 962 kHz, slave 714 kHz); RFFE full speed is 26 MHz and its TSDATAZ (10 ns) is far below a tick.
  • Not implemented: Extended Register Write/Read Long (0011x), Masked Write and SREAD of RFFE 2.x, group SIDs, trigger registers and PM_TRIG power modes (register 1Ch is a plain register), interrupts.
  • SPMI: only the shared frame layer and the four state commands; no bus arbitration, no multi-master, no ACK/NACK of SPMI 2.0 (its rules were found only in patents), no Master Read/Write or DDB commands.
  • A new SSC in the middle of a sequence is not detected: the slave finishes the frames it counts, then waits for the next SSC.
  • The slave has 32 registers (Extended addresses above 1Fh answer nine 0s and drop writes).
  • Simulation only: no board, no gate-level run.
