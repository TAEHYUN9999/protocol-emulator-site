Word counts are from tools/peasm.py. This firmware uses only existing instructions (tsetr/twait timing, gpo, woe/wrp, ld/st, host FIFO with rxb.nb/txb.nb); the RTL is unchanged. Checked in simulation only, not on a board.

Source

There is no standard for the RC servo signal. The firmware and the test use:

  • [S3003] Reely S3003 MG analog servo, specification sheet (Conrad item 2234101): "Pulse Width Control 1500usec Neutral", "Pulse Traveling 1000~2000usec", dead band 4 usec.
  • [SC] the usual frame of one pulse per channel every 20 ms (50 Hz), as described for RC servos in general (Wikipedia, "Servo control"); [S3003] gives no frame rate. Servos differ: some take 500 to 2500 us, and digital servos accept shorter frames.

For the fan output:

  • [FAN] Intel, "4-Wire Pulse Width Modulation (PWM) Controlled Fans", Revision 1.3 (September 2005), section 2.1.4 "PWM Control Input Signal". The PDF itself was only found behind a sign-in or a bot check; the text of 2.1.4 was taken from a public forum post that quotes it: target frequency 25 kHz, acceptable range 21 kHz to 28 kHz, VIL at most 0.8 V, the signal pulled up within the fan to at most 5.25 V, at most 5 mA sourced.

Pins

Pin Use
uo[2]..uo[7] Servo channels 0 to 5 (gpo bits 0 to 5), push-pull. Channel n pulses at the start of slot n; slots from NCH on stay low. Only one output is high at a time.
uio[0] (P0) Fan PWM. Open drain (default): low = driven low, high = released, the fan's pull-up makes it high. Push-pull (PMODE bit 0): driven both ways.

Hart 0 writes only gpo and hart 1 only the P port, so the harts never touch the same output bit. A fan's PWM input is pulled up to as much as 5.25 V; the chip's pins are 3.3 V parts, so an open-drain transistor (or another 5 V tolerant buffer) belongs between P0 and the fan.

Settings and host interface

Data memory, written by the host with DATA_W while both harts are stopped and read with DATA_R at any time. Each hart checks its settings once at start and writes back what it uses. 16-bit values are high byte first; times are in ticks of 40 ns.

Address Name Meaning Out of range
0x00 NCH servo channels 1 to 6 0 or more than 6: 6
0x01 NSLOT slots per frame, NCH to 255 0: 8; less than NCH: NCH
0x02, 0x03 SLOT slot length less than 1024: 62,500 (2.5 ms)
0x04, 0x05 MINW shortest pulse 0: 25,000 (1.0 ms); less than 16: 16
0x06, 0x07 MAXW longest pulse 0: 50,000 (2.0 ms); more than SLOT - 256: SLOT - 256; MINW above MAXW becomes MAXW
0x08..0x13 W0..W5 pulse widths of channels 0 to 5 0: 37,500 (1.5 ms); clamped to MINW..MAXW
0x14, 0x15 PER PWM period 0: 1000 (25 kHz); less than 128: 128
0x16, 0x17 DUTY PWM high time: 0 always low, PER or more always high, otherwise 8 to PER - 80 1 to 7: 8; PER - 79 to PER - 1: PER - 80. Hart 1 writes back the value in use
0x18 PMODE bit 0: 0 open drain, 1 push-pull
0x19 FRAMES hart 0 counts frames (mod 256)
0x1A ERR hart 0 counts FIFO commands with a bad channel
0x1B..0x1D MSEQ, MDH, MDL PWM high time from hart 0 to hart 1
0x1E, 0x1F, 0xA0 hart 0: the FIFO command being collected
0xA1..0xA3 hart 1: last sequence seen, low phase

Host FIFO (FIFO_W) to hart 0: commands of three bytes c hi lo.

c Effect Echo (FIFO_R)
0 to 5 width of servo c, clamped to MINW..MAXW, stored in Wc and used from the next pulse of that channel c hi lo with the clamped width
6 PWM high time, handed to hart 1 and used from its next period (clamped there, see DUTY) c hi lo as sent
7 to 255 dropped, ERR + 1 none

Hart 0 takes FIFO bytes in the rest of each slot, one whole command per slot; the three bytes may come in separate transfers. The echo is sent with txb.nb and is lost if the host FIFO is full. A width written to Wc never appears half old and half new: hart 0 writes it in the rest of a slot and reads it at the start of the channel's slot.

The PWM high time travels from hart 0 to hart 1 through the data memory with a sequence counter (MSEQ): hart 0 makes it odd, writes MDH and MDL, then makes it even; hart 1 takes the value only if MSEQ is even, differs from the last one it took, and is the same after reading both bytes. Otherwise it tries again in the next period.

Timing (measured)

Every edge is a fixed number of instructions after a twait, so all times are whole ticks. Measured by the test from the recorded edges, in clocks of 20 ns, 2026-11-11:

Output Setting Measured Spec
Servo pulse default (W 0) 75,000 clocks = 1500.00 us on all six channels neutral 1500 us [S3003]
Servo frame default (8 slots of 2.5 ms) 1,000,000 clocks = 20.000 ms between pulses of one channel 20 ms [SC]
Servo pulse W 16 to 40,000 ticks (case 2 below) exactly 2 x W clocks for each
Servo slots NSLOT x SLOT channel n starts n x SLOT after channel 0
Fan PWM period default (PER 0) 2000 clocks = 40.000 us = 25.000 kHz 25 kHz, 21 to 28 kHz [FAN]
Fan PWM high time DUTY 8 to 920 exactly 2 x DUTY clocks
PWM period PER 128, 200, 1000, 40,000 exactly 2 x PER clocks (195.3 kHz to 625 Hz)

The pulse resolution is one tick (40 ns), a hundred times finer than the 4 us dead band of [S3003]. The PWM high time is 8 to PER - 80 ticks, plus always low and always high: at 25 kHz that is 0.8 % to 92 %, 0 % and 100 %. The low phase must be 80 ticks (3.2 us) or more because hart 1 checks for a new high time there, and the high phase 8 ticks because it reloads the low phase length there.

How it works

Hart 0 runs one loop per slot: twait ends the slot, gpo r0 raises the channel's output (r0 is 0 in a slot without a channel), tsetr starts the pulse timer with W - 2, twait, gpo with 0 ends the pulse, tsetr starts the rest of the slot with SLOT - W - 2. In the rest it collects FIFO bytes, applies a whole command, moves to the next slot (and the next frame), loads the next width and computes the two timer values. Because the edges are always the first instruction after a twait and the timer values carry the fixed instruction counts, the pulse is W ticks and the slot SLOT ticks whatever the rest of the slot does, as long as it takes less than the rest (at least 256 ticks).

Hart 1 does the same per PWM period with the port value of the high and of the low phase in two registers, so the always-low and always-high cases run the same loop with equal values. A new high time is turned into the two timer values and the two port values in the low phase.

test/test_servo.py (cocotb). The judge records every change of uo_out and of P0 with its clock number and works on whole clocks; the expected widths, slots, frames and periods are computed from the settings and from [S3003], [SC] and [FAN] (module docstring), not from the firmware. Only the host interface (data memory addresses, FIFO commands) is taken from this document. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_servo

Limits

  • No standard: the servo numbers come from one servo's sheet and the usual 50 Hz frame. Check the range of the servo in use before widening MINW and MAXW.
  • A slot holds one pulse and at least 256 ticks (10.24 us) of rest, so a width is at most SLOT - 256 and the channels take turns: with SLOT 2.5 ms the frame is at least NCH x 2.5 ms. Servos that want a short frame with long pulses can only have a few channels.
  • One FIFO command per slot (2.5 ms by default); the host has to send the three bytes of a command before the next command. Updates of the fan's high time need hart 0 running.
  • The fan's high time is 8 ticks to PER - 80 ticks, or always low or always high: at 25 kHz 0.8 % to 92 %, 0 % and 100 %. [FAN] does not ask for the range in between, but a controller that should send 95 % cannot.
  • The fan's tachometer output is not read.
  • The servo outputs are 3.3 V push-pull and the fan output must not see the fan's 5 V pull-up directly (see Pins).
  • Checked in simulation only, not on a board, with no servo or fan attached.
