File Role Words
firmware/rc6.pe Philips RC-6 mode 0. Hart 0 sends frames (36 kHz carrier on the LED pin, envelope on a second pin) with the double-length trailer bit as the toggle; hart 1 decodes a receiver module's output by half-bit times from each middle edge. 161 of 512 (hart 1 at word 78)
firmware/sirc.pe Sony SIRC 12 bit. Hart 0 sends frames (40 kHz, pulse width coding) every 45 ms; hart 1 decodes by counting 40 us samples. 123 of 512 (hart 1 at word 55)
firmware/jvc.pe JVC. Hart 0 sends a frame with the header and repeats without it every 54.7 ms (38 kHz, pulse distance coding); hart 1 tells frames with a header from headerless repeats and counts repeats equal to the last frame. 151 of 512 (hart 1 at word 64)

They follow firmware/rc5.pe (transmitter on hart 0 with the carrier as half periods on a twait grid, wrp of three pin patterns) and firmware/nec_rx.pe (receiver counting samples). Assembling with RXIN = ENV makes one chip receive its own frames. The RTL is unchanged. Checked in simulation only, not on a board.

No manufacturer specification of these codes is public; the timing comes from secondary sources (see Sources).

Code Carrier Unit Frame Firmware
RC-6 mode 0 36 kHz, duty 25 % to 50 % t = 16 carrier periods (444 us) leader mark 6t, space 2t; start bit 1; mode bits 000; trailer bit (toggle) 2t + 2t; 8 control (address) and 8 information (command) bits MSB first; 1 = mark then space, 0 = space then mark; 6t signal free time CAR 347 ticks (36.02 kHz), t = 16 x 694 ticks = 444.16 us; the receiver reads each half bit in its centre from the last middle edge and needs the middle edge within one more half
Sony SIRC 12 40 kHz 600 us (24 periods) start burst 4 units, then for each bit a 1-unit space and a burst of 1 (0) or 2 (1) units; 7 command then 5 address bits LSB first; frames every 45 ms start to start CAR 312 (40.06 kHz), unit 24 x 624 ticks = 599.04 us; frame period 75 units = 44.93 ms
JVC 38 kHz 526 us (20 periods) header burst 16 units, space 8; per bit a 1-unit burst and a space of 1 (0) or 3 (1) units; 8 address then 8 command bits LSB first; a closing burst; repeats without the header every 50 to 60 ms CAR 329 (37.99 kHz), unit 20 x 658 ticks = 526.4 us; frame period 104 units = 54.75 ms

Receivers (sample counts at 40 us, SMP = 1000 ticks): SIRC start burst 50 to 70 samples (2.0 to 2.8 ms), a unit 8 to 22, two units 23 to 40; JVC header burst 180 or more (7.2 ms; the count saturates at 255), header space 80 to 130, a unit 7 to 20, three units 30 to 50. The RC-6 receiver needs a leader mark of at least 5t and a space of at most 3t.

Tests

test/test_ir2.py (cocotb). For each code a model written from the sources builds the frame as marks and spaces in units; the chip's envelope is recorded with clock times, every run must be an exact multiple of the unit and decodes to the sent fields; the carrier's high and low halves are measured on the LED pin. The receivers are driven by the models with stretched and jittered units. Tests at 1/8 (RC-6, SIRC) or 1/10 (JVC) of real time scale the units and the sample period by assembler constants, the models alike. Only the host interface above is taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_ir2

Controls

Each change was made in a copy and run with RC6_FW, SIRC_FW or JVC_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
RC-6: the trailer bit at single length (t per half instead of 2t) test_ir2_rc6_tx the envelope does not decode at bit 4, the trailer: its halves are not two runs of 2t
RC-6: the bit coding inverted (jc for jnc, a 1 sent as space then mark) test_ir2_rc6_tx the start bit decodes as 0
SIRC: bits sent MSB first (shl for shr) test_ir2_sirc_tx the envelope: the first bit's burst is 1 unit where the LSB of command 15h needs 2
SIRC: the gap constant 30 instead of 47 test_ir2_sirc_rx frames 34.744 ms apart at real time instead of 44.928 ms
JVC: repeats sent with the header test_ir2_jvc_rx in loopback 3 frames with a header and 0 repeats instead of 1 and 2
JVC: a 1 sent with a 2-unit space instead of 3 test_ir2_jvc_tx the envelope: the first 1 bit's space is 2 units

Limits

  • RC-6 mode 0 only (the receiver counts frames of other modes apart; RC-6A and the 32-bit modes are not decoded). SIRC 12 bit only (not 15 or 20 bit). JVC: no check of the 50 to 60 ms repeat window in the receiver; any headerless frame equal to the last one counts as a repeat.
  • The frame periods are fixed: RC-6 frames follow each other after the 6t signal free time; SIRC 45 ms; JVC 54.75 ms.
  • The carrier duty is 50 %, the upper end of RC-6's 25 % to 50 %.
  • Simulation only: no board, no gate-level run.
