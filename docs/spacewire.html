The SpaceWire line unit does the encoding layer of SpaceWire in hardware: Data-Strobe encoding and decoding, the parity of every character, the first Null, the Nulls between characters, disconnect detection and the controlled reset of the output. The firmware does the data link layer: the link state machine, flow control with FCTs and the two credit counts, packets and time-codes. The two meet at seven registers in the load/store space, so no instruction was added and tools/peasm.py and tools/peiss are unchanged.

firmware/spw.pe is a SpaceWire node on two harts: hart 0 runs the link state machine and receives, hart 1 sends. It echoes every packet it receives and keeps the last time-code. Simulation only: no SpaceWire device has been connected.

Source: ECSS-E-ST-50-12C Rev.1, "SpaceWire - Links, nodes, routers and networks", 15 May 2019, downloaded from ecss.nl without an account (MD5 82ae3517fa79023af6b909d8e804674c, the checksum ecss.nl lists for it). Clause numbers below are of that text.

Pins and mode

Signal Pin Direction
D out uo[6] out
S out uo[7] out
D in ui[6] in
S in ui[7] in

ETH_CFG[7:5] = 3 (ETH_CFG 0x60) selects the unit (rmii.md has the field). The four signals are single-ended logic levels on the dedicated pins; a SpaceWire link is LVDS (5.3.6), so the board needs an LVDS driver for D and S out and an LVDS receiver for D and S in, as for the 10BASE-T receive line. uo[6] and uo[7] are the OR of the unit's D and S flip-flops and the old value (gpo or TD+/TD-) gated by one mode flip-flop, the same pin structure as RMII; the unit's flip-flops are 0 outside SpaceWire mode (leaving the mode resets the transmitter). Change the mode only while the link is down.

Registers

In SpaceWire mode the load/store addresses 0x78 to 0x7E (frame bytes 88 to 94) are the unit's registers; the absolute ld/st forms reach them. The rest of the frame buffer and the data memory stay as they are. Reads have no side effect.

Address Name Read Write
0x78 K kind of the oldest received entry: 0 none, 1 data character, 2 control character, 3 broadcast code; 4 when an error is set and no entry is left
0x79 V its value: the data byte; the control code (FCT 0, EEP 1, EOP 2); the broadcast code's data byte removes that entry
0x7A S {gotNull, disconnect, parity error, ESC error, receive overflow, a Null sent, an FCT sent, room in the N-Char queue}
0x7B T queues a data character
0x7C C {broadcast code pending, 0 x4, FCTs requested and not started [2:0]} 0: requests an FCT; 1: queues an EEP; 2: queues an EOP
0x7D B sends a broadcast code (ESC and this data character) next
0x7E L {bit period - 1 [3:0], 0, 0, receive enable, transmit enable} the same; a 0 written to an enable resets that half

A control code is the two type bits with the first one sent as bit 0, so EOP (sent 0 then 1) is 2 and EEP (1 then 0) is 1, the values Figure 5-12 gives (0b10, 0b01). The N-Char queue holds two entries, the FCT requests up to seven, the receive ring eight entries.

What the hardware does (5.4)

  • Symbols (5.4.3): a data character P 0 D0..D7, a control character P 1 T0 T1, Null = ESC FCT, a broadcast code = ESC and a data character. The parity bit makes the 1s odd over the previous character's data or type bits, itself and the flag (5.4.3.4).
  • Data-Strobe (5.4.4): D is the bit, S changes when D does not. D and S are flip-flops and exactly one of them changes per bit.
  • Transmitter: while enabled it always sends, in the order of 5.5.6: a pending broadcast code, then a requested FCT, then an N-Char, else a Null. The first symbol after enabling is a Null whose first parity bit is 0, so the first edge is on S (5.4.5). A bit lasts L[7:4] + 1 clocks: 5 clocks (10 Mbit/s) after reset, from 1 clock (50 Mbit/s) to 16 (3.125 Mbit/s, within the allowed minimum of 5.4.10.2 b); a new value takes effect at the next bit boundary. a Null sent and an FCT sent are set when such a symbol has gone out completely.
  • Output reset (5.4.4 b to e): D = S = 0 after power-up; disabling the transmitter drops S at once and D five clocks (100 ns) later, never both at one edge (the delay is between the fastest bit period and 500 ns); the transmitter starts again only from D = S = 0.
  • Receiver: D and S come through the two-flip-flop synchronizer, one sample per clock. A change of D or S is a bit, of value D, so a received bit must last at least two clocks (25 Mbit/s). Until the first Null the last nine bits are compared with 0 1 1 1 0 1 0 0 0 (5.4.6, Figure 5-18: the Null with its three parity bits). Then each character is passed on only when the parity bit of the next one has checked it (5.4.2 c), Nulls are dropped, ESC and a data character become one broadcast code entry, ESC followed by ESC, EOP or EEP is an ESC error (5.4.9).
  • Disconnect (5.4.8): no change of D or S for 40 clocks after the first change since the receiver was enabled. With the synchronizer and the edge compare this is 840 to 860 ns after the last change at the pin (allowed 727 ns to 1 us).
  • An error (disconnect, parity, ESC, ring overflow) stops the decoder until the receiver is disabled. The entries already in the ring are read first; then K reads 4.

Where the link state machine lives: tick budget

One tick is 40 ns. At the initial 10 Mbit/s a bit is 100 ns (2.5 ticks), a data character 25 ticks, a control character 10, a Null 20, a broadcast code 35.

Task Time it allows In hardware or firmware Why
D/S encoding and decoding one bit, 2.5 ticks hardware below one tick
Parity, first-Null search per bit hardware bit-level
Nulls when nothing else is sent one every 20 ticks, forever hardware a hart writing a Null every 20 ticks would do nothing else; a gap of 727 ns (18 ticks) may already be a disconnect at the far end
Disconnect detection 727 ns to 1 us after the last edge, 18 to 25 ticks hardware a counter per clock; a firmware loop would have to read the lines every few ticks
Output reset S then D 100 ns apart hardware below three ticks
ErrorReset timer 6.4 us, allowed 5.82 to 7.22 us: 160 ticks, 145 to 180 firmware tset 160, twait: exact
ErrorWait, Started, Connecting timers 12.8 us, allowed 11.64 to 14.33 us: 320 ticks, 291 to 358 firmware tset 320 and polling loops of 7 (ErrorWait) to 17 ticks (Connecting): the state ends 320 to 337 ticks after tset
Reaction to an error not bounded in 5.5.7 firmware the unit has already stopped the receiver; the firmware disables both halves within one pass of its loop
Data character received (Run) one per 25 ticks at most firmware spw.pe takes 18 ticks from reading K to reading K again
FCT received one per 10 ticks, at most 7 in a row (5.5.4 i) firmware 10 ticks; the eight-entry ring holds a burst of seven
EOP or EEP received one per 10 ticks firmware 20 ticks; a run of more than about sixteen empty packets overflows the ring (Limits)
Data character sent one per 25 ticks firmware (hart 1) 31 ticks per character by count of spw.pe (not measured): at 10 Mbit/s about 80 % of the line, the unit fills the rest with Nulls
Credit counts, FCT requests per character firmware additions in the paths above

So the state machine and the credit counts are firmware: every timer of 5.5.7 is 160 ticks or more with a tolerance of 15 ticks or more, and the per-character work fits the character times at 10 Mbit/s once the unit absorbs the bit-level work, the Nulls and short bursts. In hardware the state machine would need a 10-bit timer, its states and the credit counters, and it would fix the start policy; it would not make any requirement easier to meet. The firmware cost bounds the sustained receive rate of data characters: 720 ns per character is 13.9 Mbit/s.

The node firmware (firmware/spw.pe)

228 words, both harts (hart 1 starts at label hart1). Settings with DATA_W before CTRL = 3: 0x00 MODE (bit 0 LinkStart, bit 1 AutoStart, bit 2 LinkDisabled, 5.5.3), 0x01 RUNL (the L value in Run; 0 means 10 Mbit/s). Status with DATA_R at any time: 0x02 state (0 ErrorReset to 5 Run), 0x07 the last broadcast code and 0x08 their count, 0x09 the number of times Run was left on an error and 0x0A the last cause (the unit's error bits, or 1 for an N-Char without receive credit, 2 for transmit credit above 56), 0x0B packets received. A byte the host writes into the FIFO is sent as a broadcast code in Run.

  • Hart 0: the state machine of Figure 5-19 with the actions of 5.5.7.2 to 5.5.7.7; in Connecting it requests seven FCTs (56 N-Chars of room); in Run it stores each N-Char into a ring of 64 (data in the frame buffer at 0x20 + i, a flag at 0xA0 + i: 0 data, 1 EEP, 2 EOP), counts the receive credit (an N-Char at credit 0 is a credit error, 5.5.5) and requests another FCT whenever the N-Chars held plus the credit given leave room for eight more of 56 (5.5.4 k, p). It counts received FCTs and checks that the transmit credit never exceeds 56.
  • Hart 1: in Run it sends the ring back, one N-Char per transmit credit (8 per FCT received minus the N-Chars sent); outside Run it drops what it held.

Formal (formal/run_formal_spw.sh, properties in pe_spw.v under ifdef FORMAL, every input free): D and S never change at one edge, including the reset; a transmitter that was off keeps both pins from rising and is not sending (so after a reset nothing is driven until a register write enables it); a receiver that was off holds no gotNull, error or entry; the ring and queue counts stay in range; a soft reset disables both halves. k-induction PASS (depth 24), BMC from reset PASS (24 clocks), ABC bmc3 PASS (100 clocks); 4 planted bugs (D and S dropped together, D raised while off, soft reset ignored, the ring count unbounded) each give a trace from reset (3 to 47 clocks). The chip-level power-on proof takes the SpaceWire register writes as a sink and shows that before START the transmitter is off and D = S = 0. formal/run_equiv_fsm.sh now also covers pe_spw, whose rph and tkind Yosys re-encodes.

Area

System Yosys 0.9, IHP typical library, flattened, macros excluded: 359,424.21 um^2, 21,607 cells, 3,554 flip-flops with RMII and SpaceWire; +17,479.21 um^2 over the RMII commit and +34,401.48 um^2 (+10.58 %) over int3. pe_spw alone: 18,367 um^2, 964 cells; the eight-entry receive ring is 80 of its flip-flops.

Limits

  • Not run with a SpaceWire device or LVDS parts; the physical layer (5.3) is the board's.
  • Leaving SpaceWire mode (an ETH_CFG write) resets the unit the same way: S falls at once, D five clocks later, so a high D stays on uo[6] for up to five clocks after the write, ORed with what the new mode puts there. Leave the mode with the link down.
  • Receive: a bit must last two clocks (25 Mbit/s); data characters are followed without loss up to about 13.9 Mbit/s (12.5 measured), and a run of control characters faster than the firmware takes them (for example more than about sixteen empty packets back to back at 10 Mbit/s) overflows the eight-entry ring and restarts the link.
  • Transmit: up to 50 Mbit/s on the line; the firmware feeds about one data character per 31 ticks.
  • spw.pe echoes packets and stores broadcast codes; it does not distinguish time-codes from distributed interrupts (5.6.4, 5.6.5), keeps no time-code counter of its own and has no routing. Packets cut by a link error are dropped, not ended with an EEP towards the network layer.
  • The receive credit is counted when an FCT is requested, not when it has gone out; this keeps the count at or above the far end's, so a credit error is never raised falsely.
