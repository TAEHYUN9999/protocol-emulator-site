File Role Words
firmware/dcc.pe Hart 0 is a DCC command station: packets from the host with the error detection byte added, 16-bit preambles, idle packets whenever there is nothing else, halves exact to the clock. Hart 1 is a DCC decoder: it times every half bit, needs 10 preamble bits, reads the bytes, checks the error detection byte and the address, keeps speed and direction, and reports its packets to the host. 243 of 512 (station 97, decoder 146)

No RTL change: existing instructions only (twait with tsetr for 58 and 100 us halves, shout of an alternating register for the polarity changes, waitp.frz and tgeth/tgetl to time the halves). Checked in simulation only.

Sources:

Source Used for
NMRA S-9.1 "Electrical Standards for Digital Command Control", July 2004 (the 2026 draft's table 2.1 has the same limits) a command station sends "1" parts of 55 to 61 us and "0" parts of 95 to 9900 us (12000 us per "0" bit at most), the parts of a "1" differ by 3 us at most; a decoder takes "1" parts of 52 to 64 us (differing by up to 6 us) and "0" parts of 90 to 10000 us; times between zero crossings
NMRA S-9.2 "Communications Standards for Digital Command Control", July 2004 preamble: a station sends at least 14 one bits, a decoder must not take fewer than 10 nor need more than 12; packet start bit 0, address byte, a 0 before each further byte, MSB first; packet end bit 1, which may count as a preamble bit of the next packet (footnote 3); the error detection byte is the XOR of the other bytes, a decoder ignores a packet that does not match; baseline packets: speed and direction 01DCSSSS (D = 1 forward), idle FF 00 FF, broadcast reset 00 00 00; figure 1: locomotive 55 forward at speed step 6 is 37 74 43

Pins

Constant Default Use
DCC P0 station output: the track polarity on the logic side of the booster's H bridge
DIN P0 decoder input (an optocoupler's output); by default the same pin, so one chip decodes its own station

Command station (hart 0)

Host to chip (FIFO): n (1 to 5), then n bytes (address and instructions); the station appends the error detection byte. Each host packet is sent once, as soon as the packet being sent ends; when no host packet is waiting it sends an idle packet, so the signal never stops. Each packet has a 16-bit preamble (the end bit of the one before makes 17). The host bytes are taken one per bit into a staging buffer, so the timing never waits for the host.

Every half is a twait period: the polarity changes one tick after the boundary (shout of 0x55) and the next period is set one tick later with H - 2, so a "1" half is exactly 1,450 ticks (58.00 us) and a "0" half 2,500 ticks (100.00 us); both halves of a bit are equal. SPKT (8) and SIDLE (9) count host and idle packets.

Decoder (hart 1)

edge waits for the next polarity change with the timer frozen at the edge and restarts it, so every half is timed to the tick. A half of 1,275 to 1,625 ticks (51 to 65 us) is a "1" half, 2,225 ticks (89 us) and more a "0" half (longer than 2.6 ms counts as 2.6 ms), anything else breaks the packet. These are the S-9.1 decoder windows with 1 us of margin for the edge detection. The decoder counts "1" halves; a "0" half after at least 20 of them (10 one bits) starts a packet; then each bit is two halves of the same kind, 8 bits per byte, a 0 before another byte and a 1 at the end. The end bit counts as two halves of the next preamble.

Data memory Use
0x10 DADDR the decoder's short address (host, before start)
0x11 DSPD, 0x12 DDIR the last speed and direction instruction for this address or broadcast: CSSSS and D; a broadcast reset sets DSPD to 0
0x13 DOK packets for this address or broadcast, also reported to the host as n, bytes (with the error byte)
0x14 DERR wrong error detection byte
0x15 DOTH other addresses
0x16 DIDL idle packets
0x17 DOVR reports lost because the FIFO was full

Tests

test/test_dcc.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_dcc

The model is written from S-9.1 and S-9.2, not from the firmware: the bits of a packet, a decoder of recorded halves that takes only the command station windows (55 to 61 and 95 to 9900 us) and needs 14 preamble bits, and a model station that drives any part widths.

test_dcc_station_longest was added on 2026-11-13 for a report of the static deadline check (petime.md): a late twait on a path where a staged host packet is copied within the first 100 ticks after the start. The test makes the station's packet set-up as long as it gets: the first packet (5 bytes, the most the station takes) is already in the FIFO when hart 0 starts, and two more 5-byte packets follow back to back. The first packet on the track is an idle packet, the three host packets follow with the right error bytes, every part is 2,900 or 5,000 clocks and the late flags are 0: the reported path cannot happen, because the "packet staged" byte SFULL is cleared just before it is read there and set only while a bit is being sent. With that test (RTL of 92b38df, same tools, three simulations sharing the machine): test_dcc TESTS=5 PASS=5 FAIL=0 SKIP=0, 234.0 ms simulated, 1,198 s wall. The host must keep n in 1 to 5: with n = 0 or above 5 the staging pointer runs over other data memory bytes.

Limits

  • Short (7-bit) addresses and the baseline speed and direction instruction only; extended packets (long addresses, 128-step speed, functions) are received and reported to the host but not decoded.
  • The station sends each host packet once (no automatic refresh or repetition); idle packets fill the gaps.
  • "0" halves longer than 2.6 ms are taken as zero halves without the 10 ms upper limit.
  • The decoder pushes each report to the FIFO and waits while it is full; the host must keep reading.
  • The booster, the track and the optocoupler are outside; the pin is the logic side.
  • Simulation only: no board, no gate-level run.
