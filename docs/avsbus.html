firmware/avsbus.pe Hart 0: a one-rail AVSBus slave in 3-wire mode (StartCode, 32-bit sub-frames, CRC-3, SlaveAck, StatusResponse, the Status Response frame after idle, back-to-back frames, 34-clock resynchronization, the alert on SData). Hart 1: a master run by host commands (one frame with both CRCs checked, resynchronization, the alert level). 503 of 512 (hart 1 starts at word 324)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (shin as a pin test, shout, high/low/rel, tsetr/twait, the CRC unit as a CRC-3, the host FIFO, the data memory); the RTL is unchanged. The two harts can face each other on one chip. Checked in simulation only, not on a board.

Section and table numbers are those of the PMBus Power System Management Protocol Specification Part III (AVSBus), Revision 1.3.1, 13 March 2015.

The clock is lowered: Table 3 gives tp 20 to 200 ns (5 to 50 MHz); here it is 40 kHz (312 ticks per half period), because the slave decodes a sub-frame and builds its answer between the last fall of the master sub-frame and the next rise (half a clock period).

Not implemented: 2-wire mode, more than one rail, CmdGroup 1 (answered 11b), the bus timeout, manufacturer-specific data types.

Pins

Constant Default Use
CLK P2 AVS_Clock, master output
MD P3 AVS_MData, master output
SD P4 AVS_SData, slave output

Timing

The slave polls the clock with shin (four ticks per poll), launches its bit right after it sees a rise and takes MData right after it sees a fall. After the 32nd fall of a master sub-frame it has half a clock period to check the StartCode and the CRC, execute the command, build the slave sub-frame and its CRC: at 40 kHz that is 312 ticks. The master runs its clock from the timer, 312 ticks per half period by default.

Host interface

Master (hart 1) commands (FIFO) and answers: 01h c s dh dl, one frame with c = Cmd << 5 | CmdGroup << 4 | CmdDataType and s = Select [status frame byte 0 (prefix, 0, StatusResponse), slave sub-frame byte 0 (SlaveAck, 0, StatusResponse), data high, data low, CRC flags (bit 0 status frame right, bit 1 slave sub-frame right)]; 02h, 40 clocks with MData high [SData level]; 03h [SData level while idle: 0 means an alert].

Address Use
0x00..0x07 slave: voltage, reset voltage, VOUT_MIN, VOUT_MAX (high byte first; 0 for VOUT_MAX: 900, 900, 600, 1200 mV)
0x08..0x0E slave: transition rate, current, temperature, power mode
0x0F, 0x10 slave: AVSBus status (VDone is added when read)
0x13, 0x14 slave counts: master sub-frames, bad CRCs
0x1D, 0x1E master: clock half period in ticks (0: 312)

Controls

Each change was made in a copy of avsbus.pe and run with AVS_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Slave without the VOUT_MAX check test_avs_slave 1500 mV accepted (00b instead of 11b)
Slave never shows an alert (idle level and prefix always 1) test_avs_overlap_resync_alert SData high while idle with OCW set
Master drives MData low during the slave sub-frame test_avs_master MData not 1 during the slave sub-frame

Limits

  • 40 kHz instead of 5 to 50 MHz.
  • One rail; CmdGroup 1 and manufacturer data types answered 11b.
  • The slave does not time out a frame left half-way; it relies on the 34-clock resynchronization.
  • Simulation only: no board, no gate-level run.
