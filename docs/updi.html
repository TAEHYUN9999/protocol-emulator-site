firmware/updi.pe The programmer side of AVR UPDI on one open-drain wire: the enable pulse, 8E2 frames, SYNCH before every instruction, double BREAK recovery, LDCS, STCS and KEY with the System Information Block, run by host commands. 180 of 512

This protocol was not part of the design when the RTL was written. It uses only existing instructions (low/rel, shout.lsb.od, shin.lsb, waitp.to, tsetr/twait, the CRC unit as a parity counter, host FIFO); the RTL is unchanged. One hart. Checked in simulation only, not on a board.

Section numbers are those of the Microchip ATtiny417/814/816/817 data sheet (DS40002288A, 2020), chapter 33 "UPDI - Unified Program and Debug Interface" and 36.21 "UPDI Timing".

Spec item Section Firmware
DATA frame: start, 8 data bits LSB first, even parity, two stop bits 33.3.1, Figure 33-3 tx, rx (parity and both stop bits checked)
Enable: the programmer pulls the line low 0.2 to 1 us (TDeb0); the UPDI holds it low 10 to 200 us (TUPDI); the programmer leaves it released 200 us to 14 ms (TDebZ), then SYNCH; the first instruction needs no second SYNCH 33.3.2.1.1, Figure 33-4, Table 36-36 en: 12 ticks low (0.48 us), wait for the line to go high (at most 0.5 ms), 0.5 ms more, SYNCH, LDCS STATUSA
SYNCH 55h before every instruction 33.3.1.3, 33.3.3 sync
BREAK: 12 or more low bits; send two to recover from any state; then SYNCH and LDCS STATUSB 33.3.1.2, 33.3.2.3 brk: 13 low bits, 2 high, 13 low
The UPDI waits its guard time before answering; the programmer leaves at least one idle bit after the UPDI's last frame 33.3.2.4 rx waits up to WT bits for a start bit; tx starts 1.5 bits after the end of a received frame
LDCS 100 0 aaaa (one byte back), STCS 110 0 aaaa (no answer), KEY 111 0 0 S CC (E5h: send the 16-byte SIB) 33.3.3, Figure 33-7, 33.3.3.5, 33.3.3.6, 33.3.3.8 commands 03h, 04h, 05h
SIB: Family_ID, NVM_VERSION, OCD_VERSION, DBG_OSC_FREQ as ASCII 33.3.7, Figure 33-19 stored at 0xA0
STATUSA 00h (UPDIREV), STATUSB 01h (PESIG, cleared on read), CTRLA 02h (GTVAL) 33.5 read and written by LDCS/STCS

Not implemented: LD, ST, LDS, STS, REPEAT, the NVM programming keys and sequences, high-voltage enable, a baud rate taken from the target (the programmer's bit time is set by the host).

Pins

Constant Default Use
UPDI P0 the UPDI line, open drain; the target has the pull-up

Host interface

Commands (FIFO) and answers: 01h enable [status, STATUSA]; 02h recovery [status, STATUSB]; 03h a LDCS a [status, value]; 04h a d STCS a, d [0]; 05h KEY SIB [status, bytes received]. Status: 0 ok, 1 no answer within WT bits, 2 parity error, 3 stop bit error, 4 the line did not come back high after the enable pulse.

Address Use
0x00, 0x01 bit time in ticks, high and low byte (0: 400, 16 us, 62.5 kbit/s; Table 33-1 recommends 225 kbit/s down to 0.075 kbit/s for the default 4 MHz UPDI clock)
0x02 WT answer wait in bits (0: 200; the UPDI's default guard time is 128 bits)
0xA0..0xAF the SIB

Tests

test/test_updi.py (cocotb). The target model is written from chapter 33 (sections in the module docstring): it holds the line low after the enable pulse, measures the baud rate from the SYNCH, samples every frame in the middle of its bits, answers after its guard time, enters the error state on a parity or stop bit error, and takes BREAKs. It records the programmer's drive changes with clock times. Only the host interface above is taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_updi

Controls

Each change was made in a copy of updi.pe and run with UPDI_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Odd parity in sent frames (the CRC register started at 8000h) test_updi_session the target takes the first instruction as a parity error and does not answer: STATUSA status 1
LDCS from host command 03h sent without a SYNCH (jz ldcs1) test_updi_session the target waits for a SYNCH and ignores LDCS CTRLA: status 1
The enable pulse 30 ticks long test_updi_session TDeb0 1.2 us, more than 1 us
The parity of a received frame not checked test_updi_errors the wrong parity reported as status 0

Limits

  • Only the control and status space and the SIB; memory access (LD, ST, LDS, STS, REPEAT) and NVM programming are not implemented.
  • The BREAK is 13 bits at the programmer's bit time, not the 6.15 to 24.6 ms of Table 33-3 for a target whose baud rate is unknown; it is meant for recovery while the target follows the programmer's rate.
  • Simulation only: no board, no gate-level run.
