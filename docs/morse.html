File Role Words
firmware/morse.pe Hart 0 keys host text (A-Z, a-z, 0-9, space) on a key line with exact dot, dash and space lengths on a unit grid. Hart 1 times the marks and spaces of a key input, decides dot or dash and letter or word gaps at the midpoints, and sends the letters (and a space after each word) to the host. Assembled with RXP = 0 the receiver reads the sender's own pin: a loopback on one chip. 269 of 512 (hart 1 from word 183)

No RTL change. Checked in simulation only. The key line is logic level (a keyed transmitter or a tone detector is outside).

Source

Recommendation ITU-R M.1677-1 (10/2009), "International Morse code" (original):

Section Used for
1.1.1, 1.1.2 the letters a-z and the figures 0-9
2.1 a dash is equal to three dots
2.2 the space between the signals forming the same letter is one dot
2.3 the space between two letters is three dots
2.4 the space between two words is seven dots

The default unit of 60 ms is 20 words per minute by the usual PARIS convention (50 units a word); that convention is not in M.1677-1.

Pins and settings

Pin Use
P0 KEY out, high = key down
P1 key in (RXP; 0 for the loopback build)
Data memory (DATA_W before the run) Use Default (0)
0x00-0x01 UNIT, ticks, high byte first (a multiple of 8, at least 96) 25000 (1 ms)
0x02 K: the unit is UNIT x K ticks (1 to 63) 60 (60 ms)
0xA0-0xC3 the code table, written by hart 0 at start: per letter A-Z, then figure 0-9, a 1 then the signals (dash 1, dot 0), right-aligned

How it works

Sender: the twait period is UNIT; a mark of n units is n x K twaits, and both key edges are the 4th instruction after a twait (the rising edge after a twait and three nops, the falling edge after the twait that ends the wait), so each mark and space is an exact number of units: dot 1, dash 3, 1 between signals, 3 after a letter, 7 between words (a space character adds 4 to the 3). A space of n units is n x K - 1 twaits, the next code is looked up, and the next mark's own twait completes it. When the host has no byte ready at the end of a gap the transmission pauses and the grid starts again (tsetr) with the next byte, so the late flag stays 0. Unknown bytes are skipped. The host paces itself on the 4-byte input FIFO.

Receiver: the key input is sampled every UNIT / 8 ticks and the runs are counted in eighths of a unit (K samples each), so the thresholds are fixed: a mark of 2 units or more is a dash (the middle between 1 and 3); a space that reaches 2 units ends the letter (the middle between 1 and 3) and the letter goes out at once; a space that reaches 5 units (between 3 and 7) sends a space character. A sequence not in the table, or more than 6 signals, gives '?'. The letters go to the host with txb.nb.

Tests

test/test_morse.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_morse

The model gives the runs of a text from M.1677-1 and decodes a key line whose every run must be a whole number of units (1 or 3 for marks; 1, 3 or 7 for spaces). The model sender for the receiver stretches or shrinks every run at random by up to 25 %. A 60 ms unit is too long to simulate, so the units are 80 us (UNIT 2000, K 1) and 120 us (UNIT 1000, K 3); everything scales with UNIT x K.

Limits

  • Letters and figures only (no punctuation or procedural signs: the sender skips them, the receiver gives '?').
  • A fixed unit: no adaptive speed tracking in the receiver; runs must stay within the midpoint thresholds (the test uses +-25 %).
  • The receiver needs hart 0 to have run (it writes the code table at start), so both harts are started even when only receiving.
  • 60 ms units (20 words per minute) were not simulated, only scaled units.
