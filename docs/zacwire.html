File Role Words
firmware/zacwire.pe Reads the single-wire ZACwire output of an IST TSic 206, 306 or 506: waits for a pause between transmissions, measures each packet's start bit as the strobe time, takes every later bit that long after its falling edge, checks both even parities and the five zero bits, and gives the host the two bytes of the 11-bit temperature. 117 of 1024 (one hart)

Written in the flexibility rehearsal of 2026-11-20 (flexibility.md), on the RTL of 4d71a25 (git tree cd2dce2 of src/) without changing it.
It uses only existing instructions: waitp.to, waitp.to.frz with tgeth/tgetl to measure the start bit, tsetr/twait to wait that long after each falling edge, shin, par and rlc for the parity, tpre for the waits of milliseconds, ld/st and the host FIFO.
Checked in simulation only, not on a board.

Source

Source Used for
ZMD AG and IST AG, "TSic Technical Notes - ZACwire Digital Output", Rev. 2.3, October 17, 2006 1.1: packets of a start bit, 8 data bits MSB first and an even parity bit, 125 us bit window (8 kHz), line high when idle, two packets per temperature (5 zero bits and bits 10 to 8, then bits 7 to 0) with half a window high between them; 1.2: duty cycle coding, start bit 50 %, a 1 75 %, a 0 25 %, the example packet 0x96 with parity bit 0; 1.3: measure the start bit's low time (Tstrobe), sample Tstrobe after each falling edge; 1.4: push-pull driver, parity for long lines, 10 Hz update rate

The test model was written from this note alone.
The conversion of the 11-bit value to degrees and the sensor's tolerance on its bit window are in the TSic data sheet, which was not used: the firmware gives the raw value, and the test varies the window from 100 to 160 us.

Pins

Pin Use
P0 the TSic signal, input only; the sensor drives it push-pull

Timing

Item Source Firmware
Bit window 125 us nominal follows the start bit of each packet; read right at 100, 125 and 160 us in the tests
Sample point Tstrobe (the start bit's low time) after each falling edge Tstrobe as counted from the start bit, 2 to 3 ticks (80 to 120 ns) earlier than the true value because the count starts a few instructions after the falling edge; a 1 held low 48 % and a 0 held low 52 % of the window read right
Start bit 50 % duty cycle a low time under 2 us is refused (0xE4), so that twait never gets a period of 0
Between transmissions 10 Hz a read starts only after the line was high for 250 us; inside a transmission it is high for at most about 156 us (a parity bit 1 and the half stop bit)
Missing edge 300 us without the next edge ends the read with 0xE4
Time-out S_TO x 4 ms (data memory 0x00, 0 = 50: 200 ms, two update periods)

tools/petime.py firmware/zacwire.pe: PASS, both twaits in time with a margin of 49 ticks (since 2026-11-21).
The period of those twaits is the measured Tstrobe in two registers, and the firmware refuses a value under 50 ticks before it waits; the tool now carries the range of each register into the period (petime.md). With the tool of the rehearsal it was UNDECIDED (period-from-register), and the tests read the late flag instead (0 in every test).

Host interface (FIFO)

Command Bytes Answer
Read the next transmission 0x01 code, first data byte (bits 10 to 8 of the temperature), second data byte (bits 7 to 0)

Codes: 0xA0 read; 0xE2 no transmission before the time-out (bytes 0); 0xE4 a missing edge or a start bit under 2 us; 0xE5 a parity is odd; 0xE6 the first byte has a 1 in bits 7 to 3; 0xE0 an unknown command (that byte only).
The two bytes are also kept in data memory 0x02 and 0x03.

Tests

test/test_zacwire.py, run from test/ or from a private directory:

cd test && make -B COCOTB_TEST_MODULES=test_zacwire

The sensor model drives the line push-pull: each bit low first, then high, the start bit low 50 %, a 1 low 25 %, a 0 low 75 % of the window, even parity, half a window high between the packets.
It sends a transmission when the test asks for one, not every 100 ms.

Limits

  • One transmission per host command; the firmware does not stream the 10 Hz readings by itself.
  • The parity cannot see a duty error that turns every 1 into a 0 in a byte with an odd number of ones: the parity bit is misread with them (test_zacwire_timing_boundary).
  • No power switching of the sensor through a pin (the note's section 1.4.2); a read that comes during a transmission waits for the next one, up to 100 ms on a real sensor.
  • A line that toggles without a pause of 250 us keeps the read waiting until the time-out.
  • Logic levels only; the conversion to degrees is for the host.
  • Not run on a board and not at gate level.
