File Role Words
firmware/swo.pe Hart 1 is an SWO receiver for both TPIU pin protocols, NRZ (UART) and Manchester, with an ITM packet decoder: synchronization, overflow, instrumentation (stimulus) packets of 1, 2 or 4 bytes reported to the host, hardware (DWT) packets, local and global timestamps and extension packets counted and skipped, an error or a framing error makes it wait for the next synchronization packet. Hart 0 is an SWO transmitter (NRZ, or Manchester frames of up to 8 bytes) for bytes from the host. Both on P0 are a loopback. 279 of 512 (hart 0 56, hart 1 223)

No RTL change: existing instructions only (twait grid, shout.lsb, shin/shin.lsb, waitp/waitp.to, tsetr, ld/st, host FIFO). Checked in simulation only, not on a board.

Timing

Data memory 0x00 selects the protocol (0 NRZ, 1 Manchester) for both harts; 0x01, 0x02 the unit in ticks, high byte first: the NRZ bit (default 100 ticks, 250 kbit/s) or the Manchester symbol (default 50 ticks: symbols at 500 kHz, 250 kbit/s).

Transmitter: every edge comes one tick after a twait boundary, so NRZ bits are exactly one unit and Manchester symbols exactly one symbol; back-to-back NRZ bytes keep the grid (the next start bit right after the stop bit). A Manchester frame takes the host's bytes while they keep coming, up to 8, then holds the line low for at least two symbols.

Receiver, NRZ: it waits for the start edge, samples 1.5 units later and then every unit, checks the stop bit, and decodes the byte while the next start bit runs (1.5 units of room) or after one unit of idle line, so the decoder never delays the next start edge. Manchester: from each middle edge it waits 1.5 symbols to read the next bit's first half, then waits up to one symbol for that bit's middle edge (a 1 falls, a 0 rises); the timer is set at the middle edge before the decoder runs, so a byte is decoded inside the next bit. A first half that is low with no rise after it is the stop (between bytes: the frame ends; inside a byte: a framing error).

Parameter Value
Transmitter NRZ bit 200 clocks (100 ticks); every run of the line a multiple of 200 clocks
Transmitter Manchester symbol 100 clocks (50 ticks); runs of 100 or 200 clocks inside a frame; the stop and idle at least 206 clocks
Receiver rate tolerance checked 250 kbit/s and +-2 %, NRZ back to back and Manchester with 2-symbol gaps

Host interface

Hart 1 sends, for each instrumentation packet, its header byte (port in bits 7..3, size in bits 1..0) and then the payload, least significant byte first. It waits while the FIFO is full, so the host must read about as fast as packets arrive.

Data memory Use
0x10 synchronization packets
0x11 overflow packets
0x12 instrumentation packets
0x13 hardware (DWT) packets
0x14 timestamps (local 1 and 2, global)
0x15 extension packets
0x16 header errors (then waiting for a synchronization packet)
0x17 framing errors (NRZ stop bit 0, Manchester frame stopped inside a byte or stuck high; then waiting for a synchronization packet)
0x18 bytes received

Hart 0 sends the host's bytes as they come; the host builds the ITM packets.

Tests

test/test_swo.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_swo

The models are written from the sources above, not from the firmware: ITM packet builders (synchronization, overflow, stimulus, hardware, local timestamps 1 and 2, global timestamp, stimulus page), a reference decoder that gives the instrumentation packets and the counts, an NRZ and a Manchester line driver (any rate, gaps, a bad stop bit, a frame cut inside a byte), and NRZ and Manchester decoders of the recorded line. Only the pin, the host bytes and the data memory addresses come from the firmware header.

Controls

Each control is a copy of swo.pe with one planted change, run with SWO_FW=<path>. All fail, each at the check it aims at.

Limits

  • Global timestamp 2 (B4h) is skipped by continuation bits like global timestamp 1; its 4-or-6-byte rule is not used. Hardware packets are skipped, not decoded (no PC sampling or exception trace output).
  • The receiver does not measure the rate: the unit is set in the data memory (TPIU prescalers are fixed and known). Checked within +-2 %.
  • No TPIU formatter frames (FF FF FF 7F sync, 16-byte frames): the receiver expects the formatter bypassed, the usual SWO setting.
  • Stimulus page extensions are counted but the page is not added to the port number.
  • The host must keep up with the stimulus packets (the receiver waits on a full FIFO).
  • Simulation only: no board, no gate-level run.
