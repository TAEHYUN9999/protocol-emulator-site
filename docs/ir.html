These protocols were not part of the design when the RTL was written; they use only existing instructions (wrp/woe, shin, waitp/waitp.to, tset/tsetr/twait, ld/st). The RTL is unchanged. Checked in simulation only, not on a board.

Sources

Vishay Semiconductors, "Data Formats for IR Remote Control", document 80071, Rev. 2.3 (26 June 2024):

Code Item
NEC 38 kHz carrier; leader: 9 ms burst, 4.5 ms pause; pulse distance coding, 1.125 ms burst to burst for 0, 2.25 ms for 1; 8 address bits, 8 command bits, each followed by its inverse; while a key is held only the leader and one bit are repeated, in 108 ms slots
RC-5 36 kHz carrier; bi-phase coding, a rising edge of the burst envelope in the middle of a bit is a 1; two start bits, a toggle bit, 5 address bits, 6 command bits; half a bit without and half with a burst of 32 carrier pulses; bit length 1.78 ms; the word is repeated every 114 ms

Secondary sources, for what Vishay leaves out: the NEC unit of 562.5 us, the order LSB first and the repeat code as 9 ms burst, 2.25 ms pause and one 562.5 us burst (Linux rc-core ir-nec-decoder.c, SB-Projects NEC page); the RC-5 start bits both 1 and RC-5X, where the second start bit is the inverse of command bit 6 (SB-Projects RC-5 page). The original NEC (uPD6121) and Philips data sheets were not read.

NEC receiver (nec_rx.pe)

The input (RXIN, P2) is at MARK during a burst: 0 for the usual active-low receiver module, 1 for an envelope such as the output of firmware/gen/nec_ir.pe. The line is sampled every SMP = 1000 ticks (40 us); nmrk and nspc count the samples of a mark or a space (stopping at 255), and each is judged against a window:

Element Nominal Window (samples of 40 us)
Leader mark 9 ms 200 to 255
Leader space, frame 4.5 ms 87 to 137
Leader space, repeat code 2.25 ms 44 to 68
Bit mark, closing mark of a repeat code 562.5 us 9 to 21
Space of a 0 562.5 us 9 to 21
Space of a 1 1687.5 us 34 to 50

A count is the number of samples after the first one at that level, so a nominal 562.5 us gives 13 or 14. A frame with a bad mark or space after a right leader is counted in NERR; a bad leader is ignored. Results in the data memory:

Address Use
0x18 NCNT frames received
0x19 NREP repeat codes
0x1A NERR frames broken off after a right leader
0x1B NST last frame: 0 address and command each with their inverse; 1 command with its inverse, the address 16 bits (extended NEC); 2 command inverse wrong
0x1C to 0x1F NDAT last frame: the four bytes as received (LSB first on the line)

RC-5 (rc5.pe)

Transmitter (hart 0)

Host to chip: a (bit 5 toggle, bits 4..0 address), c (command 0 to 127; 64 and up are RC-5X, sent with the second start bit 0), n (frames, 1 to 255). The frames start RPER = 64 bit times apart (113.7 ms), the toggle bit kept, as a held key. After the last frame the chip answers 0.

Pin Use
IR (P0) IR LED drive: the carrier during a burst, low otherwise
ENV (P1) envelope, low during a burst (the shape a receiver module gives)

Every pin change comes one tick after a boundary of a grid of CAR = 347 ticks (13.88 us): the carrier is 694 ticks, 36.023 kHz with a 50 % duty cycle, a burst is 32 carrier periods (888.3 us), a bit 64 carrier periods (1.7766 ms, 0.07 % under the nominal 64 periods of 36 kHz). The two pins change together (wrp), so the first carrier edge of a burst and the envelope's fall are in the same clock.

Receiver (hart 1)

The input (RXIN, P2) is low during a burst. The receiver waits for the first fall (the middle of S1), then for each of the other 13 bits: 3/4 of a bit after the last mid-bit edge it reads the first half of the bit, and the mid-bit edge must follow within another half bit; its direction is the bit (falling: 1, rising: 0). The bit time is the nominal 1.7778 ms of RC-5, not the transmitter's; resynchronizing on every bit lets the transmitter be 25 % off either way. A missing mid-bit edge counts the frame in RERR.

Address Use
0x10 RCNT frames received
0x11 RADR toggle << 5 | address
0x12 RCMD command; bit 6 is NOT S2 (RC-5X)
0x13 RERR frames broken off

Assembling with RXIN = ENV lets the receiver decode the chip's own transmitter.

Tests

test/test_ir.py (cocotb). The NEC sender model drives a receiver module's output from the timings above, with any scale and timing error; the RC-5 sender model drives bi-phase frames; the RC-5 line checker decodes the envelope pin, checks every envelope and carrier edge against its grid and counts the carrier pulses of every burst. Several tests run the same code at 1/10 (NEC, SMP = 100) or 1/8 (RC-5, CAR = 43 and the receiver's constants) of the real times, with the models scaled alike; each protocol also runs at its real times. Only the host interface (commands, answers, data memory addresses, assembler constants) comes from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_ir

Controls

Each change was made in a copy of the firmware and run with NEC_FW or RC5_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
NEC: no inverse check of the command (ldi r1, 0 for 2) test_nec_rx the frame with a wrong command inverse is reported with status 0
NEC: the repeat code not recognized (its window removed) test_nec_rx 0 repeat codes counted where 3 were sent
RC-5 transmitter: halves swapped (1 = burst then none) test_rc5_tx the envelope checker: bit 3 of the first frame is not a valid bi-phase pair against the frame's start
RC-5 transmitter: 31 carrier pulses per burst test_rc5_tx_default_period an envelope edge off the half-bit grid
RC-5 receiver: the bit taken from the first half (values swapped) test_rc5_rx the first frame decoded as 0x3A, 0x4A

Limits

  • No NEC transmitter is written by hand here: firmware/gen/nec_ir.pe sends the envelope only, without the 38 kHz carrier and without repeat codes. The NEC receiver takes the output of a receiver module, not the raw carrier.
  • The RC-5 carrier has a 50 % duty cycle (IR LEDs are often driven at 25 to 33 %); the tick grid gives 36.023 kHz, not 36.000.
  • The receivers do not check the 108 ms (NEC) or 114 ms (RC-5) slots, and the RC-5 receiver does not compare toggle bits of successive frames (the host can, from RADR).
  • The NEC receiver keeps only the last frame; the host must read it before the next one ends. Extended NEC (16-bit address) is reported with its two address bytes, nothing else is decoded.
  • Simulation only: no board, no gate-level run, no real receiver module.
