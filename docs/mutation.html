How many bugs planted in the RTL does the cocotb suite catch? This page gives the method, the rules and the numbers, so the score can be checked and reproduced. The scripts are in tools/mutation/private repo file.

Method

  1. Generate. mutgen.py parses the eleven simulated source files (test/Makefile PROJECT_SOURCES) and lists every place where one of the operators below applies: 2,104 candidates. It then samples a fixed number per module with a fixed seed.
  2. Baseline. mutrun.py baseline runs every one of the 144 test cases of the 21 test modules alone, as its own simulation, on the unmodified design. All 144 pass alone, so a case can be used on its own and in any order. The measured time of each case sets its order and its time limit.
  3. Run. Each mutant run with the mutant in place gets its own sandbox: a copy of src/ with the one edit, copies of test/ and tools/*.py, links to firmware/ and macro/, its own sim_build/. A shadow run (below) has one sandbox with the unmodified design and renamed copies of the mutated modules. Nothing in the repository is written.
  4. Judge. A mutant is killed when one test case fails, errors or runs past its time limit. A survivor has passed every case it was run against and has been shown, case by case, unable to fail the others (shadows, below), except where a number of unchecked cases is reported.
  5. Classify. Every survivor is read and put in one of three classes (below), and the simple test gaps are closed with new tests.

Why source-level operators and not Yosys mutate

MCY drives Yosys mutate, which flips, inverts or ties single bits of netlist cells. That was the other option. Source-level operators were chosen because:

  • The tests stay valid. The simulation is the RTL the suite already passes, with one edit. A mutated Yosys netlist would replace the RTL by a netlist, whose X handling differs (an if on X takes the else branch in RTL, a $mux with an X select gives X), and three test modules read an internal signal by name (user_project.u_core.slot in test_spi, test_device, test_i2c).
  • The faults are design mistakes. A wrong operator, an off-by-one constant, a missing assignment or a negated condition is the kind of bug a suite is meant to catch; stuck-at faults on netlist bits are closer to manufacturing faults.
  • Every mutant is a one-line diff of the source, so each survivor can be read and classified.

Yosys is still used where it is strong: proving survivors equivalent (below). What is lost is mutate -list's coverage-guided choice of sites; the sampler spreads the sample over source lines and operators instead.

What is not mutated, and duplicates

  • Code inside `ifdef FORMAL (neither simulated nor synthesized).
  • _unused wires (by construction they drive nothing).
  • localparam declarations without a range: they are opcode and FSM state encodings, where a new value is a re-encoding, not a bug. Their uses are mutated (state == S_CTRL by ROR). Sized localparam values are design constants (timing limits, CRC polynomial and residue) and are mutated by CONST.
  • for loop headers, the left side of assignments, port and range declarations, parameter defaults (every pe_ffmem instance overrides them) and the port-only SRAM stub in src/ (simulation uses the PDK model in macro/).
  • Negating the condition of an if or ?: is skipped when the condition is !x, a == b or a != b: the result is the same as the UOD or ROR mutant of that operator.

A mutant that does not compile would be invalid and left out of every score. With these rules all of the sampled mutants compile.

Test selection and judging

The full suite is 144 cases and about 3.8 CPU hours on the shared server (13,657 s measured case by case under its usual load; 5,768 s when it was quieter). Running it for every mutant is out of reach, so each mutant goes through stages, and every stage either kills it or hands it on:

Stage Which mutants Which cases How
quick all the fastest cases of the test modules selected for the mutated RTL module, up to 120 s of baseline time the mutant in place, one case at a time, stop at the first failure
shadow, module survivors of quick, except core and top level every remaining case the unmodified chip plus a shadow copy of the mutated module at each of its instances (below)
medium core and top-level survivors of quick; survivors whose module shadow differed every remaining case up to 60 s of baseline time (where a shadow differed) the mutant in place, one case at a time, stop at the first failure
shadow, chip reset-branch survivors, core and top-level survivors every remaining case the unmodified chip plus a shadow copy of the whole chip with the mutant inside
rest survivors the cases where a shadow differed or that no shadow covered the mutant in place, spread over the workers, stop at the first failure
formal survivors equivalence check of the mutated module, below

So a mutant reported as survived has, for each case, either passed it with the mutant in place or been shown unable to fail it, except for the unchecked cases reported with it. Of the 328 kills, the quick stage made 293, cases of up to 60 s made 32 more and longer cases 3 (pe_pel_026 by test_pel_spi_device_sweep, pe_eth_tx_011 and pe_eth_tx_026 by test_eth_frame_and_link_pulses).

Shadows. A shadow is an instance of the mutated copy of a module, fed by hierarchical reference with the same input nets as an original instance, whose outputs are compared with the original's (mutshadow.py). The chip under test is the original, so the test runs exactly as on the original design. If no output of the shadow ever differs from the original during a case, the mutant cannot fail that case: put in place of the original, it hands the rest of the chip the same values at every time, so the test bench sees the same pins and does the same thing (the tests are deterministic; their random generators are seeded). Signals the tests read by name (u_core.slot) are compared too. Every compared signal is a function of flip-flops only (each chip input passes a register first, and the tests move rst_n on a rising clock edge), so it changes only at clock edges; the comparison is taken 5 ns after every rising and falling edge, which sees each settled value and none of the event ordering inside a time step. A shadow that has differed once is frozen (its inputs held at 0) and costs nothing for the rest of the case. Many mutants share one simulation, which is where the saving comes from: the test bench and the original chip are simulated once for all of them.

A module shadow is cheap but conservative (a difference at the module's outputs may never reach a pin); a chip shadow costs about 0.4 of a full simulation but compares exactly what the test bench sees (uo_out, uio_out, uio_oe and u_core.slot).

Mutants inside the rst_n branch of an always block (a different reset value, a deleted reset assignment) get one more rule at chip level: such a mutant has the original's logic as soon as reset is released. So when the whole state of its chip copy (all 337 flip-flop vectors from Yosys and the 512 SRAM words) equals the original's, and no pin has differed so far, the rest of the case is identical and the copy is frozen as "converged". A later reset assertion would count as a difference. Most reset mutants converge at the first soft reset, a few microseconds into the case.

Every shadow simulation also pays for the test bench and the original chip once, and a shadow that never differs is simulated for the whole case, so a group of shadows runs slower than the plain suite (measured 3.1 to 3.9 times for 79 small module shadows, 5.6 times for 10 chip copies). Mutants that would need a core or chip shadow therefore first go through the medium stage: most of them fail one of the short cases. Two checks of the method:

  • every killed mutant must differ in the case that killed it (if a case can fail the mutant, the shadow must see a difference there): 63 killed mutants were checked, 11 with module shadows and 52 with chip shadows, each in the case that killed it, and all 63 differed (one of them only when its case was rerun alone, after the shared run of that case hit its time limit)
  • a shadow of an unmodified module or chip must never differ: 4 unmodified chip shadows over test_pel_direct showed no difference.

Selection rule for the quick stage: a test module is selected for an RTL module when it exercises that module's function. The Ethernet transmitter and receiver select the seven test modules that send or receive frames (test_eth, test_eth_rx, test_net, test_mem512, test_spi, test_swd_gen, test_usb_gen); the launcher selects test_pel; the capture unit selects the modules that use capture or the frame buffer. Everything else (core, host interface, FIFO, memories, top level) is on the path of every test and selects all 21 modules. The rule only orders the work: a wrong guess costs time, never a verdict.

A test case kills a mutant by: an assertion failure or exception in the test, a simulator error or a missing result (error), or no result within 4 x its baseline time plus 60 s (timeout). Every timeout kill was rerun with a limit of 20 x baseline plus 600 s, so that the test's own time limit or a pass decides: all 26 failed again.

Equivalent mutants

Some mutants cannot be told from the original by any test. They are handled in two ways:

  1. Formal proof (automatic). mutequiv.py compares the mutated module (with its submodules flattened in) with the original in Yosys: equiv_make matches the ports and every flip-flop by name, internal wire names are hidden first so a difference masked before a flip-flop or port does not count, then equiv_simple -undef and equiv_induct -undef -seq 1 must prove every match. One-step induction is a statement about one clock step from any state in which the matched signals agree, so it holds for the falling-edge flip-flops and the asynchronous resets too. The check can miss an equivalence (a difference only in unreachable states), never claim a false one. pe_ffmem is checked at each of its three parameter sets; at the top level the SRAM macro is cut out (its inputs must match, its output is shared). Identity mutants (no edit) of pe_core, pe_eth_tx and the top level were proven, as a check of the check.
  2. By reading (manual). A survivor that the proof does not cover is read and put in one class: - equivalent: no input sequence after reset changes an output (the reason is written down, for example a register value that is always overwritten before use); - unreached: the behaviour does change, but only in a function or a corner the suite does not exercise; - gap: the suite exercises the behaviour but does not check it.

Scores:

  • raw = killed / valid mutants
  • adjusted = killed / (valid mutants - equivalent), equivalent = proven + by reading

What was not checked

  • Unchecked cases. 40 survivors miss some cases (count per mutant in results_seed1.mdprivate repo file): 15 reset-value mutants miss 2 cases (test_pegen_nec, test_uart_report_speed); the 10 core and top-level survivors miss 38 to 46 of the cases longer than 60 s; 8 launcher mutants miss 11 to 37 cases; 4 others (pe_hart_regs_005, _011, _012, pe_host_spi_022) miss 8 to 46; three reset-value mutants whose chip copy never converges (pe_pel_037, pe_eth_rx_024, pe_eth_tx_028) miss 119 to 128. The shadow stage made most cases cheap, but every shadow simulation still runs the test bench and the original chip, and the suite's long sweeps (up to 23 minutes for one case on the loaded server) dominate. The scores count these mutants as survivors.
  • The shadow argument rests on three facts of this design and suite, each checked: the tests are deterministic (every random generator in test/ is seeded); every signal compared is a function of flip-flops (all clocked blocks in src/ have the asynchronous reset, all chip inputs pass a register first); and the tests observe only uo_out, uio_out, uio_oe and u_core.slot (a search of test/ for user_project. finds only slot). 63 killed mutants were used as a check that a case that can fail a mutant does show a difference in the shadow; none failed it.
  • Formal check coverage. It proved 2 of the survivors equivalent; it cannot prove a mutant whose difference is masked only by reachability (most reset values). It was not run for top-level survivors (one top-level check takes more than 10 minutes); those are classified by reading.
  • Classification by reading is a judgement. Each note in classes_seed1.jsonprivate repo file gives the reason; a reviewer who disagrees can move a mutant between classes and rerun mutreport.py. Only the "equivalent" class changes the adjusted score.
  • RTL only. Mutants are simulated at RTL with Icarus; the gate-level netlist and the FPGA build are not part of the campaign.
  • One sample. 410 of 2,104 candidates with seed 1. A larger cap gives a superset of the same mutants (ids follow the pick order), so the campaign can be extended without rerunning these.

Reproduce

cd tools/mutation
S=/path/to/scratch; W=$S/campaign
python3 mutgen.py --seed 1 --out $S/mutants.json --cap pe_core=80 --cap pe_host_spi=60 \
  --cap pe_eth_rx=50 --cap pe_pel=50 --cap pe_eth_tx=40 --cap project=40 --cap pe_capture=30 \
  --cap pe_fifo=25 --cap pe_hart_regs=15
python3 mutrun.py baseline --work $W --jobs 12
python3 mutrun.py run    --work $W --mutants $S/mutants.json --jobs 12 --no-rest              # quick
python3 mutrun.py run    --work $W --mutants $S/mutants.json --jobs 12 --no-rest --medium 60 \
  --only <core and top-level survivors>                                                          # medium
python3 mutrun.py shadow --work $W --mutants $S/mutants.json --jobs 12 --group 80 \
  --modules <the other modules>                                                                  # module shadows
python3 mutrun.py shadow --work $W --mutants $S/mutants.json --jobs 12 --level chip --order short \
  --ids <survivors whose module shadow differed>                                                 # chip shadows
python3 mutrun.py run    --work $W --mutants $S/mutants.json --jobs 12                            # rest + formal
python3 mutrun.py verify-timeouts --work $W --mutants $S/mutants.json --jobs 4
# the new tests on every mutant still alive
python3 mutrun.py baseline --work $S/after --jobs 4 --cases '^test_outputs\.|test_rx_address_filter_every_byte'
python3 mutrun.py run --work $S/after --mutants $S/mutants.json --jobs 12 --no-formal --only <alive ids>
python3 mutreport.py --work $W --mutants $S/mutants.json --classes classes_seed1.json --after $S/after

Every command appends to records.jsonl in its work directory and continues where it stopped when run again. tools/mutation/README.mdprivate repo file has the details and the pitfalls met on the way.

Second campaign: the int2 RTL

The first campaign (above) ran on the 512-word RTL of branch mem512, before the per-hart pin registers, the extended instructions, the deep capture and the USB full-speed line unit. The second runs on the RTL of branch int2 (commit 156b801, src/ unchanged since 72daf64) against its whole suite: 63 cocotb modules, 365 test cases, and the 21 cases this campaign added (386 in all, 384 of which pass on the original; see What was not checked). It had three goals: carry the first sample over and kill its 32 survivors with tests, sample again including the new RTL, and check every survivor against every case, so that no score is a lower bound.

What changed in the method

  • Weak run (new). mutinf.py puts an infection monitor for every mutant into a copy of the original design, and mutrun.py weak runs every case once on it. A procedural edit is marked when its innermost statement runs; an edit of a continuous assignment or a port connection is marked when its value differs from the original's (a twin wire of the same width carries the edited expression). A mutant not marked in a case simulates exactly like the original there, event for event, so it cannot fail that case, whatever the case reads. This holds for test_iss_diff, which reads internal signals and where shadows do not apply. 12 mutants (localparam values, part-select targets) have no monitor and count as infected everywhere. As a check, mutrun.py weak-check compared 156 pairs of a killed mutant and the case that killed it: every mutant was marked in its killing case.
  • Strong cases first. After the quick stage, each parked mutant ran the cases that check its module most closely, for real (--first): the lockstep test (test_iss_diff), test_isa2, test_reset_state and test_outputs for the core, host interface, FIFO, memories and top level; test_pel_model and test_pel for the launcher; test_eth_rx and test_eth for the Ethernet units; the capture tests for the capture; test_usb_fs for the USB unit.
  • Shadows converge at module level too. A mutant in the rst_n branch acts only while the chip is in reset. Its module shadow is frozen as converged once every flip-flop of each shadow equals the original instance's and no output has differed, as chip shadows did in the first campaign; a later reset counts as a difference. Top-level mutants get chip shadows (--level mixed).
  • Every case. A survivor is checked against every case: run with the mutant in place, shown unable to fail it by the weak run, a module shadow or a chip shadow, or the whole mutant proven equivalent. Where that was not affordable the results say so per mutant (22 mutants, listed with their counts in results_seed2.mdprivate repo file).
  • Test cases that fail on the original are left out (test_eeprom93.test_mw_ops and test_mw_2mhz fail on 156b801 when run alone; see What was not checked).
  • Fixes found on the way. The generator ordered modules with equal candidate counts by Python's set order, which changes with the hash seed (int2 has pe_eth_rx and pe_pel at 276 each): ties are now broken by name, and seed 1 regenerates unchanged. Shadow runs kept only the last 20,000 characters of a log, so a mark printed early in a long log could be lost: they now keep the whole log (the first campaign's shadow results were read from truncated logs; its killed mutants all differed in their killing case, which does not rule this out for the passed ones). test_sent.py draws jitter from Python's global generator, which cocotb seeds from the clock unless COCOTB_RANDOM_SEED is set: the runner now sets it, since shadows and the weak run assume deterministic tests. The test list missed decorators with a call in their arguments (skip=not hart_wired_and()). mutreport.py did not count the weak run for test_iss_diff.

Findings beyond the score

  • Launcher error term overflowed at d = -8; fixed on branch pelfix. src/pe_pel.v takes an interval as consistent when it is -8 to +7 clocks from the integer period (d[15:3] all zeros or all ones), while its comment said -4 to +3 "(then err_per fits 12 bits)". At d = -8 with a non-zero fraction of per, err_per = {d[3:0], 8'd0} - per[7:0] was below -2048 and wrapped to a positive value near +8 clocks, so the phase correction dph moved the wrong way, and with a fraction above 8/256 the estimate too (up to 8/256 the + 8 of the rounding wrapped err_r back). This campaign first wrote that no test reached it. That was wrong: test_pel_launch_offsets_exact passes d = -8 twice (fractions 153/256 and 255/256) and passed only because its model followed the RTL, wrap included. On pelfix the model computes the error and dph without a width, and on the RTL of a40404a three cases fail: that one (the fourth launch 13 clocks early), and two new ones, test_pel_short_interval_exact (after an interval 8.9961 clocks short, PEL_R rises from 231.9961 to 232.4336; the model gives 231.4336) and test_pel_period_step_down_exact (the first launch 14 clocks early). The fix keeps the window, which every test and the board sweep used, and widens the arithmetic: the error to 13 bits (-2303 to 1792) and dph to 6.8. The second is needed too: with the error right, a period step of -8 clocks takes dph - err to 33.6 clocks, which wrapped the 14-bit difference (the step-down case fails on that intermediate RTL, its eighth launch 56 clocks early). Narrowing the window to the comment's -4 to +3 instead would have changed the lock behaviour two cases rely on and still left the 14-bit dph - err able to wrap (an exhaustive search of the update over that window reaches 9381 > 8191; for -3 to +3 it stays at 7288). Property 6 of formal/pe_pel_props.sv now proves the update without a width (k-induction): per never moves away from the measured interval, and a consistent interval gives the header's update on wide integers. On the old RTL it fails: k-induction at once, and BMC from reset at step 17 with edges 11, 3 and 1 clocks apart, where the third interval is 8 clocks short of per = 9 + 2/256 and the 12-bit err_per is +2046 instead of -2050 (formal/logs/pel_orig_20261112). One more case, and a third step of an existing one, came from mutants of the fixed lines. All 101 candidates of the estimator and launch arithmetic and of the per/dph assignments (lines 80 to 105 and 170 to 175, every operator, not sampled) ran against the 12 cases of test_pel_model and test_pel: 88 killed.
