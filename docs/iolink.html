File Role Words
firmware/iolink.pe An IO-Link device on the logic side of a transceiver: waits in SIO mode for the wake-up request, then answers M-sequences TYPE_0 at COM2 (38.4 kbit/s, 8E1): page channel reads and writes, the 6-bit checksums in CKT and CKS, the response time tA, MasterCommands for the device states and Fallback. 236 of 512 (one hart)

No RTL change: existing instructions only (the twait grid at 651 ticks per bit, waitp.to.frz for the wake-up pulse width, shin.lsb/shout.lsb, the CRC unit as a parity generator). Checked in simulation only.

Source: IO-Link Interface and System Specification V1.1.3 (June 2019, IO-Link Community order no. 10.002), read from the published PDF:

Pins

Constant Default Use
RXD P0 receive data from the transceiver (UART polarity, idle high); the wake-up request also shows here
TXD P1 transmit data, push-pull, idle high
TXEN P2 high while the device drives C/Q

Timing

A bit is TB = 651 ticks (26.04 us, 38.402 kbit/s, 0.006 % from 38.4). The receiver waits for the start bit, checks it again at its middle, then samples every bit at its middle on a 651-tick grid that restarts at every start bit; it checks the even parity and the stop bit. The transmitter changes TXD one tick after each grid boundary, so every bit is exactly 1,302 clocks.

  • Wake-up: in SIO mode a low pulse on RXD of 65 to 95 us (1,625 to 2,375 ticks, measured with the frozen timer) is a wake-up request; the device is ready for the first message as soon as the pulse ends.
  • Inside a message the next octet's start bit must come within 2 T_BIT of the middle of the previous stop bit (t1 at most 1 T_BIT plus margin).
  • The answer's start bit comes TAP + 0.5 T_BIT after the end of the master's last stop bit: tA 2.52 to 2.55 T_BIT measured. TXEN rises one T_BIT earlier and falls at the end of the last stop bit; the octets of the answer follow each other with no gap (t2 = 0).

Device

Direct parameter page (page channel addresses 0x00 to 0x1F) at data memory 0xA0 to 0xBF, filled by the host with DATA_W before start (MinCycleTime, M-sequenceCapability, RevisionID, process data lengths, VendorID, DeviceID, FunctionID). Reads return it; writes are stored at 0x00 (MasterCommand), 0x01 (MasterCycleTime), 0x0F (SystemCommand) and 0x10 to 0x1F (page 2), and ignored (but answered) elsewhere. Other channels read as 0 and their writes are ignored.

Data memory Use
0 DST 0 SIO, 1 STARTUP (after the wake-up or MasterCommand 0x97), 2 PREOPERATE (0x9A), 3 OPERATE (0x99)
1 MWU wake-up requests taken
2 MOK messages answered
3 MERR messages not answered: parity, stop bit, M-sequence type not 0, checksum, an octet too late

MasterCommand 0x5A (Fallback) is answered, then the device returns to SIO and waits for the next wake-up request. CKS always has event 0 and PD status 0.

Tests

test/test_iolink.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_iolink

The master model is written from the specification, not from the firmware: the wake-up pulse, T_DMT, UART frames at exactly 38.4 kbit/s (or a chosen rate), TYPE_0 messages with the checksum computed from equations (A.1), a decoder of the device's TXD with parity and stop checks, the device checksum check, tA and t2 limits, and the bit grid of every answer edge. Two checksum vectors were worked out by hand from (A.1): a read of MinCycleTime is A2 00, and an answer OD 05 has CKS 2E.

Limits

  • COM2 only, and only M-sequence TYPE_0 on the page channel: no TYPE_1_x/TYPE_2_x, no process data, no ISDU, no events (event flag always 0), no diagnosis channel content.
  • No T_DSIO: the device does not fall back to SIO by itself when the master stops; a wake-up request during SDCI is taken for a broken octet, not detected as a wake-up.
  • The wake-up request is detected as a pulse on the logic RXD line; a real device's transceiver detects the current pulse on C/Q.
  • The answer time is fixed by TAP (tA 2.5 T_BIT by default; 1 to 9 grid periods give 1.5 to 9.5 T_BIT).
  • Simulation only: no board, no gate-level run.
