File Role Words
firmware/pca9555.pe The chip answers on I2C as a PCA9555 16-bit I/O expander: input, output, polarity inversion and configuration register pairs behind a command byte, writes and reads that alternate inside the pair, input data taken at the ACK clock, outputs on the pins as configured, and an open-drain INT that goes low when an input changes and is reset per port when that port is read or the pin returns. Hart 0 runs the bus and the outputs, hart 1 drives INT. 194 of 512 (hart 1 from word 164)

Source: Texas Instruments, "PCA9555 Remote 16-bit I2C and SMBus I/O Expander with Interrupt Output and Configuration Registers", SCPS131J (August 2005, revised March 2021); section numbers below are from it. No RTL change. Checked in simulation only.

Pins

Pin Use
P6 SCL (input)
P7 SDA (open drain)
P5 INT (open drain, driven by hart 1 only)
P0-P4 IO0_0 to IO0_4: port 0 bits 0-4, input (released) or push-pull output
uo[2]..uo[7] port 1 bits 0-5, output side: the output register bit, or 1 for a bit configured as input (a released pin with a pull-up)
ui[3]..ui[7] port 1 bits 0-4, input side

The chip has eight protocol pins, three of which go to SCL, SDA and INT, so only port 0 bits 0-4 are real bidirectional pins. Port 1 uses the general outputs and inputs, which are one-way pins: its input register reads ui, not the uo levels. Bits that have no pin (port 0 bits 5-7, port 1 input bits 5-7) read 1, like unconnected inputs with pull-ups, and their output register bits drive nothing. SCL and SDA need pull-ups (SCL must be P6 and SDA P7: the byte loop reads them together with rdp).

Data memory

Address Content
0x02-0x07 registers 2-7 (output 0/1, polarity 0/1, configuration 0/1): data address = register number
0x08, 0x09 the port 0 / port 1 levels last read through register 0 / 1 (INT reference)
0x10 A2..A0 (bits 2-0), written with DATA_W before the run; default 0, address 20h
0x11 own address byte, write form (firmware)

Behaviour

Data sheet Firmware
8.5.2.1 / Table 8-2: address 0100 A2 A1 A0; no general call address 20h + A2..A0 from 0x10; 00h is not acknowledged
Table 8-3: command byte, 3 bits; power-up output FFh, polarity 00h, configuration FFh the low 3 bits select the register; defaults written at start
8.5.2.3: input registers show the pin levels whatever the direction; writes to them have no effect port 0: P0-P4 as they are (an output reads its own level); port 1: ui; writes ignored
8.5.2.3: polarity inversion of pins defined as inputs input register = levels XOR (polarity AND configuration)
8.5.2.3: configuration 1 = input (high impedance), 0 = output P0-P4 released or driven; uo bit = output bit or 1
8.5.2.4.1: after one register the next byte goes to the other of the pair; no limit on bytes as stated; the outputs change in the ACK clock of each byte
8.5.2.4.2: reads alternate inside the pair; input data is taken at the rising edge of the ACK clock; after a restart the stored command is the register being read the pins are sampled at the rising edge of the address ACK and of each controller ACK; the stored command moves to the other register after an ACK and stays on the last one after the NACK, so the next read starts there
8.4.1: INT on a change of an input pin; reset when the pin returns or when the port that caused it is read (at the ACK or NACK clock); port 0 and 1 separately; outputs never cause it; output -> input may give a false interrupt hart 1 compares each port's input bits (configuration 1) with the levels last read from that port; hart 0 stores those levels at the ACK or NACK clock of a read of register 0 or 1
6.7: tiv, tir at most 4 us; tpv 200 ns after the ACK clock measured below

Not emulated: the INT errata of 8.4.1.1 (INT wrongly released when the last command byte was 00h and another device acknowledges a read) and the 1 us input hold time tph (the pins are sampled once, at the ACK clock rise).

Tests

test/test_pca9555.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_pca9555

Pca9555 is written from the data sheet sections above, not from the firmware: registers and defaults, the pair alternation of writes and reads, input values from the pin levels with the polarity inversion of input bits, the stored command after a read, the INT reference per port. The pins around the chip are test drivers (P0-P4 with pull-ups, ui). The controller and bus monitor are the UM10204 models of test_i2c.py at 400 kHz.

Controls

Each control is a copy of pca9555.pe with one planted bug, run with PCA_FW=<path>. All three fail.

Limits

  • Five real I/O pins on port 0; port 1 is split into uo outputs and ui inputs.
  • Outputs change in the ACK clock of the byte that sets them, about 1 us of firmware time after the 8th clock fall; at 1 MHz (Fm+) the ACK clock would be shorter than that.
  • 400 kHz is the documented speed.
