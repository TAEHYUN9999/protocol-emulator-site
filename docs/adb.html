File Role Words
firmware/adb.pe Hart 0: an ADB device (default address 2, handler 1): attention and sync detection, command byte, Talk registers 0 to 3, Listen registers 0 to 3 with the address and handler changes of register 3, service request on the stop bit, Flush, Send Reset and global reset. Hart 1: a host run by host commands (global reset, any command, Talk with the reply, Listen with a data packet). 342 of 512 (hart 1 starts at word 175)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (low/rel, shin, waitp, waitp.to, tset/tsetr/twait, the host FIFO and the data memory); the RTL is unchanged. Both harts share one open-drain line, so the host can talk to the device on one chip. Checked in simulation only, not on a board.

The timing comes from the Apple IIgs Hardware Reference, 2nd edition, chapter 6 (original Apple text; Table 6-8, Table 6-9, Figures 6-10 to 6-12). Register 3's bit layout and the Listen register 3 handler codes come from Microchip AN591 and the TMK ADB notes (secondary).

Not implemented: the random address in Talk register 3 and the collision detection of address resolution, the activator (FDh) and self-test (FFh) handler codes, device-specific Flush beyond clearing the pending data, more than one device per chip.

Pins

Constant Default Use
ADB P0 the ADB data line, open drain (external pull-up)

Host interface

Host commands (FIFO) and answers: 01h global reset [0]; 02h c command c only [Srq]; 03h c Talk c [status (0 data, 1 no answer), Srq, n, n bytes]; 04h c n and n bytes, Listen [Srq].

Address Use
0x00..0x07 device registers 0 to 3, high byte first
0x08 device: register 0 holds new data (set by the host keys or by a Listen 0)
0x09, 0x0A device default address (0: 2) and handler (0: 1)
0x0B device: 1 = two host FIFO bytes become register 0 with new data (device-only use)
0x0C, 0x0D, 0x0E device counts: commands for it, service requests, resets

Timing

The device polls the line with shin while idle, takes 560 us of low as an attention and samples every bit 50 us after its fall. A packet ends when no fall comes within 100 us of a rise, so the host waits 300 us after its data packet before the next command (the device is still closing the packet). Sampling at 50 us reads a 0 right while 60 % of the cell is more than 50 us and a 1 right while 40 % is less, so cells of about 84 to 124 us are taken (Table 6-8 allows 70 to 130 us); checked at 90 and 110 us.

On one chip the two harts write the same pin register, so a hart releasing the line would cut the other hart's low: the device releases the line only after its own lows, and the service request is not tested on one chip (it needs the host's release not to end the device's low, which the next integrated RTL with per-hart drives provides).

Limits

  • One device on the chip; no address resolution with random addresses or collision detection.
  • Bit cells of about 84 to 124 us only (a fixed sample point at 50 us), not the full 70 to 130 us.
  • The service request is checked against models only (see Timing).
  • The host waits 300 us after a Listen data packet before it reports, to let the device close the packet.
  • Simulation only: no board, no gate-level run.
