File Role Words
firmware/i2c_sniff.pe Watches an I2C bus without ever driving it and reports START, repeated START, STOP, the address byte with R/W, every data byte and each ACK/NACK to the host, up to Fm+ (1 MHz). Hart 0 samples and decodes the bus into a mailbox of 8 records, hart 1 moves them into a ring buffer (counting what does not fit) and from there to the host FIFO. 128 of 512 (hart 0 82, hart 1 46)

Reference: NXP UM10204 Rev. 7.0 (I2C-bus specification): 3.1.3 (SDA stable while SCL is high), 3.1.4 (START and STOP), 3.1.5 (byte format, MSB first, then the ACK clock), 3.1.6 (ACK), 3.1.10 (the first byte after a START is the address and R/W), Table 10 (Fm+ minimums: tLOW 0.5 us, tHIGH 0.26 us, tHD;STA, tSU;STA, tSU;STO 0.26 us, tBUF 0.5 us, tSU;DAT 50 ns, tHD;DAT 0). No RTL change. Checked in simulation only.

Pins

Pin Use
uio[6] (P6) SCL, input
uio[7] (P7) SDA, input

The pins are fixed: the poll loop reads both with one rdp and takes them as bits 6 and 7.

The firmware has no low, high, shout or woe instruction: it cannot disturb the bus.

Host interface

Two bytes per event:

Event Meaning
01, 0 START
02, 0 repeated START
03, n STOP; n = SCL pulses after the last whole byte (0 unless a byte was cut)
14 | N, byte the first byte after a START or repeated START (address and R/W); N = 1 when it was not acknowledged
10 | N, byte any other byte

The events pass through a ring buffer of 96 bytes (0xA0 to 0xFF, 47 events) so the host can fall behind during a burst; when the ring is full new events are dropped and counted in OVF (data memory 0x10, saturates at 255; it was 0 before 2026-11-11). The mailbox between the two harts is data memory 0x00 to 0x0F.

How it decodes

Hart 0, the sampler, does nothing but follow the lines. A bit: wait for SCL high (waitp), take SDA one tick later (shin), then read SCL and SDA together (rdp, masked to bits 6 and 7) every 4 ticks (160 ns) until one of them changes: SCL low ends the bit, SDA changing while SCL is still high is a repeated START or a STOP. Reading both in one sample keeps an SDA change right after the SCL fall (a hold time of 0, Table 10) from being taken for a START or STOP. A free bus is watched the same way until SDA falls with SCL high.

Each event goes into the mailbox as a record of kind (even address) and value (odd address): the value is written first and the kind, never 0, last, which hands the record to hart 1. A byte costs hart 0 three ticks after its eighth SCL fall (the byte) and five after its ninth (the kind with the ACK bit). A START is recorded after the SCL fall that ends its hold time, so after a STOP the sampler is back watching the bus within about 15 ticks (600 ns) of the STOP, before tBUF + tHD;STA (760 ns) are over. A STOP stores the bits left in the byte; hart 1 turns them into the pulse count.

Hart 1, the recorder, takes each record, frees its slot, adds it to the ring (or counts it in OVF) and moves the ring to the host FIFO one byte at a time with txb.nb, so it never waits for the host. Before 2026-11-11 hart 0 also kept the ring (11 to 12 ticks per byte event) and was exact only up to 625 kHz.

Tests

test/test_i2c_sniff.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_i2c_sniff

The reference is the bus itself: the UM10204 bus monitor of test/test_i2c.py decodes every edge into START, repeated START, STOP and bytes with ACK/NACK, and the sniffer's events must equal that decode, event for event. Traffic comes from the controller and target models of test/test_i2c.py (writes, a write then a read with a repeated START, a plain read, an address nobody answers). The monitor also measures the bus against the Table 10 minimums, so a test at the Fm+ limits shows that the traffic really is at them. The test also checks that the chip never enables P6 or P7 as outputs. The test's host reads the FIFO about every 25 us (4 bytes), slower than a 1 MHz bus makes events; the tests wait until all events are read, the ring holding them meanwhile.

Where it stops, in clocks: a short tLOW leaves too little time after the ninth SCL fall (the fall is seen up to 5 ticks late, the byte's record takes 5 ticks, then waitp for the next rise); a short tHIGH leaves no sample of the high phase between the rise and the fall (the bit is read 2 ticks after the rise is seen); a short tBUF leaves the sampler still writing the STOP record when the START comes (about 15 ticks from the STOP to the next sample). Before 2026-11-11 the sniffer was exact only up to 625 kHz.

Limits

  • Speed: Sm, Fm and Fm+: exact at 1 MHz, also at the Fm+ minimums of Table 10, and up to 1.25 MHz with SCL low 60 % of the period; wrong from 1.6 MHz on. The margins below the Fm+ minimums are 5 clocks (tLOW), 8 clocks (tHIGH) and 7 clocks (tBUF). The 3.4 MHz high-speed mode is out of reach.
  • The pins are P6 and P7 (one rdp, mask 0xC0); the other pins may change freely.
  • 7-bit addressing only in the sense that every first byte is reported as it is; a 10-bit address shows as its two bytes, the second marked as data.
  • Clock stretching is invisible to the sniffer (it only follows SCL), which is correct for a passive monitor.
  • No time stamps: the events carry no time. (The capture block can record pin changes with time stamps, but it shares the frame buffer, not this ring.)
