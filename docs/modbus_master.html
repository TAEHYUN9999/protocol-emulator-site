File Role Words
firmware/modbus_master.pe Modbus RTU master on hart 1: request from the host, CRC-16 added, 8E1 (or 8N2) characters back to back with a driver enable pin, response time-out, broadcast turnaround delay, reply checked for character errors, the t1.5/t3.5 rules, length, CRC and slave address; a reply from another address is ignored while the time-out runs on. Runs alone, or after modbus.pe (the slave on hart 0) so that one chip is master and slave. 182 of 512; with modbus.pe 422 (master from word 240)
firmware/modbus_ascii.pe Modbus ASCII master on hart 1, same host interface: ':' start, two upper case hex digits per byte, LRC, CR LF, 7E1 (or 7N2) characters; reply checked for parity, framing, hex digits, digit pairs, CR LF, the inter-character time-out, length, LRC and slave address; characters before ':' are ignored and a ':' inside a frame starts it again. 223 of 512

The RTU master and the ASCII master are two files because the RTU master has to fit next to the 240-word slave in the 512-word program memory (both modes in one file took 322 words). No RTL change: tset/twait bit grid, shout.lsb, shin.lsb, waitp.to, the CRC unit, ld/st and the host FIFO. Checked in simulation only, not on a board.

Sources

Document Sections used
MODBUS over Serial Line, Specification and Implementation Guide V1.02 (Modbus.org, 20 December 2006) 2.4.1 master states (no reply to a broadcast and a turnaround delay; a response time-out; a reply from an unexpected slave keeps the time-out running; a frame with an error is not processed), 2.5.1 RTU character (start, 8 data bits LSB first, even parity by default, stop; no parity takes 2 stop bits), 2.5.1.1 (t1.5, t3.5, fixed 750 us and 1.750 ms above 19200 bit/s, Figure 14), 2.5.1.2 and 6.2.2 CRC (preset 0xFFFF, polynomial 0xA001, low byte first), 2.5.2 ASCII (start, 7 data bits LSB first, parity, stop; frame ':' address function data LRC CR LF; '0'-'9', 'A'-'F'; up to 1 s between characters), 2.5.2.2 and 6.2.1 LRC (two's complement of the 8-bit sum of the bytes, not of ':' and CR LF, sent high digit first), 3.2 Data Signaling Rates (better than 1 % when sending, accept an error of 2 % when receiving); 2.4.1 also gives typical values (response time-out 1 s to several seconds at 9600 bit/s, turnaround delay 100 to 200 ms)
MODBUS Application Protocol Specification V1.1b3 (Modbus.org, 2012) 6.3, 6.6 and 6.12 (the read and write functions used in the one-chip test), 7 exception responses (function + 0x80)

The worked examples of the model check (11 03 00 6B 00 03 with CRC 76 87 and LRC 7E) are the read of three registers from slave 0x11 that Modbus tutorials use; the model computes both from the formulas above.

Pins

Constant Default Use
MTX P3 transmit data, push-pull, high when idle
MRX P4 receive data
MDE P5 RS-485 driver enable: high from one bit before the first start bit to the end of the last stop bit

For one chip with modbus.pe: MTX = 1 (the slave's RX) and MRX = 0 (the slave's TX), assembled as assemble(modbus + "\n" + modbus_master, {"MTX": 1, "MRX": 0, "NREG": 32, ...}). NREG = 32 keeps the slave's registers at 0xA0-0xDF, below the master's buffer.

Host interface

The host sends a request: n (1 to 29), then n bytes: slave address, function, data. The master appends the CRC (low byte first) or the LRC, sends the frame and then reports three or more bytes: status, count, then count bytes.

Status Meaning Count
0 reply from the addressed slave: address, function, data (CRC or LRC checked and left out); an exception reply comes as function + 0x80 2 or more
1 no reply (RTU: no start bit; ASCII: no ':') within the response time-out 0
2 wrong CRC or LRC, or shorter than 4 bytes (RTU) or 3 bytes (ASCII) 0
3 character error: parity, framing, more than 31 bytes; RTU: a character more than t1.5 after the one before; ASCII: not a hex digit, an odd number of digits, no LF after CR, a gap over the inter-character time-out. The ASCII master waits until the line is quiet for that time-out before it reports, so that the rest of a broken frame is not taken as the next reply 0
4 broadcast (address 0) sent and the turnaround delay over 0
Data memory Use
0x08 MPAR 0: even parity; otherwise no parity and 2 stop bits
0x09, 0x0A MTOH/L response time-out in units of 100 us (2,500 ticks); 0 = 65,536
0x0B, 0x0C MTAH/L broadcast turnaround delay, same units
0x0D MSAD address of the request (used by the master)
0x0E, 0x0F MSVH/L the time-out left when a reply started (used by the master)
0x10 MOTH replies from another address, ignored
0x11 MREQ requests sent
0x12, 0x13 MICH/L ASCII only: inter-character time-out, units of 100 us (the guide's default is 1 s: 10,000)
0x14 MSKP ASCII only: characters before ':', ignored
0x15 MCE ASCII only: character error flag of the frame (used by the master)
0xE0-0xFE request with its CRC or LRC, then the reply (31 bytes)

The spec leaves the response time-out and the turnaround delay to the application; the host sets them. The turnaround and the time-out wait for a start bit in steps of 100 us (mwait); the broadcast turnaround counts only time with the line idle.

Timing

MBIT is the bit time in ticks, MHBIT half of it; the RTU file also takes the three silences of modbus.pe (MT15H/L = t1.5 + half a bit, MTCWH/L = t3.5 - t1.5, MT35H/L = t3.5 + half a bit, counted from the middle of the stop bit). Defaults are 19200 bit/s: 1302 ticks (52.08 us, -0.006 %), t1.5 16.5 + 0.5 bits, t3.5 38.5 + 0.5 bits. The tests use 115200 bit/s: 217 ticks (8.68 us, -0.006 %), t1.5 750 us and t3.5 1.750 ms.

Every character is sent on the twait grid: each edge one tick after a period boundary, the next start bit right after the last stop bit, so every edge of a request is a whole number of bits after its first start edge (measured: all edges on the grid, DE up 1 bit + 2 ticks before the first start bit and down in the clock the last stop bit ends).

The receivers sample each bit in its middle from the start edge (waitp finds it within a tick), check the start bit at its middle, the parity and the stop bit. Without parity they check the first stop bit and return in it, so a slave that sends one stop bit (8N1, 7N1) is also taken.

Tests

test/test_modbus_master.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_modbus_master

The slave model is written from the sources above, not from the firmware: CRC-16 and LRC, character slots for 8 or 7 data bits with or without parity, frame builders, a decoder of the recorded TX line that samples every slot in its middle, checks parity and stop bits and puts every edge of a frame on the bit grid of its first start edge, a DE check, and a model slave on RX that sends any bytes with gaps, parity errors and bit times off by a factor.

Limits

  • The response time-out does not count while a reply from another address is being received (it goes on from where it was when that reply started).
  • RTU: 1 to 29 request bytes and 31 reply bytes (the buffer); ASCII: 29 and 31 bytes before hex encoding. A length outside 1 to 29 is dropped, and the bytes that follow are then read as new lengths.
  • Below about 14,700 bit/s the RTU silences do not fit the 16-bit timer (as in modbus.pe).
  • No retries: the host sees the status and decides.
  • ASCII: the LF end character is fixed (the guide allows another one to be set by function 08).
  • Simulation only: no board, no gate-level run.
