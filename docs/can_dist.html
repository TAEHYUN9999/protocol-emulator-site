Simulation only, not checked on a board. The chip sits on a CAN bus as a third party, finds a chosen bit of another node's frame and drives it dominant for a chosen time. Swept over the pulse length in steps of one clock (20 ns), this measures the sample point of the node that transmits the frame, the way bus disturbance tools do it (Vector VH6501: "sample point" determination by changing the length of a disturbed bit, search summary only). The same firmware disturbs one bit with one length (one point) when a test needs a single bit error at a known place.

Test bench use only. It provokes errors on purpose: never connect it to a bus that carries real traffic (a vehicle, a machine).

Pins

Pin Signal Direction
P0 (uio[0]) TXD to the transceiver output, driven high (recessive) at start
P1 (uio[1]) RXD from the transceiver input

Dominant = 0, the same transceiver wiring as can.pe and can_gen.pe (docs/can.md). Through a transceiver the chip can only add dominant level to the bus. It cannot force a recessive bit: a node that sends dominant always wins. VH6501 can (it sits in the bus lines with analog switches); this chip cannot.

How it works

Both harts run (CTRL = 3, START1 = label hart1), 157 of the 512 words.

  • Hart 1 follows the bus like a receiver: it waits for 10 recessive bit times, hard-syncs on SOF, samples the middle of every bit and restarts the bit time on every recessive to dominant edge (the first half of a bit belongs to the bit that edge starts). At the start of bus bit BIDX (SOF = 0, stuff bits counted) it drives TXD low.
  • A pin changes only in the clock of the hart that writes it, and each hart owns every second clock. So hart 1 alone makes even lengths: low, tsetr X, twait, high gives 8 + 2X clocks. For odd lengths hart 0 ends the pulse: it waits on the chip's own TXD pin (waitp P0,0; the pad input is the driven level), then X ticks, then rel, 13 + 2X clocks after hart 1 pulled the pin low. Each hart has its own pin registers and a pin is low while either hart drives it low (dual_role.md), so for an odd length hart 0 drives TXD low as well (woe with the odd flag that hart 1 sets, 9 clocks after hart 1's edge), hart 1 lets go 12 clocks after its edge (high), and hart 0's rel ends the pulse: one low stretch of D clocks. Lengths from 15 clocks up are possible, in steps of one clock. The first version of this firmware was written for the 512-word RTL before the per-hart pin registers, where both harts wrote one shared pin register and hart 0's high ended hart 1's pulse; on this RTL that left TXD low after the first odd pulse (the three sweep tests timed out), hence the change.
  • After the pulse it waits 8 ticks (the own pulse leaves RXD through the transceiver loop), then looks for an error flag: a dominant level that starts within 2 bit times and lasts 5.5 bit times. Frame data has at most 5 equal bits in a row (stuffing), an error flag at least 6. The result (1 = flag) goes to the map, and the next frame gets the next length.
  • The sweep ends after NPTS lengths or after ESTOP flags in a row. The threshold is the first length that drew a flag.

Why the first flagged length is the sample point: the pulse starts at the bit start (measured 180 to 200 ns late at the bus, 120 ns of it the transceiver loop of the bench, see Measured). The transmitting node sends recessive in that bit, so it resynchronizes on the pulse's falling edge (Bosch CAN 2.0 Part A section 8: "All other recessive to dominant edges ... will be used for RESYNCHRONIZATION with the exception that a node transmitting a dominant bit will not ..."; with a phase error within SJW the effect "is the same as that of a HARD SYNCHRONIZATION"). Its sample point then lies SP after the edge, whatever the chip's lateness. It reads the bit back there: dominant (a bit error, section 6.1, signalled with an error flag from the next bit, 6.2) when the pulse is longer than SP, recessive otherwise. So the first length D with a flag satisfies (D - 1) x 20 ns <= SP < D x 20 ns: the node samples dominant when the pulse still lasts at its sample point.

Settings (data memory, DATA_W before CTRL = 3)

16-bit values high byte first, ticks of 40 ns, with the path lengths of this firmware taken off (dist_settings() in test/test_can_dist.py). BIT = ticks per bit.

Address Name Value
0, 1 BM BIT - 9: middle of a bit to the middle of the next
2, 3 HF BIT/2 - 9: falling edge to the middle of that bit
4, 5 H2 BIT/2 - 4: middle of bit BIDX - 1 to the pulse
6, 7 W2 window for the start of the error flag after the pulse (2 BIT)
8, 9 F55 a dominant stretch this long is an error flag (5.5 BIT)
10 BIDX bus bit to overwrite, SOF = 0, stuff bits counted (2 or more); bit BIDX - 1 and bit BIDX should be recessive, so the pulse starts with an edge
11, 12 D0 first pulse length in clocks (15 or more)
13 NPTS lengths to try, D0 to D0 + NPTS - 1 (1 to 96)
14 ESTOP stop after this many flags in a row (0 = never). Keeps the number of provoked errors small: a node goes error passive after 16 transmit errors and its flags turn recessive

Results (DATA_R at any time):

Address Name Value
15 DONE 1 when the sweep is over (hart 1 halts)
16 NDONE lengths tried
17 THRI index of the first length that drew a flag, 0xFF if none
18, 19 THR that length in clocks
20 to 22 work bytes (hart 0's X, flags in a row, 1 when hart 0 ends the pulse)
0xA0 + i MAP 1 = error flag after length D0 + i, 0 = none

The node under test must send the frame again for each length (a node retransmits a frame after an error by itself; after a good frame the host of that node sends it again).

Measured

All on the RTL of commit 422ec10 with the per-hart pin registers (Icarus Verilog 11.0, cocotb 2.0.1), test_can_dist run whole on 2026-11-12, TESTS=4 PASS=4 FAIL=0, 89 s of simulation wall time. The first version on the earlier 512-word RTL gave the same table, maps and pulse lengths. The model node sends standard ID 0x123 with data F7 3C (52 stuffed bits SOF to CRC); the chip disturbs bus bit 21 (the second data bit, recessive after a recessive bit).

  • Every pulse, odd and even, measured at TXD from edge to edge, was exactly the programmed number of clocks (46 pulses in the three sweeps, 115 to 353 clocks).
  • The pulse's falling edge reached the bus 180 to 200 ns after the node's own bit start (its phase error), inside SJW, so the node restarted its bit on the edge, as the rule says. 120 ns of that is the transceiver loop of the bench; the rest is the chip's sampling of RXD (two synchronizer clocks and the hart slot).
  • The node's own verdict per frame (bit error at bus bit 21 or no error) equals the chip's map entry for every length, and the node's bit error was always at exactly the disturbed bit. Its transmit error count ended at 32 (4 errors): error active throughout, so its flags stayed dominant and visible.
  • One pulse of 180 clocks (90 % of a bit) on a data bit (bus bit 26) and on the CRC delimiter (bus bit 52 of a frame whose last CRC bit is recessive): the node reported a bit error at exactly that bit and the chip saw the flag; a pulse of 40 clocks on the same data bit stayed before the sample point and the frame went through (map 0).

Test (test/test_can_dist.py)

make -B COCOTB_TEST_MODULES=test_can_dist (CAN_DIST_FW selects another firmware file). The node is a model written from Bosch CAN 2.0 Part A, not from the firmware: bit time with hard synchronization and resynchronization (section 8: phase error, SJW, rules 1 to 4, also the negative phase error), bit monitoring at its sample point with the exceptions for the arbitration field and the ACK slot (6.1), an active error flag from the next bit (6.2), the error delimiter (first recessive bit sampled, 7 more) and intermission (3.1.3, 3.1.5), retransmission, and its own error counts (test/can_rules.py). An ideal receiver drives the ACK slot of every frame the transmitter reaches. The bus is the wired AND of the chip's TXD after a 120 ns transceiver loop, the node and the ACK driver.

Test Checks
test_can_dist_sample_point 250 kbit/s, SP 2990 ns: chip threshold = floor(SP / 20 ns) + 1 = 150; every pulse exactly D clocks; pulse edge within SJW of the node's bit start; map = the node's verdicts = the expected verdicts; one frame per length; exactly 4 flags (ESTOP)
test_can_dist_sample_point_moved the same with SP 2510 ns: the threshold moves to 126
test_can_dist_sample_point_125k 125 kbit/s, SP 7010 ns, lengths above 255 clocks: 351
test_can_dist_bit_position one pulse on a data bit and on the CRC delimiter: the node's bit error is at exactly that bus bit; a short pulse makes no error

Against another chip instead of a model node: can_j7.md runs this firmware on a second chip that disturbs the frames of a chip running can_gen.pe. That transmitter does not resynchronize on the pulse edge, so the sweep finds its read-back point (137 clocks: the sample point counted from its own TXD edge, 72 % of the bit at the bus; 103 clocks, 55 %, before its readback moved to the sample point on 2026-11-18), not floor(SP / 20 ns) + 1.

Limits

  • Resolution 20 ns: 0.5 % of a bit at 250 kbit/s, 2 % at 1 Mbit/s. A real controller's sample point sits on its time quantum grid; the measured threshold then lies within one clock of it. The model node here samples in continuous time.
  • The node must resynchronize on the pulse edge: the lateness of the pulse edge at the bus (measured 180 to 200 ns in the bench, 120 ns of it the transceiver loop) must be within its SJW. With a smaller SJW the measured value is SP plus the lateness beyond SJW.
  • The first node that samples the disturbed bit dominant reports the error, so a receiver with an earlier sample point than the transmitter would be measured instead. The test bench has only the transmitter and an ideal acknowledging receiver.
  • Dominant only; no recessive forcing, no analog disturbance (short, wrong termination), no CAN FD data phase (no bit rate switch in the firmware).
  • Only one disturbance per frame, one target bit per sweep (a list of targets would need a longer table).
  • Tested at 250 and 125 kbit/s only. The bit follower spends 9 ticks of path per bit and samples once per bit; faster rates were not run.
  • The pulse ends on a clock edge. TXD is P0, which has a delay line since part D1 of branch int5 (dly.md); with dlyw the pulse end could move inside one clock and the threshold be found finer than 20 ns. This firmware does not use the line, and nothing of that was measured.
  • The bus bit is counted from SOF including stuff bits, so the host computes BIDX from the frame it expects (stuffing included); a frame with other content moves the target.
