File Role Words
firmware/timecode.pe Hart 0 decodes DCF77 from a receiver module's pulse output: second marks of 0.1 s (0) and 0.2 s (1), the missing 59th mark as the minute boundary, 59 bits checked (bit 0 = 0, bit 20 = 1, parities P1, P2, P3, BCD digits) and stored as minute, hour, day, weekday, month, year and the announcement / time zone bits. Hart 1 decodes IRIG-B 000 (DC level shift): 2, 5 and 8 ms pulses at 100 pps, frame start on two identifiers in a row (P0, Pr), identifiers checked at every tenth bit, BCD seconds, minutes, hours, day of year, year and the straight binary seconds of day stored. Each runs alone or both at once. 388 of 512 (hart 1 from word 161)

No RTL change: each hart samples its input on a twait grid (1 ms and 0.1 ms by default) and counts; a shared routine (fld) takes a bit field out of the stored bit array, the CRC unit of hart 0 serves as the parity generator. Checked in simulation only, not on a board.

Decoding

DCF77 (hart 0), unit DUH:DUL ticks (25,000: 1 ms):

Pulse width Meaning
40 to 139 units 0
140 to 250 units 1
below 40 or above 250 the minute is spoiled
1,500 units without a new pulse start the missing 59th mark: the minute ends

A minute of exactly 59 bits is checked: bit 0 = 0, bit 20 = 1, P1 (bits 21-28), P2 (29-35) and P3 (36-58) even, every BCD units digit 0 to 9. The parity is the CRC unit of hart 0 with the polynomial 0x8000 (a 1-bit CRC); it is cleared once before P1, so each later check also covers the fields before it, which are already known to be even. Only then are the fields copied to the results and DOK counted; otherwise DERR counts and the results stay. The first minute boundary after start only synchronizes.

IRIG-B (hart 1), unit IUNIT ticks (2,500: 0.1 ms):

Pulse width Meaning
10 to 34 units 0 or index bit (2 ms)
35 to 64 units 1 (5 ms)
65 to 95 units position identifier (8 ms)
other error: hunt again

While hunting, two identifiers in a row are P0 and Pr; Pr is bit 0. An identifier must come at bits 9, 19, ..., 99 and nowhere else, and Pr must follow P0. After P0 the frame is decoded: BCD units digits 0 to 9, then the fields are copied and IOK counted. A misplaced or missing identifier counts IERR and starts the hunt again.

0x00 minute (BCD) 0x10 seconds (BCD)
0x01 hour 0x11 minutes
0x02 day of month 0x12 hours
0x03 weekday, 1 = Monday 0x13 day of year, tens and units

Tests

test/test_timecode.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_timecode

The transmitter models are written from the sources above, not from the firmware: the 59 DCF77 bits of a date and time with the parities, sent as pulses at the start of each second with no pulse in second 59; the 100 IRIG-B symbols of a time with identifiers and the straight binary seconds, sent as 2, 5 and 8 ms pulses every 10 ms. A minute of DCF77 is 60 s and an IRIG-B frame 1 s, which an RTL simulation at about 6 s of wall time per simulated ms cannot run in real time many times; so the decoding is checked with the time units scaled (DCF77 1/500, IRIG-B 1/20, both decoders at once), and the default units in real time on single pulses.

Controls

Each control is a copy of timecode.pe with one planted bug, run with TC_FW=<path>.

Planted bug Test First failure
IRIG-B: a data bit in an identifier slot not checked (the r3 = 9 test in i_chk left out) test_tc_scaled the frame without P5 is decoded (IOK 3, IERR 0) where the model wants it dropped
DCF77: minute field taken from bit 22 instead of 21 test_tc_scaled minute A is dropped (DOK 0, DERR 1) where the model wants 21:37
DCF77: the P1 check left out test_tc_scaled no failure: minute B (P1 wrong) is still dropped. The parity register is not cleared between P1 and P2, so a wrong P1 also makes the P2 check fail; this change does not alter what the decoder accepts for a single parity error, so it is an equivalent change rather than a gap in the test (a minute with both P1 and P2 wrong would need the P1 check)

Two of the three fail at the check they aim at; the third is equivalent, as explained.

Limits

  • DCF77: amplitude modulation only (no phase-modulated pseudo-random code), no leap second (a minute of 60 bits is dropped), no check of the date's range beyond the BCD digits, the weather bits 1-14 are not kept.
  • IRIG-B: format B with a DC level shift input (no 1 kHz carrier demodulation), the control functions 60-78 are not kept; no check of the index bits.
  • Results go to the data memory only (the host polls the counters); there is no 1 PPS output.
  • The real-time runs check the time units on a few pulses, not a whole minute or frame.
  • Simulation only: no board, no gate-level run.
