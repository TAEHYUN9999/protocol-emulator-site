File Role Words
firmware/eeprom256.pe The chip answers on I2C as a Microchip 24LC256 (256 Kbit): two address bytes, chip select bits compared with three pins, a 64-byte page buffer written at the STOP with the page roll-over, WP sampled at the STOP, a 2.5 ms write cycle with ACK polling, sequential reads rolling over from 7FFFh to 0000h. 155 of 512 (one hart)
firmware/fram.pe The chip answers on SPI (mode 0 and 3) as a Fujitsu MB85RS64V FRAM (64 Kbit): WREN, WRDI, RDSR, WRSR, READ, WRITE, RDID; data written as each byte arrives (no write cycle), the write enable latch rules, block protect, WPEN with the /WP pin, address roll-over from 1FFFh. 145 of 512 (one hart)

No RTL change. Checked in simulation only. The arrays are windows on the chip's memory (below); the address space of each part is decoded in full.

24LC256 (eeprom256.pe)

Pin Use
P6, P7 SCL (input), SDA (open drain); SCL must be P6 and SDA P7 (read together with rdp)
ui[3], ui[4], ui[5] A0, A1, A2 chip select inputs
ui[6] WP (high: write protected)

Array window: EEPROM address a is ld/st address 0x20 + (a & 0x7F), the 128-byte frame buffer: it repeats every 128 addresses (two pages) over the 32 KB. The host fills it with ETH_W before the run and reads it with CAP_R; Ethernet and the capture cannot be used at the same time. Data memory 0xA0-0xDF is the page buffer; 0x00 holds the start position of the write, 0x01 counts the write cycles started and 0x02 the writes dropped by WP (mod 256).

Data sheet Firmware
5.0 control byte 1010 A2 A1 A0 must match the pins the expected control byte is built from ui[3..5] at each START, before the first bit
5.0 A15 don't care ignored
6.2 page buffer, six low bits roll over, more than 64 bytes overwrite each byte goes to the buffer at its page position; at the STOP min(n, 64) positions from the start are written to the window
6.3 WP sampled at the STOP read at the STOP; high: nothing written, no write cycle, counted
7.0 no ACK during the write cycle, TWC 5 ms max 2.5 ms (62,500 ticks, the hart's timer)
8.3 roll-over from 7FFFh to 0000h A14..A0 increment, A15 dropped

Assumption (the data sheet is silent): a write ended by a repeated START is dropped (the page buffer is written only at a STOP); the address counter has moved on by the bytes received.

MB85RS64V (fram.pe)

Pin Use
P2 SCK
P3 SI
P4 SO (driven only while data goes out; released while /CS is high and while data comes in)
P5 /CS
P6 /WP

Array window: FRAM address a is ld/st address a & 0xFF, the whole 256-byte load/store space (data memory and frame buffer), repeating 32 times over the 8 KB. The host fills it before the run and reads it with DATA_R and CAP_R. The status register is kept in a register (power-up 00h).

Data sheet Firmware
op-codes 06h, 04h, 05h, 01h, 03h, 02h, 9Fh; others are not to be sent the seven; any other byte is ignored until /CS rises
CS rising inside the op-code: not performed nothing happens
WEL set by WREN, reset by WRDI and at the CS rise after a WRSR or WRITE was recognized as stated, also when the WRITE or WRSR was cut short
WRITE: written when 8 bits have come in, address increments and rolls over stored at the 8th rising edge; a byte cut by /CS is not written
BLOCK PROTECT 01: 1800h-1FFFh, 10: 1000h-1FFFh, 11: all a threshold on A12..A8, set at each WRSR
WRITING PROTECT: WEL 0 protects all; WPEN 1 and WP low protect the status register as stated
RDID: 04h 7Fh 03h 02h, then SO holds the last bit as stated
tODV 20 ns at up to 20 MHz SO changes 1 to 3 ticks after the SCK fall the chip sees (at most 280 ns measured); the master samples at the rise, half a period later

Every wait for an SCK level times out after 32 ticks and then looks at /CS once (as in w25q.pe), so /CS must stay high at least 36 ticks (1.44 us); the data sheet's tD is 60 ns.

Tests

test/test_eeprom256_fram.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_eeprom256_fram

Eeprom256 and Fram are written from the data sheets; the windows are the firmware's documented host interface. The I2C controller and monitor are those of test_i2c.py; the SPI host is FlashHost of test_w25q.py (DI at the falling edge, DO read at the rising edge, any DO change while SCK is high fails).

Limits

  • Windows of 128 (EEPROM) and 256 (FRAM) bytes, repeated over the address space.
  • 24LC256: 400 kHz is the documented speed (the 24FC256's 1 MHz is not), fixed 2.5 ms write cycle.
  • MB85RS64V: no /HOLD, SCK up to 1.25 MHz (data sheet 20 MHz), /CS high at least 1.44 us; the status register is volatile here (non-volatile on the part).
