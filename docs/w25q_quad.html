File Role Words
firmware/w25q_quad.pe w25q.pe (the W25Q128JV flash emulation: JEDEC ID, status, write enable, read, fast read, page program, sector and chip erase, BUSY times on hart 1) with Quad SPI added: Fast Read Quad Output (6Bh), Fast Read Quad I/O (EBh) and Read Status Register-2 (35h). IO0-IO3 are P4-P7, so a data nibble is one wrp. 481 of 512 (hart 1 from word 443)

w25q.pe itself is unchanged (it keeps the board pin map of spi_device.pe); the quad version is a separate file with its own pin map. No RTL change. Checked in simulation only.

Source

Behaviour

Instruction Firmware
35h 02h on DO for every byte until /CS rises, accepted while BUSY (checked before the BUSY test)
6Bh address on DI as for 0Bh, the same 8 dummy clocks, then at each falling edge one nibble on P7-P4 (woe F0h, wrp): D7..D4 then D3..D0; the next byte is fetched in the low half of its second clock
EBh decoded right after the instruction byte (its address comes on four lines at once): A23-A16, A15-A8, A7-A0 and M7-M0 read with rdp at the rising edges (two per byte), 4 dummy clocks during which the window address is worked out, then data as for 6Bh
any quad read while BUSY ignored: the IO lines stay released

The window is that of w25q.pe: flash bytes 000000h-00007Fh are the frame buffer, every other address reads FFh, and a quad read runs on past 00007Fh with FFh. At /CS high the firmware releases all four IO lines (woe 0). Every wait for a CLK level times out and looks at /CS (w25q.pe's scheme), so a quad read cut short by /CS ends the instruction.

Tests

test/test_w25q_quad.py (quad reads), and test/test_w25q.py run on the quad file (single SPI), both from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_w25q_quad
W25Q_FW=<repo>/firmware/w25q_quad.pe W25Q_PINS=2,4,5,3 PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_w25q

QuadHost is written from the sections above: it drives CLK, /CS and IO0-IO3, changes its outputs at the falling edges, lets go of the IO lines from the first dummy clock and samples at the rising edges; it checks that the chip drives no IO line before the data clocks and that no IO line changes while CLK is high. The data and the BUSY state come from FlashModel of test_w25q.py. W25Q_PINS (new, default 2,3,4,5) lets test_w25q.py run on the quad pin map.

Limits

  • No Quad Input Page Program (32h), Fast Read Dual (3Bh, BBh), Set Burst with Wrap (77h) or the QE write path (31h): QE is fixed to 1 as on the IQ/JQ parts.
  • CLK up to 1.25 MHz for the quad reads (the part: 133 MHz).
  • 481 of 512 words are used.
