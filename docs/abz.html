File Role Words
firmware/abz.pe Hart 0 generates quadrature signals A, B and the index Z: moves from the host (direction, state period, number of states), position modulo the states per revolution, Z for one state at position 0. Hart 1 is a 4x quadrature counter: +1 or -1 for every state change, the count set to 0 when Z rises (the count it had is kept), changes of both lines at once counted as errors. 151 of 512 (generator 65, counter 86)

No RTL change: existing instructions only (wrp so that A, B and Z change in the same clock, the twait grid, rdp polling, a transition table in data memory). Checked in simulation only.

Source: Broadcom (Avago) HEDS-55xx/56xx datasheet AV02-1046EN (November 20, 2014), "Definitions" (secondary: incremental encoders have no standard): four states per cycle, each 90 electrical degrees; in one direction A leads B, in the other B leads A; the index is "a one state width (nominally 90 electrical degrees), high true index pulse which is coincident with the low states of channels A and B".

Pins

Constant Default Use
PA, PB, PZ P0, P1, P2 A, B, Z: outputs of the generator, inputs of the counter

With both harts running the counter counts the generator of the same chip; with hart 1 alone it counts an external encoder on the same pins. MSK and ZM are the pin masks; the counter's transition table assumes A in bit 0 and B in bit 1.

Generator (hart 0)

CPRH:CPRL (data memory 0, 1) is the number of states per revolution (4 per line, a multiple of 4), set by the host before start. The position p starts at 0. The output is the Gray code of p mod 4, so forward (A leads B) runs through (A, B) = 00, 10, 11, 01, and Z is high exactly in the state 00 at p = 0.

Host to chip (FIFO), 5 bytes per move: direction (bit 0: 1 = reverse, B leads A), state period in ticks (2 bytes, at least GMIN = 31 ticks: 806 k states/s), number of states (2 bytes). The timer starts once the 5 bytes are in; each state change is written one tick after a period boundary, so every state lasts exactly the period. GDONE counts finished moves (it is 1 after the start).

Counter (hart 1)

It first builds a 16-entry table (old A, B, new A, B) -> +1, -1, 0 or error from the state number s = 2B + (A xor B) (about 26 us after start), then polls A, B and Z every 4 ticks. Each change costs 27 ticks: the count is right up to one state change every 1.1 us (0.91 M states/s) and wrong at 1.0 us. Data memory, readable at any time with DATA_R: CNTH:CNTL (4, 5) count, 16-bit two's complement; CERR (6) changes of both A and B at once (not counted); CIDX (7) index pulses; CLASTH:CLASTL (8, 9) the count at the last index, before it was set to 0.

Tests

test/test_abz.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_abz

The model is written from the datasheet definitions, not from the firmware: the state order with A leading B, +1 / -1 / error from two states, the index state, a model generator on the test side and a model 4x counter with index reset that gives the expected count, index pulses and kept count for any list of steps.

Limits

  • Counter rate 0.91 M states/s (about 227 k cycles/s), generator 806 k states/s; a real encoder at a higher edge rate needs a hardware counter.
  • The counter reads all three lines in one rdp; Z rising resets the count whatever A and B are doing, so an index that is not gated to A = B = 0 resets in another state.
  • No glitch filter; a change of both lines at once is skipped and counted, and the counter goes on from the new state.
  • The count is 16 bits and is written to data memory after every change as two bytes; a host read between the two stores can see a mixed value.
  • Simulation only: no board, no gate-level run.
