File Role Words
firmware/wiegand.pe Wiegand card reader on hart 0 (26-bit and 34-bit messages from the host, both parity bits computed) and access panel on hart 1 (DATA0/DATA1 pulses decoded, glitches filtered, end of message by silence, parity checked, ID bytes for the host). Both harts on the same two pins make a one-chip loopback. 184 of 512 (hart 1 starts at word 79)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (low/rel, shin, tset/twait, the CRC unit as a parity bit, ld/st, host FIFO); the RTL is unchanged. Checked in simulation only, not on a board.

Sources

The interface standard, SIA AC-01-1996.10 (Access Control Standard Protocol for the 26-Bit Wiegand Reader Interface), is sold by the Security Industry Association and was not read. Its timing is quoted the same way by several reader data sheets; the formats come from a reader manual. These are secondary sources.

Item Value Source
Lines DATA0 and DATA1, idle high (open collector, pulled up at the panel); a 0 is a low pulse on DATA0, a 1 a low pulse on DATA1 SIA AC-01 as quoted by reader data sheets
Pulse width 20 to 100 us same
Pulse interval 200 us to 20 ms; taken here as leading edge to leading edge same
26-bit format bit 1 even parity over bits 2 to 13; bits 2 to 25 the ID (8-bit facility code, 16-bit card number, HID H10301); bit 26 odd parity over bits 14 to 25 AEI DK-2822 manual, "Wiegand output formats"
34-bit format bit 1 even parity over bits 2 to 17; bits 2 to 33 the 32-bit ID; bit 34 odd parity over bits 18 to 33 same

The bit order is bit 1 first, and each format's two halves are equal (13 + 13, 17 + 17 bits including the parity bit), so the firmware uses one rule for both: the first half has an even number of ones, the second half an odd number.

Pins

Constant Default Use
D0, D1 P0, P1 reader outputs DATA0, DATA1: pulled low for a pulse, released otherwise (open drain; the pull-up is on the panel side)
D0IN, D1IN P2, P3 panel inputs

Assembling with D0IN = D0 and D1IN = D1 connects the reader to the panel inside the chip. Only hart 0 drives the pins and hart 1 leaves its own pin registers released, so the wired AND of the two harts' registers is hart 0's drive.

Reader (hart 0)

Host to chip (FIFO): k, then k ID bytes, first byte sent first (most significant bit first). k = 3 sends a 26-bit message (facility code, card number high, low), k = 4 a 34-bit message. After the message and its silence the chip answers 0. Any other k is answered 1 at once and nothing is sent; the bytes after it are not taken.

The two parity bits are computed before the first pulse with the CRC unit set to polynomial 1, which makes its bit 0 the parity of the bits fed in (crc.lsb). The second half of a 26-bit message starts in the middle of byte 1, so the firmware feeds the low nibble of byte 1 and byte 2 for it, and byte 0, byte 1 and the low nibble of byte 1 again for the first half (a nibble fed twice cancels). For 34 bits the halves are whole bytes.

Constant Default Meaning
PW 1250 ticks (50 us) pulse width, at most 4095
PER 20 (1 ms) pulse interval in pulse widths, leading edge to leading edge, 3 to 255
GAP 30 (30 ms) silence after a message in pulse intervals, before the answer

Every pulse starts one tick after a boundary of a PW grid and lasts exactly one period, and the next one starts PER periods after it, so the widths and intervals are exact to the clock. The silence after the message (GAP intervals) is longer than the panel's end-of-message time, so two messages never run together at the panel.

Panel (hart 1)

The panel samples both lines every SMP = 25 ticks (1 us). A low line starts a pulse; it lasts until both lines are high again. Results go to the data memory:

Address Use
0x08 WCNT messages received (the host polls it)
0x09 WN bits in the last message (stops at 255)
0x0A WST 0: 26 or 34 bits, parity right; 1: 26 or 34 bits, parity wrong; 2: another length (not checked)
0x0B WERR pulses on both lines at once (not taken as a bit)
0x0C to 0x13 WDAT the bits between the two parity bits, first bit in bit 7 of 0x0C; for 26 and 34 bits exactly the reader's k bytes; a length that is not 2 + 8k leaves the last bits in the low bits of the last byte
0xA0 to 0xDF one byte per bit received (64 bits are kept)
0x00 to 0x03 the reader's ID bytes
Constant Default Meaning
PMIN 10 samples (10 us) a shorter pulse is a glitch and is ignored; half the 20 us minimum of the interface
TEND 100 (25 ms) end of a message after TEND x 250 samples without a pulse; above the 20 ms longest pulse interval

A pulse on both lines at once counts in WERR and is not a bit. The panel writes WN, WST and WDAT before it counts the message in WCNT.

The long waits were simulated with shorter constants as well as the defaults: test_wiegand_reader_default runs one 26-bit message at the default times (57 ms of simulated time); the other tests use PER = 4 (200 us, the shortest interval of the interface), GAP = 8 and TEND = 4 (1 ms).

Tests

test/test_wiegand.py (cocotb). The format model builds and checks 26 and 34 bit messages from the bit ranges above; the panel model watches DATA0 and DATA1 with the clock number of every edge and checks every width and interval against the interface windows and against the firmware's exact clocks; the reader model drives the panel with pulses of any width and interval. Only the host interface (command, answer, data memory addresses, assembler constants) is taken from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_wiegand

Controls

Each change was made in a copy of wiegand.pe and run with WIEGAND_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Reader: the odd parity bit is the second half's parity, not its inverse test_wiegand_reader the first 26-bit message has a wrong parity at the panel model
Reader: one period too many between pulses (addi r6, -1 for -2) test_wiegand_reader intervals of 12500 clocks (250 us) where 10000 are due; still inside the 200 us to 20 ms window, so only the exact check sees it
Panel: no glitch filter (cmpi r1, PMIN and its jc removed) test_wiegand_panel the 5 us glitch is taken as a bit: 27 bits where 26 are due
Panel: the second half checked for even parity (ldi r3, 0) test_wiegand_panel the first good 26-bit message is reported with status 1

Limits

  • The interface standard itself was not read (see Sources); the windows are those the reader data sheets quote.
  • Only 26 and 34 bit messages are sent and parity-checked. The panel takes any length up to 255 bits and keeps 64 of them, without a check for other formats (35-bit Corporate 1000, 37-bit H10304 and others have other parity layouts).
  • The reader's times are assembler constants, not data memory settings. A pulse is at most 4095 ticks (164 us), which covers the 100 us maximum.
  • The panel samples every 1 us, so it sees widths to within 1 us; it does not check the widths or intervals of a message against the interface windows, only drops pulses under PMIN.
  • Simulation only: no board, no gate-level run.
