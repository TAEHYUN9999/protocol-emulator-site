firmware/jtag.pe General JTAG adapter: the host orders TMS sequences and IR/DR shifts of 1 to 65535 bits through the FIFO and gets the TDO bits back. TCK speed from the data memory. One hart. 81 of 512

jtag.pe is checked in simulation only, not on a board. Start it on hart 0 (CTRL 0x01 with value 1).

Pins

Pin Use
uio[0] (P0) TCK output, low when idle
uio[1] (P1) TMS output, high at start
uio[2] (P2) TDI output, low at start
uio[3] (P3) TDO input. 1149.1 lets the target release TDO outside Shift-IR / Shift-DR, so it needs a pull-up (the cocotb bench models released lines as pulled high)

Pin numbers are .equ values (instruction fields), not run-time settings. Neither TRST nor SRST is driven; reset the TAP with five TCK cycles with TMS high.

Settings (data memory, host DATA_W before the run)

Address Name Meaning Value 0 means
0x00, 0x01 HALFH, HALFL TCK half period in ticks (one tick = 40 ns at 50 MHz), 16 bits, high byte first. Exact for 4 and above. 10 ticks (1.25 MHz, .equ HALF)
0x02 ERR Written by the firmware: an unknown command byte, stored before it halts

Commands (host FIFO_W, 0x20)

Bytes Action Reply
0x01 n t0 t1 ... n TCK cycles (1 to 255, 0 = none) with the TMS bits t, LSB of t0 first, ceil(n/8) bytes. TDI keeps its level. none
0x02 nl nh d0 d1 ... Shift n = nl + 256 nh bits (1 to 65535, 0 = none) with the TDI bits d, LSB of d0 first. TMS is 0, and 1 on the last bit, so Shift-IR / Shift-DR goes to Exit1-IR / Exit1-DR. ceil(n/8) TDO bytes, LSB first; the last byte holds the remaining bits right-aligned
0x03 nl nh d0 d1 ... The same with TMS 0 on every bit: the TAP stays in Shift-xR, so one scan can be split over several commands the same
anything else The byte is written to ERR (0x02) and the firmware halts; STATUS then shows hart 0 halted none

The adapter does not track the TAP state; the host moves it with TMS sequences, for example from Run-Test/Idle: 0x01 3 0x01 (TMS 1, 0, 0) to Shift-DR, 0x01 4 0x03 (1, 1, 0, 0) to Shift-IR, and after a 0x02 shift 0x01 2 0x01 (1, 0) through Update to Run-Test/Idle. 0x01 6 0x1F (five 1s, then 0) resets and goes to Run-Test/Idle. Chains of several TAPs are handled by the host (IR and DR lengths are the sums), as in the two-TAP test.

The FIFOs are 4 bytes each way. For a shift longer than 32 bits the host must read TDO bytes while it writes TDI bytes, otherwise both FIFOs fill (jtag_io in test/test_jtag.py does this).

Timing

Each bit: TDI (or TMS) changes while TCK is low, TDO is sampled one tick before TCK rises, then TCK rises. Within one TDI byte the rising edges are exactly 2 x HALF ticks apart; TCK is high for HALF - 1 ticks and low for HALF + 1 ticks. Between bytes, and before the last bit of a 0x02 shift (where TMS goes high), TCK stays low longer: at least 2 x HALF + 9 ticks from rise to rise when the next TDI byte is already in the FIFO (measured 680 ns at HALF = 4), and as long as the host takes otherwise (up to 31 us with the cocotb host). 1149.1 allows TCK to stop low for any time.

Supported, not supported, limits

Item Status
Host-given TMS sequences, 1 to 255 bits per command Supported, tested (reset, Pause-DR, Pause-IR, Exit2 paths)
IR and DR shifts, 1 to 65535 bits per command Supported; tested at 1, 2, 4, 7, 8, 9, 10, 13, 15, 16, 17, 20, 27, 30, 31, 32, 33, 40, 64, 76, 77, 78, 100, 255, 256, 300, 301 bits (and 0: no clock)
One scan split over several shift commands Supported (0x03), tested: 87-bit DR in four commands with a pass through Pause-DR
BYPASS, IDCODE, long user register Tested against the model, also behind another TAP
Two TAPs in a chain Tested: both IDCODEs after reset, 10-bit IR, 301-bit DR (300-bit USER + BYPASS), IDCODE behind BYPASS
TCK speed from the data memory Supported, HALF 4 to 65535 exact (tested at 4, 5, 10, 37, 1000)
Fastest exact TCK HALF = 4: 320 ns period, 3.125 MHz within a byte, late flag clear (measured). With HALF 1 to 3 the period is set by the bit loop: 7 ticks, 280 ns (3.57 MHz), and the late flag is set; the data was still right in the test
TDO clock-to-output delay of the target Measured: TDO may change up to 100 ns after TCK falls at HALF = 4 (120 ns fails) and up to 340 ns at HALF = 10 (360 ns fails), that is about 100 ns before TCK rises
TDI/TMS stable while TCK is high Checked by the model at every speed tested
Unknown command Reported in ERR, firmware halts (tested). JTAG itself has no acknowledge, parity or CRC, so there is nothing else the adapter can detect; the host checks the TDO data (for example the IR capture bits ...01, IDCODE bit 0 = 1)
TRST, SRST Not supported: no pins assigned; TMS reset is used
TDO during a TMS command Not returned: use a shift command when TDO matters
TDI level during a TMS command Not settable: it keeps the level of the last shifted bit (low at start)
Adaptive clocking (RTCK), IEEE 1149.7 (cJTAG) Not supported: not requested; RTCK would need one more input pin and a wait per edge
Throughput of long scans Limited by the host SPI, not by TCK: one SPI transfer per FIFO byte each way

Tests

test/test_jtag.py (cocotb). The TAP model is written from the TAP rules of IEEE 1149.1 as secondary sources describe them (the IEEE text was not read; see Sources), not from the firmware: the 16-state controller diagram (state changes on the rising edge of TCK following TMS), Capture on the rising edge that leaves Capture-xR, one shift stage per rising edge in Shift-xR with TDI entering at the far end, Update and the Test-Logic-Reset instruction load on the falling edge, TDO changing only on the falling edge and driven only in Shift-xR, IR capture ending in 01, BYPASS one bit capturing 0 (also selected by unused codes), IDCODE 32 bits with bit 0 = 1. Two TAPs: A (IR 4 bits, IDCODE 0x4BA00477, 77-bit USER) and B (IR 6 bits, IDCODE 0x13631093, 300-bit USER). Every scan is checked both ways: the bits the first TAP received equal the TDI bits sent, and the TDO bits returned equal the bits the last TAP showed; the expected register contents are computed from the rules above.

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_jtag
Test What
test_jtag_single_tap IDCODE after reset, IR capture, USER scans of 17 lengths (1 to 300 bits), BYPASS with 3 opcodes, IDCODE followed by TDI
test_jtag_two_taps The chain cases above
test_jtag_pause_and_stay Split DR scan through Pause-DR, IR scan through Pause-IR
test_jtag_tck_speed HALF 0 (default), 1000, 37, 10, 5, 4, 3, 2, 1: period, high time, late flag, data
test_jtag_errors Zero-length commands do nothing, unknown command halts with ERR
test_jtag_tdo_delay Longest TDO delay at HALF 4 and 10

Results are printed as JTAG ... lines. JTAG_FW selects another firmware file.

Sources

IEEE Std 1149.1 itself was not read (it is sold by IEEE), and the commit that added this test (4302012) names the standard but no edition or copy that was read. Each rule of the TAP model above appears in the two Texas Instruments documents that docs/jtag_tap.md (Source) cites with section numbers; both state that they follow IEEE Std 1149.1-1990. The one exception is that unused instruction codes select BYPASS: the model chooses this, as jtag_tap.pe does, and the two documents do not settle it.
