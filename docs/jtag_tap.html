Source

IEEE Std 1149.1 itself was not available (it is sold by IEEE). The firmware and the test models follow two Texas Instruments documents that describe it and state that they follow IEEE Std 1149.1-1990:

  • [P] "IEEE Std 1149.1 (JTAG) Testability Primer", SSYA002C, 1997, chapter 3.
  • [S] SN54BCT8244A / SN74BCT8244A data sheet, SCBS042E (revised July 1996), "state diagram description", "register overview" and "bypass register".

That unused codes select BYPASS is a choice made here; the rule for unused codes was not checked in the sources ([S]'s device also defaults the codes it does not support to BYPASS).

Pins

Pin Use

uio[1] (P1) TMS, input
uio[2] (P2) TDI, input

These are the pin numbers of jtag.pe, so one cable fits both. They are .equ values (TAP_TCK, TAP_TMS, TAP_TDI, TAP_TDO), not run-time settings.

Two harts on one chip

pin_out and pin_oe in src/pe_core.v are one register each, shared by the two harts, but low, high, rel, shout change only the bit of the pin they name, in the cycle of the hart that runs them (the harts own alternate cycles, so neither works on a stale copy). Two harts disturb each other only on a pin both of them write (docs/lin.md "Pins", docs/ps2.md). In the loopback each pin has one writer: jtag.pe on hart 0 writes P0, P1 and P2 and only reads P3; jtag_tap.pe on hart 1 writes only P3 and reads P0 to P2 through the pad. So the same four pins work with no wire outside the chip, which test_tap_loopback shows. Neither firmware uses wrp or woe, which would rewrite all eight bits.

Review B asked for the target's pins to move. The reason given there is the FPGA board, not the harts: the board's peer (fpga/common/pe_peer.v) always drives P1 (its UART TX) and drives P4 while P5 is low. A board run must therefore keep TMS off P1 for both firmwares. That needs no new file: the assembler's defines override the .equ values, and assemble(jtag.pe + jtag_tap.pe, {"TMS": 5, "TAP_TMS": 5}) gives TCK P0, TMS P5, TDI P2, TDO P3 (the pins review B named); test_tap_loopback runs that image too. Not run on the board.

How it works

Each TAP state is a block of code: waitp TCK,0 and the state's falling-edge action, waitp TCK,1, shin.lsb r4,TMS (Z = 1 when TMS is 0), a branch to the next state's block. The data-register states (Run-Test/Idle to Update-DR) exist three times, once for each register, so the current instruction is held by the program counter: Update-IR compares the new IR once and jumps into one of the three copies, and no other state decodes it.

  • USER (8 bits) is one register, r0. After each falling edge shout.lsb r0,TDO puts out bit 0 and rotates r0 right; after the rising edge shl r0 undoes the rotate and shin.lsb r0,TDI shifts right with TDI into bit 7.
  • IDCODE (32 bits) is r0 to r3, one shift loop per byte with a bit count, so the bytes never move; after 32 bits the loop is back at r0, which now holds the first 8 TDI bits. The register is loaded in Select-DR-Scan: its value is a constant, so this is the same as loading it at the capture edge.
  • BYPASS (1 bit) is bit 0 of r0: shout.lsb rotates right and shin shifts left with TDI into bit 0, so only bit 0 changes.
  • IR (4 bits): shin.lsb r6,TDI keeps the register in bits 7..4 of r6, for the compare in Update-IR. TDO comes from four one-bit cells, bit 0 of r0, r1, r2, r3, used in turn by four copies of the shift block: each cell puts out its bit and takes TDI in its place, so it is read four shifts after it was written.
  • Exit1-xR is entered with call from the shift loop. Exit2-xR returns with ret when TMS is 0, so the shift goes on where it stopped (bit and byte); Update-xR is a plain jump. These blocks call nothing (the hart has one call level).

The longest code between two rising edges of TCK is 9 instructions (a Shift-IR or IDCODE byte step that exits to Exit1-xR): that and the two input synchronizer flip-flops set the speed below.

Timing (measured)

Measured by the test's bus monitor. The host model's TCK has a 50 % duty; TMS and TDI change with the falling edge and TDO is sampled at the rising edge with no setup margin, so "lead" below is the margin a real host's setup time must fit in.

Two runs on 2026-11-11 (the second with more periods; each period uses its own random data, so the two runs place the critical cycles at different phases):

Fastest TCK that passes: 410 ns, 2.44 MHz (every period from 1000 ns down to 410 ns passed in both runs; periods that are not a whole number of 40 ns ticks sweep the phase between TCK and the core clock). Below that the result depends on where the critical cycles fall against the core clock. TCK may stop low for any time (the Pause scans and the host model's gaps between operations).

With the jtag.pe host on the same chip (its TDO sample is one tick before its own TCK rise, docs/jtag.md), the loopback passes at HALF 10 (default, 1.25 MHz), 8, 7 and 6 (2.08 MHz) with hart 0's late flag clear, and fails at HALF 5 (2.5 MHz) and 4 (the IDCODE comes back wrong), the same in both runs: the two harts share one clock, so the phase is fixed. A loopback must set jtag.pe's HALF (data memory 0x00/0x01) to 6 or more. With TMS on P5 instead of P1 (both firmwares, by defines) HALF 10 passes too.

Tests

test/test_jtag_tap.py (cocotb). The host model and the reference TAP are written from [P] and [S] (see the module docstring), not from the firmware: the host drives TMS and TDI with the falling edge, samples TDO at the rising edge and parks TCK low; the reference TAP follows Figure 3-3 and the register rules. A monitor on the pins runs the reference at every TCK edge and records an error when TDO is driven outside Shift-xR, differs from the reference, or changes (level or enable) while TCK is high. Only the host interface (instruction codes, the IDCODE address, the USER capture and update pins, the capture value beyond its two LSBs) is taken from this document. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_jtag_tap

Limits

  • Not a compliant 1149.1 device: no boundary-scan register, SAMPLE/PRELOAD or EXTEST, no TRST (above).
  • TCK at most 2.44 MHz against the host model (410 ns; faster periods depend on phase), 2.08 MHz against jtag.pe on the same chip (measured above). The firmware polls TCK; there is no RTCK output to tell a host to wait. The host must also allow for TDO changing up to 190 ns after the falling edge at that speed (120 ns at 1.79 MHz and slower).
  • IDCODE and the IR codes are fixed per image (IDCODE from the data memory, codes from .equ); the IR capture value is 0001.
  • USER captures 5 input bits and updates 6 output bits; bits 7..5 of the capture are 0 and bits 7..6 of an update are dropped.
  • The data memory is read only at start (DATA_W writes only while both harts are stopped anyway).
  • Not tested: a real JTAG adapter or tool (OpenOCD, SVF), a chain with other devices on a board, gate-level simulation, and the board.
