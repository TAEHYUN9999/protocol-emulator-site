File Role Words
firmware/cec.pe An HDMI-CEC device on the open-drain CEC line: sends the host's messages (start bit, 10-bit blocks, signal free time, arbitration on the initiator address, ACK check, retransmissions), and receives messages for its logical address or broadcast (start bit and bit timing checks, ACK of directly addressed blocks), reporting each block to the host. 353 of 512 (one hart)

No RTL change: existing instructions only. Checked in simulation only.

Sources. The HDMI specification's CEC supplement was not read. The times and rules are those that the Linux kernel's bit-banging CEC adapter states for it:

Source Used for
Linux drivers/media/cec/core/cec-pin.c start bit low 3.7 ms (3.5 to 3.9), total 4.5 ms (4.3 to 4.7); data bit 0 low 1.5 ms (1.3 to 1.7), 1 low 0.6 ms (0.4 to 0.8), total 2.4 ms (2.05 to 2.75); earliest safe sample 0.85 ms; a follower ACKs by holding the line low to 1.5 ms; bits 0 to 7 data, 8 EOM, 9 ACK; arbitration lost when the line reads 0 at the sample point of a 1 bit within the first 4 bits; broadcast ACK is a 1 (a 0 is a rejection), direct ACK is a 0
Linux include/media/cec.h signal free time: 3 bit periods before a retransmission, 5 for a new initiator, 7 for the same initiator's next frame

Pins

Pin Use
uio[0] (P0) the CEC line, open drain (driven low or released), idle high through the pull-up (27 k on a real HDMI port)

Timing

Everything runs on steps of B = 1,250 ticks (50 us). A bit is 48 steps (2.4 ms): low for 12 (a 1, 0.6 ms) or 30 (a 0, 1.5 ms), the line is sampled at step 21 (1.05 ms). The start bit is low for 74 steps (3.7 ms), 90 in all (4.5 ms). One bit engine drives both directions: each step ends with a twait and the level for the next step is put on the line with shout.od in the following tick, so the chip's own lows are exact to the clock (start bit 185,000 clocks low, 225,000 in all; bits 30,000 or 75,000 clocks low, 120,000 apart).

Receiver windows (steps counted from the falling edge that starts a bit; the step grid starts a few ticks after the edge is seen, so the lower limits are one step lower, as cec-pin.c lowers its limits by one sample period): start bit low 3.45 to 3.9 ms, start bit 4.25 to 4.7 ms in all, the next bit's fall 2.0 to 2.75 ms after this one's, and the line high again at 2.05 ms.

Polling loops (idle, start bit, waiting for the next bit) wait with waitp.to; after a timeout they reload the step with tsetr B - 4, because 4 ticks have passed since the end of the step. A twait there would end late (the timer already ran out), set the late flag and stretch every step by 2 ticks.

Host interface

Direction Bytes
Host to chip (FIFO) n (1 to 16), then n bytes, the header (initiator << 4 | destination) first
Chip to host two bytes per event (below)
Event Meaning
01 \| EOM << 1 \| header << 2, byte a block received, of a message to the chip's logical address or broadcast
10 \| status, attempts a transmission ended: 0 ACKed, 1 not ACKed after all attempts, 2 arbitration lost, 3 the line was low at 2.05 ms in a bit the chip sent
08, code a received frame was dropped after a valid start bit: 3 line still low at 2.05 ms in a bit, 4 no next bit within 2.75 ms inside a block

The logical address is the assembler constant LA (default 4, Playback Device 1). The host must read the FIFO at least every second event: the chip waits while the FIFO is full and loses the bus timing meanwhile.

Transmitter

The message is taken from the FIFO one byte per step while idle and kept in data memory (0xA0). It is sent when the line has been free for the signal free time: 5 bit periods at the start and after another device's frame, 7 after the chip's own successful frame, 3 before a retransmission. The free time is counted from the end of the last bit (the step after its 48th) and the start bit comes at the next step boundary, so it is at most one step (0.02 bit periods) longer than required.

Arbitration: in the first four header bits every 1 the chip sends is checked at step 21; a 0 there means a device with a lower initiator address is sending, and the chip reports status 2, stops driving and receives the rest of that frame (it ACKs and reports it if it is addressed to the chip). The message is dropped; the host decides whether to send it again.

ACK: the ACK bit is sent as a 1 and sampled at step 21: for a directly addressed message a 0 is the ACK, for a broadcast a 0 is a rejection. A missing ACK stops the frame; it is retransmitted up to RETRY = 2 times (3 attempts), then status 1 is reported. (The CEC specification's retransmission count was not checked.)

Receiver

A low pulse that is not a valid start bit is ignored and counted in SERR (data memory 10); so are the bits of a frame whose start bit was missed. After a valid start bit the chip follows the frame bit by bit. When the header block's destination is the chip's address, the chip ACKs every block (it pulls the line low at the ACK bit's falling edge and holds it to step 30, 1.5 ms); for a broadcast it does not drive the ACK bit (it never rejects). Blocks of messages for other devices are followed (to know when the bus is free) but not reported. A frame that stops after an ACK bit (its initiator saw a NACK) ends without an error.

Tests

test/test_cec.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_cec

The models are written from the times and rules above, not from the firmware: a follower that checks every start bit and data bit window (it samples each bit at 0.85 and 1.25 ms and requires the same level), ACKs blocks addressed to it and can reject broadcasts, and an initiator that sends with chosen times, checks arbitration on its initiator bits and reads the ACK. They share P0 with the chip as a wired-AND. The test also asserts the chip's own low pulses in clocks and the signal free time before each retransmission. Times are divided by 10 except in test_cec_realtime.

Rerun of the whole module on commit b4edcc2 (2026-11-11 23:27, Icarus Verilog 11.0, cocotb 2.0.1, RTL, two simulations sharing the machine): test_cec TESTS=4 PASS=4 FAIL=0 SKIP=0, 1,300 s wall; every test listed above passed.

test_cec_transmit_longest was added on 2026-11-13 for a report of the static deadline check (petime.md): a late twait in the bit engine on a path where the shift loop that picks the data bit (tb0) runs 255 times. The loop count is the bit number BITK (data memory 6). The test sends the longest message, 16 blocks, with data bytes of all ones, all zeros and single bits, ACKed by the TV model, and reads BITK from the data memory about every 20 us of the frame (times / 10): the values seen are 0 to 9, every bit the chip drives has its exact width, and the late flag is 0. The reported path cannot happen: only this hart writes BITK, with 0 and with its old value plus 1 up to 9. With that test (RTL of 92b38df, same tools, three simulations sharing the machine): test_cec TESTS=5 PASS=5 FAIL=0 SKIP=0, 274.7 ms simulated, 1,317 s wall.

Two checks were added for test_gaps.md on 2026-11-13. test_cec_receive measures the chip's own ACK pulses: 8 of them, one per block sent directly to the chip, each holding the line low for 1.5026 ms (times x 10) from the falling edge of the ACK bit, inside the 1.3 to 1.7 ms of a 0 bit. test_cec_transmit requires that the chip's next frame after its own ACKed frame starts at least 7 bit periods after the end of the last bit: 7.028 bit periods in both places. Controls: an ACK held to step 37 (1.85 ms) fails the first check while the initiator model still reads every ACK; 5 free bit periods instead of 7 after an own successful frame fail the second (5.028 measured). The 5 bit periods for a new initiator are not asserted.

Limits

  • One logical address, fixed at assembly (LA); no polling for a free address, no CEC opcodes handled by the chip itself (the host does that).
  • No low-drive error signal (3.6 ms low) is generated; one coming from another device during a bit the chip sends ends that transmission with status 3.
  • The chip never rejects a broadcast.
  • The host must read the FIFO at least every second event.
  • Messages up to 16 bytes (the CEC maximum is 16 blocks including the header).
