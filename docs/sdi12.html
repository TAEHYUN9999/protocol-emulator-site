firmware/sdi12.pe An SDI-12 sensor on the data line: break and marking detection, 1200 baud 7E1 in negative logic, the address commands a!, aI!, aM!, aD0! and ?!, answers after 8.33 ms of marking, standby after 100 ms of marking or a command for another address. 171 of 512 (one hart)

No RTL change: existing instructions only (waitp.to with the timer for the break, marking and gaps, tsetr for bit times above 4,095 ticks, shin.lsb/shout.lsb, the CRC unit as a parity generator, low/rel to take and release the line). Checked in simulation only.

Source: "SDI-12, A Serial-Digital Interface Standard for Microprocessor-Based Sensors", Version 1.4 (December 1, 2017), read from the published PDF (a copy on the NOAA PSL site; the later 1.4 clarification revisions were not read):

Section Used for
3.1, table 1 marking = logical 1 = -0.5 to 1.0 V, spacing = logical 0 = 3.5 to 5.5 V: the logic pin is low for marking
4.1, table 2 1200 baud, start bit, 7 data bits LSB first, even parity, stop bit
4.4, tables 5, 7, 9, 11 a! -> a CR LF; aI! -> a, ll (14), 8 vendor characters, 6 model, 3 version, CR LF; aM! -> a ttt n CR LF (ttt = 000: no service request, 4.4.6); aD0! -> a, values, CR LF; ?! -> a CR LF
7.0 break at least 12 ms, ignored under 6.5 ms; 8.33 ms of marking after the break before the address; the sensor marks 8.33 ms (-0.40) and its first start bit comes within 15 ms (+0.40) of the command's stop bit; at most 1.66 ms between characters; the sensor releases the line within 7.5 ms (+0.40); standby after an invalid address or 100 ms of marking, a break after 87 ms; timing tolerance +-0.40 ms

Pin

Constant Default Use
DQ P0 the data line, on the logic side of a level shifter: low = marking, high = spacing. The sensor drives it (push-pull) only while it answers and releases it otherwise.

Timing

BT = 20,833 ticks per bit (1200.02 baud), BTH half a bit, MS = 25,000 ticks per millisecond, all as high and low byte constants because they exceed tset's 12 bits. The tests also run the firmware with every time divided by 20 (BT 1,042, MS 1,250).

  • Break: the line must stay spacing for BRK = 8 ms (between the 6.5 ms that must be ignored and the 12 ms that must be taken).
  • Marking after the break: MARK = 8 ms (the recorder gives at least 8.33).
  • A command character is sampled at the middle of each bit on a grid from its start bit; parity and stop bit are checked. The next character must start within GAP = 3 ms.
  • Answer: the sensor takes the line (marking) at once, waits RESP = 9 ms and one bit, then sends the characters with one bit of marking between them, and releases the line at the end of the last stop bit. Measured in real time: first start bit 9.42 ms after the command's stop bit, 9.84 ms of driven marking before it, 0.834 ms between characters, released 0 ms after the last stop bit.
  • Awake for SLP = 100 ms of marking after an answer: a command without a break is taken; after that, or after a command for another address, a break is needed.

Sensor

Data memory, written by the host with DATA_W before start: ADDR (0, the ASCII address, '0' usually), NVAL (1, the ASCII digit n of the aM! answer), IDS (0xA0, the identification text after the address, 0 terminated), VALS (0xC0, the aD0! values, 0 terminated). Counters: NCMD (2) commands answered, NERR (3) characters with a parity or stop bit error, NBRK (4) breaks taken. A character with a spacing stop bit may be the start of a break: the sensor then needs only 2 ms more of spacing to take it.

Tests

test/test_sdi12.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_sdi12

The recorder model is written from the standard, not from the firmware: break and marking times, 7E1 characters in negative logic at 1200 baud, a decoder of the sensor's answer with parity and stop checks, the 7.0 windows with their tolerances (first start bit, driven marking before it, gaps, release), the bit grid of every answer character, and the sensor's drive enable read from uio_oe.

Limits

  • Only a!, aI!, aM! (ttt = 000, so no service request), aD0! and ?!; no aC!, aV!, aR0!, CRC commands, aAb! address change or extended commands. The answer texts come from data memory.
  • The sensor does not check the 1.66 ms gap limit of the recorder's characters (it takes up to 3 ms).
  • Timing on a millisecond grid: break, marking and awake times are counted in whole MS periods.
  • The level shifter, the 12 V supply and the line drivers are outside; the pin is the logic side.
  • Simulation only: no board, no gate-level run.
