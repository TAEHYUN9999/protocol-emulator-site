File Role Words
firmware/arinc429.pe Hart 0 is an ARINC 429 transmitter: 32-bit words from the host, label most significant bit first, bits 9 to 32 least significant first, odd parity computed, bipolar return-to-zero on two logic lines, at least 4 bit times of NULL between words. Hart 1 is a receiver on two logic lines: bit by bit on each HI or LO pulse, word gap hunt, parity check, words reported to the host. High speed (100 kbit/s) or low speed (12.5 kbit/s), chosen per hart by a data memory byte. 204 of 512 (hart 0 78, hart 1 126)

No RTL change: the firmware uses existing instructions only (twait grid, high/low, rdp polling, waitp.to, shin/shin.lsb, the CRC unit as a 1-bit parity generator). Checked in simulation only, not on a board.

Pins

Constant Default Use
TXA P0 transmitter HI line (a driver's One input), push-pull, low when NULL
TXB P1 transmitter LO line (a driver's Zero input)
RXA P2 receiver HI line (a line receiver's One output)
RXB P3 receiver LO line

RXM and RXAM are the masks of the receive pins and must be changed with them. Assembling with {"RXA": 0, "RXB": 1, "RXM": 3, "RXAM": 1} makes the receiver listen to the transmitter of the same chip.

Timing

One period of the twait grid is half a bit: 125 ticks (5 us) at high speed, 1,000 ticks (40 us) at low speed. A bit is HI or LO for one period and NULL for the next; each line changes one tick after a period boundary, so every HI or LO pulse is exactly 250 or 2,000 clocks and every bit 500 or 4,000 clocks (100.000 and 12.500 kbit/s). Between two words the transmitter keeps the lines NULL for at least 8 periods after the end of bit 32, i.e. exactly 4 bit times when the next word is ready. The longest work between two boundaries is the parity and word set-up before bit 1 (about 35 ticks), far below a period.

The receiver polls both lines every 4 ticks. For each bit it checks that only one line is high, takes the bit from RXA, and waits for the end of the pulse with waitp.to (a pulse longer than 7.5 us or 60 us is an error). After each pulse the next bit must start within 63 polls (10 us) or 500 polls (80 us); otherwise the word stopped early. After bit 32 the lines must stay NULL for 125 polls (20 us) or 1,000 polls (160 us) before the word counts, and the same NULL is needed before the receiver takes a pulse as bit 1 after start-up or an error.

Host interface

Both directions use 4 bytes per word: the label as an octal number in a byte (label 310 is 0xC8), bits 9-16, bits 17-24, bits 25-32 (bit 9, 17 and 25 in bit 0 of their byte). The transmitter replaces bit 32 by the odd parity bit; the receiver reports bit 32 as received (always the odd parity bit, because words with even parity are dropped).

Data memory Use
0x00-0x03 the word being sent
0x04-0x07 the word being received
0x10 TCNT words sent
0x11 ROK words reported
0x12 RPAR words with even parity, dropped
0x13 RBIT HI and LO at once, or a pulse that is too long
0x14 RSHT words that stopped before bit 32
0x15 RGAP a pulse less than the NULL after bit 32: the word is dropped and the receiver hunts
0x1E TSPD, 0x1F RSPD 0 = high speed, 1 = low speed; read once at start, written by the host with DATA_W while the harts are stopped

The transmitter takes host bytes one per half bit while the lines are NULL; the host FIFO holds the next word while one is sent, so words go out back to back. The receiver waits on a full FIFO (it pushes 4 bytes per word with txb), so the host must read each word before the next one ends.

Tests

test/test_arinc429.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_arinc429

The model is written from the sources above, not from the firmware: an encoder that numbers the bits 1 to 32, puts the label's most significant bit in bit 1 and bits 9 to 31 least significant first, sets bit 32 for odd parity, and a decoder of the recorded HI and LO lines that groups pulses into words, times every pulse and every bit to the clock and measures the NULL between words. The transmitter model on RXA/RXB sends words at any bit time, high time and jitter. Only the host byte layout and the data memory addresses come from the firmware header. test/fw_host.py holds the host helpers shared with the later protocol tests (load with data memory settings, a host coroutine that owns the SPI link, edge recorder).

Limits

  • The receiver does not check the bit rate as a window: it accepts pulses up to 7.5 us (60 us) and NULL inside a word up to about 10 us (80 us), so it also takes words somewhat slower than the 83 kbit/s (10.4 kbit/s) at which the HI-3593 stops. It checks that only one line is high, the pulse length upper limit, the word length, the parity and a NULL of 2 bit times after the word (the HI-3593 asks for 3).
  • No label filter, no SDI or SSM handling: every word with odd parity goes to the host.
  • The receiver pushes each word to the FIFO and waits while it is full; a host that does not read for a whole word time loses words.
  • Edges change within one tick of 40 ns; the analog slope (1.5 us or 10 us rise time) is the line driver's job (the HI-8585 SLP1.5 pin).
  • Simulation only: no board, no gate-level run.
