File Role Words
firmware/knx.pe A KNX TP1 device on one open-drain logic pin: 9600 bit/s with 35 us active pulses for 0 bits, 13-bit characters with even parity, standard frames with the check octet, acknowledgement (ACK or NACK) 15 bit times after a frame addressed to it, sending with the idle time, the repeat flag and up to 3 repetitions after NACK, BUSY or silence, and arbitration: a 0 on the line while it sends a 1 makes it stop and read the winner's frame. 320 of 512 (one hart)

No RTL change: existing instructions only (shout.od/shout.lsb.od for the pulses, a three-segment twait grid per bit, shin.lsb, the CRC unit as a parity generator). Checked in simulation only.

Sources. The KNX standard's TP1 chapter (03_02_02) is a members' document and was not read; these public documents describe it:

Source Used for
KNX Association, "Serial Data Transmission and KNX Protocol", KNX Tutor Seminar E0808f control field 1 0 R 1 P P 0 0 (R = 0 for a repetition; P 00 system, 10 alarm, 01 normal, 11 low); source and destination addresses, group address bit in the next octet; check field by cross check with odd parity of every bit column; characters with even parity and one stop bit, t4 = 2 bit times between characters (13 per character); the acknowledgement in the character after t2 of one character width; IACK 0xCC, INACK 0x0C, BUSY 0xC0; bus idle t3 = 50 bit times after the acknowledgement; priorities 1 and 2 and repetitions start at once, others t1 = 3 bit times later; 0 overrides 1, the device sending a 0 in the source address goes on; repetitions up to three times
onsemi NCN5121 datasheet (NCN5121/D Rev. 5) 9600 bit/s, a bit period of 104 us, a logical 0 is the active pulse of 35 us, a 1 is the DC level
Siemens TP-UART 2 technical manual (June 2024) 15 bit times of idle before the acknowledgement character; data bits LSB first
KNX "Data Link Layer General" 03_03_02 v01.02.02 LG in a standard frame counts the APDU octets (a frame is LG + 8 octets)

Pin

Constant Default Use
P P0 the bus on the logic side of a transceiver: open drain (pulled low for a 0 pulse, released otherwise), read by the device at every bit, so the line is the wired AND of all devices

Timing

A bit is three twait segments: 425 ticks from the bit start to the sample point (17 us), 450 more to the end of the pulse (35 us after the start), 1,729 to the end of the bit, 2,604 ticks (104.16 us, 9600.6 bit/s) in all. Each segment is "twait, one action, tset next - 2", so the pulses are exactly 875 ticks (1,750 clocks) and the bit starts exactly 2,604 ticks apart. A character is a start bit, 8 data bits LSB first, the even parity bit, the stop bit and 2 idle bits. When reading, the grid is restarted at every start bit edge (the bit start is taken 14 ticks after the edge is seen). The acknowledgement starts 15 bit times after the end of the frame's last stop bit; the test measured 15.01 (times / 10).

Device

Data memory Use
0, 1 OWNH:OWNL individual address (host, before start)
2, 3 GRPH:GRPL one group address
0xA0 RBUF the last frame read, with its check octet
0xC0 TBUF the frame being sent
11 RXOK, 12 RXERR frames read right, frames with a parity or check error
13 ACKS acknowledgements sent
14 TXOK, 15 TXREP, 16 TXLOST frames acknowledged, repetitions, arbitrations lost

Reading: every frame on the line is read. One that is addressed to the device (its individual address with bit 7 of octet 6 clear, its group address with it set) gets ACK, or NACK if a character had a parity or stop bit error or the XOR of all octets is not 0xFF. Each frame is reported to the host with one FIFO byte: the number of octets, bit 5 for an error, bit 6 if the device acknowledged. A single character that is not a control field (an acknowledgement of another device) is ignored.

Sending: host to chip (FIFO) n (7 to 22), then the n octets without the check octet. The device waits for 50 idle bit times (53 for normal and low priority), sends the frame with R = 1 and waits up to 20 bit times for the answer. ACK ends the transfer; NACK, BUSY or nothing starts a repetition with R = 0 after 50 idle bit times (150 after BUSY), up to 3. The result goes to the host: 0x80 ACK, 0x81 NACK, 0x82 BUSY, 0x83 no answer (the last answer after the repetitions). While sending, every 1 bit is read back at the sample point; a 0 there means another device won: the device stops driving, reads the rest of that frame as a normal frame (and acknowledges it if addressed) and sends its own frame later.

Tests

test/test_knx.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_knx

The model is written from the sources above, not from the firmware: frames with the control field, LG and the check octet; characters as pulses on the open-drain line (the model pulls the pin low through the test bench, the chip with its own driver, so the line is a real wired AND); a decoder of the line from its falling edges; a model device that acknowledges with chosen answers 15 bit times after a frame, and a model sender that checks its own 1 bits for arbitration. All tests except test_knx_realtime run with every time divided by 10 (the firmware's segment constants and the model alike).

Limits

  • Standard frames only (no extended frames, no polling); one individual and one group address; BUSY is never sent by the device.
  • The device's own ACK is not checked for collisions; the line timing assumes the 2-bit character gap of the sender within 3.8 bit times.
  • The repeat rule follows the TP-UART and NCN5121 descriptions (3 repetitions, 150 bit times after BUSY); the KNX TP1 chapter itself was not read.
  • Logic level only: the transceiver (pulse shaping, 30 V bus, equalisation pulse) is outside.
  • Simulation only: no board, no gate-level run.
