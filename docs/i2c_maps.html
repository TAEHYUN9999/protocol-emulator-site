File Role Words
firmware/edid.pe The display side of DDC: an EDID 1.4 base block and one extension block (256 bytes) at A0h/A1h. The firmware writes each block's checksum at start and then raises HPD; sequential reads run on past 128 bytes and wrap at 256; data writes are not acknowledged; the E-DDC segment pointer (60h) is not implemented and not acknowledged. 84 of 512 (one hart)
firmware/qsfp.pe The management interface of a QSFP module (SFF-8636, flat memory): lower page 00h and upper page 00h at A0h/A1h, the address counter rolling over inside each 128-byte page, writes of up to four bytes applied at the STOP to the writable bytes only, page select reverting to 00h, CC_BASE and CC_EXT computed at start, interrupt flags latched and cleared when read, IntL from the flags, masks and the power-up interrupt, ModSelL, four Tx disable outputs, four Rx LOS inputs. 228 of 512 (one hart)
firmware/ipmb.pe An IPMB responder node: takes request messages written to its slave address, checks both checksums, and sends the response as a master write to the requester (Get Device ID, Get Self Test Results, completion codes C1h, C2h, C7h), with bus idle detection, clock stretching, arbitration and retries. 262 of 512 (one hart)

No RTL change. The I2C byte loop is the one of firmware/eeprom24.pe (SCL and SDA read together with rdp, so SCL must be P6 and SDA P7). Checked in simulation only.

DDC/EDID (edid.pe)

Pin Use
P6 SCL (input)
P7 SDA (open drain)
P5 HPD: low until both checksums are written, then driven high

EDID byte e (0 to 255) is ld/st address e: block 0 at 0x00-0x7F, block 1 at 0x80-0xFF (data memory 0x00-0x1F and 0xA0-0xFF, frame buffer 0x20-0x9F). The host writes the EDID before the run with DATA_W and ETH_W; the firmware writes byte 7Fh of each block (addresses 0x7F and 0xFF) so the block sums to 00h, so the host can change any field without computing the checksum. Ethernet and the capture cannot be used with it (shared frame buffer).

Standard Firmware
E-DDC 6.1 to 6.3: current address, random and sequential reads at A0h/A1h the word offset is set by a write of one byte; reads increment it after each byte
E-DDC 2.2.6: reads may continue past 128 bytes they do, and wrap from 0xFF to 0x00
E-DDC section 6: data writes need not be supported a data byte after the word offset is not acknowledged and not stored
E-DDC 10.2, 9.1.2: no segment pointer when the data fits in segment 0 60h is not acknowledged; a host that writes the segment pointer first reads segment 0 as usual
EDID A2 3.11: checksum computed at start for both blocks

QSFP management interface (qsfp.pe)

Pin Use
P6, P7 SCL, SDA
P5 IntL, open drain, low = asserted
P4 ModSelL input, low = selected (the test drives it; with the pull-up alone the module is deselected)
P0-P3 Tx1..Tx4 Disable outputs = byte 86 bits 0-3
ui[3]..ui[6] Rx1..Rx4 LOS conditions: a 1 latches byte 3 bit 0-3

Map byte e (0 to 255) is ld/st address e: lower page 00h = bytes 0-127, upper page 00h = bytes 128-255 (Flat_mem: no other page). The host loads the map before the run (identifier, monitors, serial ID, any preset flags). At start the firmware writes CC_BASE (191) and CC_EXT (223), clears the writable bytes (86-106, 111, 112, 118-127; Table 5-3, 5.5), sets byte 2 to 04h (Flat_mem, IntL asserted, Data_Not_Ready low), drives the Tx disable pins from byte 86 and asserts IntL. Vendor-specific bytes 252-255 of the upper page hold the data words of the last write (the firmware's write buffer).

Standard Firmware
5.3.1 the address counter rolls over inside the 128-byte page reads and writes: 127 -> 0 and 255 -> 128
5.3.2, 5.3.3 up to four data words, written at the STOP; a repeated START discards them buffered, applied at the STOP; a fifth word is not acknowledged and the write is dropped; a repeated START drops it
Table 5-3 writable bytes 86-106, 111, 112, 118 stored; 119-126 (password, optional) acknowledged, not kept; 127 page select; everything else acknowledged and ignored
6.2.11 page select of an unsupported page reverts to 00h any value written to 127 leaves 00h (only page 00h exists)
6.2.3 flags latch and clear when read bytes 3-21 are cleared after they are sent; Rx LOS conditions are latched between transfers and set again while they last
6.2.8 masks bytes 100-104 mask flag bytes 3-7; bytes 8-21 have no mask (theirs are on page 03h)
6.2.2 IntL until byte 2 is read after power up; byte 2 bit 1 shows IntL as stated; IntL and byte 2 are updated at every STOP and when a LOS condition latches
6.2.4 two-byte monitor reads must be coherent the monitors change only between transfers (the host writes them before the run)
SFF-8679 6.3.1 ModSelL high: no response checked at the address byte and before every byte of a transfer; a read stops driving SDA within one byte
Table A-1 tNACK (volatile writes) 0: the next transfer is acknowledged at once

IntL and byte 2 are recomputed after the STOP (19 flag bytes and 5 masks, about 4.6 to 8.1 us), inside the 20 us bus free time of Table 5-1.

IPMB responder (ipmb.pe)

Address Use
0x00 OWN own slave address, 8-bit (write) form; 0 at start: 72h
0x01 NDEV number of Get Device ID data bytes at 0xA0; 0 at start: 11 bytes of defaults (device ID 01h, revision 01h, firmware 1.00, IPMI version 02h, no additional support, manufacturer and product 0)
0x02 COK, 0x03 CBAD, 0x04 CFAIL responses sent, requests dropped, responses not delivered (mod 256)
0x05 LAST 01h response sent; 81h shorter than 6 bytes; 82h header checksum; 83h message checksum; 84h a response (odd netFn); 85h longer than 32 bytes; C0h not delivered after 3 tries. Stored before its counter, after the counters in address order
0x06 LEN length of the last request (rsSA not counted)
0xA0.. Get Device ID data (up to 16 bytes)
0x20-0x5F request and response buffers (frame buffer)
Request Response
netFn 06h, LUN 0, cmd 01h Get Device ID, no data 00h and the NDEV bytes
netFn 06h, LUN 0, cmd 04h Get Self Test Results, no data 00h, 55h, 00h
either of those with request data C7h
another cmd or netFn, LUN 0 C1h
rsLUN not 0 C2h
bad header or message checksum, odd netFn, fewer than 6 bytes none (dropped, counted)
33 bytes or more the 33rd byte is not acknowledged; dropped
a read of the node's address not acknowledged (IPMB uses master writes only)

The response header follows Figure 2-2: rqSA, netFn + 1 with rqLUN, checksum, rsSA, rqSeq with rsLUN, cmd, completion code, data, checksum. While the node answers it does not listen, so a request that comes then is not acknowledged (2.5 allows it) and the requester retries.

Master side: 100 kHz, SCL LOW 125 ticks (5.0 us) and HIGH 125 ticks counted from the rise the node sees (5.16 us measured), START hold and STOP setup 5 us. Before a START the node waits for SCL and SDA high for 55 us (SMBus tHIGH max 50 us), so it does not start inside another master's transfer. A target may stretch SCL at any bit. When a 1 it sends reads back as 0 it has lost arbitration: it lets go of both lines and tries again 100 us later; an address NACK is retried the same way; after 3 tries the response is dropped (C0h, CFAIL).

Limits

  • EDID: 256 bytes (base block and one extension); no segment pointer, so no E-DDC segment 1 and up; no DDC/CI (37h); HPD only goes high once (no hot-plug pulse on a change).
  • QSFP: flat memory only (no pages 01h-03h, so no thresholds and no channel masks), no password check, no Data_Not_Ready time (monitors are valid from the start), no ResetL or LPMode input, no tWR or tNACK busy time; monitors and LOS inputs as described; byte 8 and bytes 9-21 are not maskable.
  • IPMB: two commands; one request at a time (a request that arrives while the node is answering is not acknowledged); no Seq-based duplicate rejection (the two commands have no side effect, 2.6.1); 32-byte messages; it never sends requests of its own, so it never waits for a response.
  • Simulation only, no board.
