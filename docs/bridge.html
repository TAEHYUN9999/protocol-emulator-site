File Role Words
firmware/i2c_uart_bridge.pe Hart 0 is an I2C target, hart 1 a UART transmitter, both running at the same time. Bytes written over I2C come out on the UART. The harts share only the data memory. 105 of 512 (hart 1 starts at word 82)

The point of this firmware is concurrency: two different protocols, each with its own timing, served by the two harts of the barrel core without the host. Hart 0 follows the I2C clock edge by edge with waitp; hart 1 keeps an exact UART bit grid with twait. Each hart owns alternate clock cycles, so neither can delay the other. Checked in simulation only, not on a board. It was added on the RTL of commit a2aad45 without changing it; the 512-word program memory added later (f08b33c) kept the instruction format, so the program assembles to the same words and its tests pass on the current RTL too.

Pins

Pin Use
uio[6] (P6) SCL, open drain, input only (the target never stretches)
uio[7] (P7) SDA, open drain
uio[0] (P0) UART TX, idles high

I2C side (7-bit address 0x4D)

Transfer Meaning
S 0x9A A d0 A d1 A ... P Each byte goes into the ring. A byte that finds the ring full gets no ACK, so the controller stops and sends it again later (flow control without clock stretching).
S 0x9B A n A n ... N P n = bytes in the ring not yet sent on the UART.

The ring index and the full flag are worked out before each byte arrives, so the ACK follows the eighth SCL fall within a few ticks; the next count is worked out while the controller drives its ACK, so the first data bit of a read byte is valid well within the Fm+ tVD;DAT of 450 ns.

UART side

8N1, LSB first, 50 ticks per bit (500 kbaud, .equ BIT). Each frame starts on a fresh timer period (tset just before the start bit), so the bits inside a frame sit exactly on the bit grid whatever the I2C side is doing. A byte leaves the ring when its stop bit starts.

Data memory

Address Use
0x00 to 0x0F Ring, 15 bytes usable
0x10 HEAD, written by hart 0 only
0x11 TAIL, written by hart 1 only

Each index has one writer, so no lock is needed: hart 0 stores the byte before it moves HEAD, hart 1 reads the byte before it moves TAIL. Hart 1 clears both at start.

Tests

test/test_bridge.py (cocotb) reuses the UM10204 controller and bus monitor of test/test_i2c.py and the UART frame decoder of test/test_uart.py; neither looks at the firmware. A test passes only if both protocols are right at the same time: every I2C edge meets UM10204 Table 11, every UART frame has a start bit, a stop bit and all inner edges on the bit grid, the bytes come out in order with none lost or doubled, and hart 1's late flag stays 0. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_bridge
Test What Result (2026-11-10)
test_bridge_fm 40 random bytes at 400 kHz. The I2C byte (22.5 us) is slower than the UART byte (20 us), so the ring never fills. PASS: 40 frames exact, 0 NACKs, 0 Table 11 errors, pending count right after the last write 0
test_bridge_fmplus_flow_control 60 random bytes at 1 MHz. I2C fills the ring faster than the UART empties it. PASS: 9 ring-full NACKs, all 60 bytes out in order, 0 Table 11 errors, pending 14 right after the last write, 0 at the end
test_bridge_wrong_address Address 0x42 PASS: NACK, UART idle

Controls (test_bridge_fmplus_flow_control with a changed firmware): without the ring-full check the UART gives only 44 of 60 bytes; with the write ACK delayed by 800 ns the bus is left busy. Both fail.

Rerun of the whole module on commit b4edcc2 (2026-11-12 00:25, Icarus Verilog 11.0, cocotb 2.0.1, RTL, two simulations sharing the machine): test_bridge TESTS=3 PASS=3 FAIL=0 SKIP=0, 19 s wall; every test listed above passed.
