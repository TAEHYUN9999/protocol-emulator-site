File Role Words
firmware/picicsp.pe Hart 0: a PIC16F1847 in Program/Verify mode (LVP key 'MCHP', six-bit commands, 14-bit data words, 32 row latches, internally timed programming, bulk and row erase, configuration space with the device ID). Hart 1: a programmer run by host commands (key entry, any command with or without a data word, reads, row writes and reads, timed waits). 512 of 512 (hart 1 starts at word 350)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (shin as a pin test, shin.lsb, shout.lsb, high/low/rel, tset/tsetr/twait, tgeth/tgetl, the host FIFO, ld/st on the data memory and the frame buffer); the RTL is unchanged. The two harts use the same three pins in turn (ICSPDAT is driven by the programmer for commands and data and by the target during reads), so the programmer can program the target on one chip. Checked in simulation only, not on a board.

Section and table numbers are those of the Microchip PIC16F/LF1847/PIC12F/LF1840 Memory Programming Specification (DS41439A, 2010).

Timing

The target polls MCLR and ICSPCLK with shin (four ticks per poll); while it waits for a rise it also runs the busy timer (65535-tick periods for the 5 ms cycles). It drives read data at most 20 clocks (0.40 us) after an ICSPCLK rise (TCO is 80 ns), so the high phase must be longer than that: 2 us at the programmer's 250 kHz. A command arriving during TPINT, TERAB or TERAR is counted and has no effect (its data clocks are still taken). The programmer leaves two half periods (4 us at 250 kHz) as TDLY; the target's command decode fits in the 1 us minimum TDLY at 250 kHz.

Host interface

Programmer commands (FIFO) and answers: 01h enter [0]; 02h c command c [0]; 03h c lo hi command c with a data word [0]; 04h c command c and a read [lo, hi]; 05h c n command c, then n x 100 us [0]; 06h r and 64 bytes, row r (Reset Address, r x 32 Increment Address, 32 Load Data for Program Memory with an Increment Address between them, Begin Internally Timed Programming, 2.5 ms) [0]; 07h r row r read [64 bytes]; 08h exit [0].

Controls

Each change was made in a copy of picicsp.pe and run with PIC_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Target expects the key MSB byte first test_pic_target_session no entry: the device ID reads 3FFFh (ICSPDAT not driven)
Target without the busy check test_pic_target_session the command 4.8 ms after Bulk Erase is taken (count 0)
Target programming replaces instead of AND test_pic_target_rules 2AAAh programmed over with 3555h reads 3555h
Programmer TENTH 160 us test_pic_programmer TENTH 8026 clocks, below 250 us
Programmer TPINT wait 2.0 ms test_pic_programmer commands while the model is busy

A copy without the two TDLY half periods passes test_pic_programmer: the code between a command and its data alone leaves 116 clocks (2.3 us, 1 us required) at 250 kHz, so the explicit TDLY is a margin, not a need, at this clock.

Limits

  • Program memory 0000h..003Fh only; no data memory; no externally timed programming; no high-voltage entry.
  • The key is matched bit by bit from the first clock after MCLR falls; after a wrong bit the match starts again at the next bit, so a key preceded by stray bits that look like its start can be missed (the programmer sends it right after MCLR falls).
  • Read data is valid 0.40 us after the ICSPCLK rise (TCO 80 ns), so the high phase must be longer.
  • Simulation only: no board, no gate-level run.
