File Role Words
firmware/endat.pe Hart 0 is an EnDat master: position requests with the EnDat 2.1 mode command 000111 or the EnDat 2.2 command 111000 at a lowered clock (500 kHz), the mode bits after 2T, DATA let go in period 9, the start bit polled, F1, F2, the position LSB first and the CRC5 checked. Hart 1 is an encoder: saves its position at the first falling edge, reads the mode command, drives DATA from period 10, a computing time, the start bit, F1, F2 (inverted F1 for 2.2), the position and the inverted CRC5, then the recovery time tm. Both on the same pins are a loopback. 274 of 512 (hart 0 136, hart 1 138)

No RTL change: existing instructions only (twait grid, high/low/rel, shout/shout.lsb, shin, waitp/waitp.to, the CRC unit as CRC5, ld/st, host FIFO). Checked in simulation only, not on a board. The clock is lowered as asked: 500 kHz by default, the encoder checked at 1 MHz too (EnDat allows up to 2 MHz without propagation-delay compensation, 16 MHz with it).

Sources

The EnDat specification itself is HEIDENHAIN's; its public technical information was read:

Source Used for

Not found in public text and chosen here: the encoder samples the mode bits at the rising edges (the H-TI figure suggests it); no additional data words after the 2.2 command (111000 is answered like an EnDat 2.2 position request with F2).

Pins

Pin Use
P0 CLOCK: master output, high at rest
P1 DATA: master drives it in periods 2..8, the encoder from period 10 and at rest (low); a pull-down (the logic side of an RS-485 receiver held low) when nobody drives

Timing

Master: one twait period is half a clock period (data memory 0x01, default 25 ticks: 500 kHz). It changes DATA right after its falling edges and reads a bit just before the rising edge that follows the one on which the encoder put it out. While it reads, the low half is one or two ticks longer than the high half (the read sits before the rising edge). It polls up to 64 clocks for the start bit, then reads F1, F2 (2.2), the position bits (data memory 0x00, default 25) and 5 CRC bits, raises CLOCK for good and waits for DATA to fall (the end of tm) before the next request. Between two bits it only stores the bit, which fits in half a period; the last position byte is shifted into place after the last clock (a first version did it before the CRC bits and stretched one high half to 39 ticks).

Encoder: it follows CLOCK with waitp; after the first falling edge it lets DATA go (period 1), reads the six mode bits at rising edges 3..8, and drives DATA low from the falling edge of period 10. After the computing time (data memory 0x0A clocks, default 2) it puts out the start bit, F1, F2 and the position bits LSB first at successive rising edges, feeding them to the CRC unit, then the inverted CRC MSB first; at the master's last rising edge it drives DATA high for tm (data memory 0x0B, 0x0C ticks, default 500 = 20 us) and then low.

Parameter Value
Master clock 500 kHz: every period 100 clocks; low halves 50..54 clocks, high halves 46..50 clocks (tHI, tLO at least 0.2 us = 10 clocks)
Encoder tm 20.26..20.28 us from the master's last rising edge (EnDat 2.1 commands: 10..30 us)
Encoder DATA direction lets go 8 clocks after falling edge 1, drives 6 clocks after falling edge 10 (the master lets go in period 9)
Encoder clock right at 500 kHz and 1 MHz

Host interface

Master (hart 0): host command 01 (000111) or 02 (111000); answer: status (0 good, 1 no start bit within 64 clocks, 2 CRC wrong), F1, F2 (1 for an EnDat 2.1 command), the position as 4 bytes LSB first, the CRC as received.

Encoder (hart 1), data memory: 0x04..0x07 position LSB first, 0x08 position bits (0 = 25), 0x09 F1 (bit 0), 0x0A computing time in clocks (0 = 2), 0x0B, 0x0C tm in ticks (0 = 500), 0x0F = 1: 4 host bytes taken while it idles replace the position (only when hart 0 is not running: the two harts share the host FIFO, and in a loopback the encoder would take the master's commands); counters 0x0D transfers answered, 0x0E other mode commands (not answered).

Tests

test/test_endat.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_endat

The models are written from the sources above, not from the firmware: the CRC5 (checked against the third-party values), the answer layout, a master model (2T, mode bits on falling edges, DATA let go in period 9, polling, reading before rising edges) and an encoder model (position at the first falling edge, mode bits at rising edges, drive from period 10, computing time, answer at rising edges, tm). A recorder logs CLOCK, DATA and the chip's DATA enable. Only pins, host bytes and data memory addresses come from the firmware header.

Controls

Each control is a copy of endat.pe with one planted change, run with ENDAT_FW=<path>. All fail, each at the check it aims at.

Planted change Test First failure
Encoder CRC from 00000 instead of 11111 test_endat_encoder the 000111 answer's CRC bits differ from the model's
Encoder F2 not inverted test_endat_encoder the 111000 answer has F2 = 0 with F1 = 0
Master keeps driving DATA after period 9 test_endat_master no start bit within 64 clocks: status 1
Encoder drives DATA from period 9 test_endat_encoder the drive starts 8 clocks after falling edge 9, not after falling edge 10

Limits

  • Position requests only: no parameter, memory-area, reset or test commands, no additional data words (111000 answered without them), no propagation-delay compensation, no clock above 1 MHz checked.
  • tm is the EnDat 2.1 recovery (10..30 us); the short 2.2 recovery (1.25..3.75 us) is a setting, not checked.
  • The encoder's computing time is a number of clocks, not a time.
  • Simulation only: no board, no gate-level run.
