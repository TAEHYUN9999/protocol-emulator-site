Host reads of the shared SRAM without a steal: design, not built

Status: a design for review (branch int5b, 2026-11-13). Nothing here is in the RTL. It answers item R-07 of the plan: can a host command that reads the shared SRAM be kept from taking a clock edge from a hart ("steal") by a dummy byte in the read command?

What the RTL does now

Read from src/pe_shm.v and src/pe_host_spi.v of this branch; the two statements marked "test" are checked by test/test_shm.py test_shm_host_read_ahead.

  • Each core has one single-port SRAM (pe_shm). One access per clock edge. A hart's ld/st (h_req) is refused at its edge when the zero fill, a host access (x_req) or an urgent line-unit access has the port; the hart then waits one tick and the sticky steal flag is set (STATUS byte 6 bit 5).
  • A host byte is answered one clock after byte_valid, so the host access is made at the byte_valid edge and cannot wait. That is the only reason a host read can steal.
  • There is already a read-ahead: p_req/p_word name the word the host will read next, pe_shm reads it at an edge no hart, queue or urgent unit wants (sel_p), and a host read of a word held in that buffer (p_hit) needs no access. A store to the buffered word drops the buffer.
  • When the read-ahead is asked for:
Command First byte or word Following bytes or words
DATA_R (0x13, 0x17) from the 7th bit of the address byte to byte_valid: one SCK period, 8 clocks at the fastest SCK (clk/8), 10 in the tests a whole SPI byte, 64 clocks or more
CAP_R of frame buffer words (0x32) none: the access at the address byte's byte_valid always takes the port from the first data byte on, one word ahead (two SPI bytes)
ETH_W (0x40), DATA_W a write: always takes the port at its edge the same
  • So a DATA_R steals only if every edge of the window is taken: 8 clocks are four edges of each hart, and an edge is free whenever the hart that owns it does not run a ld/st in it. With one hart loading in every tick the other hart's edges are free and no steal happens (test). With both harts loading in every tick there is no free edge and the host takes one (test). The first word of a CAP_R of the frame buffer and every ETH_W word take the port whether or not a hart wants it, and steal when one does.
  • DATA_W cannot steal from its own core (it is written only while both harts of the core are stopped), and the two cores have separate SRAMs.

What a dummy byte can and cannot do

A dummy byte between the address and the first data byte gives the first read the window the later bytes already have: 64 clocks or more (32 edges of each hart) in place of 8. It removes the unconditional access of CAP_R's first word in the same way.

It cannot give a guarantee. The read-ahead only uses edges nobody wants, and a firmware may run ld/st in every tick of both harts for longer than any window (the copy loops of the repository's firmware hold the port for at most 19 edges in a row, pe_shm.v header; 64 clocks cover that, 8 do not). A guarantee needs one of two rules at the byte_valid edge when the buffer is still empty:

  1. Steal as now (dummy byte only). The contract stays "exact unless steal is set", and the flag stays the only evidence. Steals by host reads become rare, not impossible.
  2. Never steal for a read; say so on MISO. The host access for a read is dropped when the buffer does not hold the word; the byte sent is then not valid and the host must know. The dummy byte becomes a ready byte: 0xA5 when the word is in the buffer, 0x00 when not, repeated every byte until it is (the host keeps clocking and takes the data after the first 0xA5); later data bytes keep the same rule through a per-byte pattern, which is where this gets expensive: every data byte would need its own ready mark, or the read stops being a plain byte stream. With this rule a host read can never change a hart's timing, and the cost moves to the host: a read may take longer, or never complete while a firmware saturates the port.

Rule 2 for the first byte only, with rule 1 for the following bytes, is not a guarantee either. The clean form of rule 2 is word-at-a-time: one command reads one word (0x18: address byte, ready byte(s), hi, lo), and a block read is a loop on the host. A 128-byte frame buffer then costs 64 commands of 5 bytes in place of one of 130.

Proposal

Keep the present commands and their timing (the host library host/pehost, 46 test modules through test/fw_host.py, the boards' scripts and the lockstep model all use them), and add the dummy byte as new command codes, so that nothing existing changes:

Code Command Bytes
0x18, 0x1C DATA_RD of core 0, core 1 address, one dummy byte (answer 0x00), then data bytes as DATA_R
0x36 CAP_RD as CAP_R with one dummy byte after the address byte(s); for the deep memory the dummy byte changes nothing (the capture SRAM is not shared with the harts)

RTL, src/pe_host_spi.v:

  • A flag rd_dummy set by the new codes. The address byte stores the address and makes no access (dr_go, cr_go gated off while rd_dummy and the state is the address state); p_req is raised from that byte_valid on with p_word of the first byte; the dummy byte's byte_valid makes the access, which is a p_hit when any edge of the dummy byte was free.
  • The 32 host states are all in use (S_CMD to S_START1B, 5 bits). The dummy byte needs no new state if the address states are passed twice under the flag (first pass: latch the address; second pass: the access and the move to the data state), which keeps the state register at 5 bits and the FSM proofs (run_equiv_fsm.sh, the host_state == 5'd1 probe of pe_por_props.sv) as they are.
  • src/pe_shm.v does not change: the buffer, p_hit and the arbitration are already there. The st that drops the buffer in the dummy window is covered by the existing rule (the buffer is refilled at the next free edge, or the access steals).

Checks:

  • formal/pe_shm_props.sv: a new claim, "if p_req named word w for n clocks with at least one edge in which no hart, queue or urgent unit asked, and no write to w came after it, the host read of w is a p_hit" (no steal by that read). The environment already bounds x_req to one in 8 clocks; the claim is local to pe_shm. That is item (나) of the plan's T20, and it also covers the present DATA_R.
  • cocotb, test/test_shm.py: the steal flag stays 0 through 1,000 DATA_RD and CAP_RD transfers while each hart runs the longest ld/st run of the repository's firmware; it is 1 with the present DATA_R under the same load (the control); both harts loading in every tick still steal with DATA_RD, and the test says so.
  • A common check at the end of every cocotb test that does not use a line unit: steal is 0 (item (다) of T20). This needs no RTL change and can be done first; it would show how many of the present tests already see a steal from the host helper's DATA_R.
  • Host side: Chip.data_read() and fw_host.mem() switch to the new code when STATUS byte 11 says the RTL has it (this is what the revision byte is for), and keep 0x13 otherwise. The revision that carries it is the one after the last built one: revision 2 was named here first, but it went to the delay lines of P0 to P3 (dly.md), which were built first, so these commands would come with revision 3 or later.

What stays open after it, to be written into the contract sentence of the documents: host writes to the frame buffer while harts run (ETH_W) and line units still steal; a firmware that never leaves a free edge in 64 clocks is still stolen from by a read, with the flag set. The sentence becomes: "a hart's timing is exact unless steal is set; host reads with the dummy byte set it only when both harts use the shared SRAM in every tick for 64 clocks or more".

Size

About 25 lines in pe_host_spi.v, none in pe_shm.v; one formal claim and its planted bugs (the read-ahead dropped, the dummy access made at the address byte); two cocotb cases and controls; pehost, fw_host.py, pins_mock.py, the command tables. The RTL and tests are within a day. It was not built on this branch because the command format is a decision for the host library and the held-out procedure (plan items D-01 and 4.7 depend on a fixed command list), and because the pe_shm proof it should come with takes hours per run on the shared machine (its unbounded step did not converge in the runs on int5).

Rule 2 (never steal, ready byte) is the stronger claim and is not proposed now: it changes what a read returns, needs the word-at-a-time form to be clean, and makes read time depend on the firmware.
