Four small additions to the core (src/pe_core.v), all on instruction bits that the assembler has always written as 0. Every firmware of the repository assembles to the same words as before (test/check_asm_compat.py: 145 files, 32,857 words), so no existing program changes its behaviour.

Instruction Word Meaning
low.h, high.h, rel.h pin pin set with bit 9 the write lands one clock later
shout[.lsb][.od].h rd, pin, wrp.h rd, woe.h rd the plain form with bit 0 the same
twait.t pin 0000 1ppp 0000 0010 twait, and the hart's output bit pin toggles in the tick the period ends
waitm[.ne][.to][.frz] ra, rb 1000 aaab bb00 1zen wait until (pins & ra) == (rb & ra); .ne: until they differ
waite[.to][.frz] ra 1000 aaa0 0010 1ze0 wait until one of the events in ra is there
evs n, evc n (n = 4 to 7) 0000 0nnn 0000 1101 / 1110 set or clear event flag n of the core

z is .frz (the timer freezes on a match), e is .to (give up when the timer period ends, Z = 1; Z = 0 on a match), as for waitp.

Why

  • A hart runs one instruction every two clocks, so its pin writes fall on a 40 ns grid. With .h a write lands in the other hart's clock: the hart can place an edge on any clock, a 20 ns grid. A bit time that is an odd number of clocks, or a fraction like the 33.33 clocks of USB low speed spread as 33, 33, 34, no longer has to be rounded to ticks.
  • A clock output costs instructions. A square wave was twait, a pin write, twait, a pin write and a jump. twait.t does the pin write in the tick the period ends, so twait.t and jmp make a half period, two ticks at the least: a 6.25 MHz clock from two instructions.
  • Waiting on more than one pin. waitp and waitp2 watch one or two pins at a level. waitm watches a pattern on any set of pins (a START condition, a parallel strobe with its address lines), waitm.ne any change of a set (both phases of an encoder).
  • Waiting on something that is not a pin. waite ends on a byte from the host, on room in the output FIFO, on the end of the timer period, or on a flag the other hart of the core set: a device firmware can sleep until "the bus or the host" needs it instead of polling rxb.nb.

Events of waite

Bit of ra Event
7 to 4 event flags 7 to 4, set by evs and cleared by evc of either hart of the core; cleared by a soft reset
3 the timer period of this hart has ended (what twait waits for)
2 the host output FIFO has room
1 the host input FIFO has a byte
0 never

The flags belong to one core: harts 0 and 1 share four, harts 2 and 3 another four.

How .h is built

The write goes into a holding register of the hart instead of its output and enable registers, and from there into those registers one clock later. The holding register keeps a mask of the bits that land, and the mask depends on the form:

  • One-pin forms (low.h, high.h, rel.h, shout.h and its variants) land their pin, whether or not the instruction changed it. A launch of the predictive launcher that fires on that pin in the clock between is overwritten by the held write (the later write wins), also when the pin already had the written level (test_int6_cross.test_h_same_bit_pel).
  • Port forms (wrp.h, woe.h) land only the bits the instruction changes. A launch that fires in the clock between on a bit the instruction leaves as it was keeps its value; on a bit the instruction changes, the held write wins.

Either way a launch on another output bit of the hart keeps its bit (test_int6_cross.test_h_write_keeps_pel_bit, harts 0 to 3). That clock is the other hart's, which writes its own pair, so the two never meet. The launcher writes output bits only, so nothing writes the hart's enable bits in the clock between: the enable mask (hp*_me) is logically redundant and kept only so that the out and enable paths have the same form. The reference model applies the same masks (tools/peiss/isa.py, test_isa3.test_isa3_model_h_masks); it has no launcher, so the lockstep cannot show the difference. The pads are still registered from the next values of the hart registers, and the pad rule (no pad changes its output and its enable at the same edge on the way from released to driven high and back) is applied behind them as before.

Verification

test/test_isa3.py:

Test What it judges
test_isa3_half_tick high/low, shout and wrp followed by the same write on another pin: the second edge is 2 clocks after the first without .h and 3 clocks with it
test_isa3_twait_t twait.t and jmp at periods of 2, 3, 7 and 25 ticks: every edge of the pin is exactly a period after the one before (4, 6, 14, 50 clocks)
test_isa3_waitm the hart sleeps through three wrong patterns and a change outside the mask, wakes on the pattern; waitm.ne ignores a pin outside the mask and ends on one inside; waitm.to gives up with Z = 1
test_isa3_waite hart 0 wakes on the flag hart 1 sets, then on a host byte; after evc the same flag no longer wakes it (waite.to runs out); then the end of the period and room in the FIFO
test_isa3_lockstep 60 random programs with these instructions (tools/peiss/gen.py, isa3=True), RTL against the reference model at every clock

The reference model (tools/peiss) has the six instruction groups; its generator adds them only when asked, so the programs of the older lockstep tests are the same as before, seed by seed. Planted bugs: test/controls.sh, entries isa3_*.

Firmware that uses them (2026-11-18) [measured, RTL, Icarus 11]

Each is a copy of a firmware with only the timing part changed, so the original and its evidence stay as they were.

Firmware Instruction Change Result Original
usb_ls_h.pe (usb_ls.md) wrp.h, woe.h bit times 16, 17, 17 ticks, the second and third write of every three bits one clock late: boundaries on clocks 0, 33, 67, 100 test_usb_tx_h, 5 packets: edges within 6.7 ns of the grid, consecutive 13.3 ns, paired 13.3 ns: inside the low-speed host limits TDDJ1 25 ns and TDDJ2 14 ns (USB 2.0 Table 7-10) 26.7 ns everywhere: outside both host limits
i2c_target_gen_m.pe (i2c.md) waitm.ne while SCL is high the hart sleeps on SCL and SDA and reads SCL with shin when one changes, instead of polling the two in a 10-clock loop test_i2c_target_sr_hold, Fm+ LOW and HIGH 500 ns with stretching, tSU;STA swept over one loop (260 to 450 ns): a repeated START is seen at every set-up down to a hold of 80 ns (wrong at 60); every target test of test_i2c passes with it down to 120 ns (wrong at 100, at tSU;STA 320 ns)

Both holds are far inside UM10204 Table 11 (tHD;STA at least 260 ns in Fast-mode Plus); what waitm buys there is about 40 ns of the worst case and a reaction that no longer depends on where the change lands in a polling loop. The USB change is the one that moves a firmware from outside a limit to inside it.

Limits

  • .h moves a write by one clock, not by less: the grid is 20 ns.
  • twait.t toggles; it does not set a level. The firmware sets the starting level once.
  • The event flags do not cross between the two cores (the peer FIFOs do).
  • twait.t and the event flags of waite are not used by a protocol firmware yet; .h and waitm are (below), the I2S and S/PDIF rates went to the tick generator instead (docs/tickgen.md).
