Which RTL the rest of this page covers

Which RTL this page covers. Sections 1 to 11 were written for the one-core RTL, commit 422ec10, and "the one-core RTL" on this page means that design. The RTL in src/ has since grown a second core, SRAM data memories, a reset synchronizer and delay lines (int5.md, dly.md). The claims table gives the result on the RTL in src/ first where there is one, and then the results of the earlier designs; section 1 and int5.md have the runs of the later steps, and revisions.md says for each check which design it was run on. The sections cover the RTL of commit 422ec10 (merged into this branch in commit 0ba7952): the 512-word design with per-hart pin registers, extended instructions, a deep capture, a USB full-speed line unit, the pad timing rule (dual_role.md) and the waitp2 instruction (architecture.md), hardened with precheck passed. That RTL was built in steps; Revisions below names each step (int1, int2, int3 and the others) with its commits. Sections 1 to 3 were run again on the merged tree (section 1, "Result on the merged tree"), and section 1 once more on the tree of 31851bb with the modules added since (section 1, "Result on the tree of 31851bb"). Section 5 has the gate-level equivalence proof of the hardened int3 netlist, section 6 gate-level runs of it, section 9 a board self test of it and section 10 its static timing and physical checks. The results on int2, int1 and the 512-word RTL are kept and name their RTL; the vendor IP co-simulation (section 8), the SDF timing simulation (section 6) and the 8-hour board runs (section 9) are of earlier RTL versions. Where a result comes from an earlier version of the design, the text says so. Branch int4 adds the RMII and SpaceWire line units (rmii.md, spacewire.md) and the design of a CAN FD bit engine (canfd.md, not built); sections 1 to 4 and the FPGA system simulation were run again on its RTL (f340c4b), and section 6 has its Yosys-netlist gate-level runs.

The kinds of evidence named in the Strength column:

  • Proof. A formal tool shows the property for every input sequence (unbounded), or for every sequence up to a stated depth (bounded). The properties themselves are written by the author.
  • Hardware. The RTL running on a real FPGA at speed. The FPGA is not the ASIC, and the test host and peer on the boards are the author's logic, except the KD240's Xilinx AXI IIC and AXI Quad SPI.
  • Independent model. Simulation against something that does not share the author's reading of the bus: unmodified vendor IP, PDK models, or a protocol model written from the text of a cited specification rather than from the firmware. A specification model is only as independent as its reading of the specification; each protocol page cites the sections it used, so the reading can be checked.
  • Same-author model. Simulation against expectations written by whoever wrote the design (the author, with AI assistance, see docs/ai-use.md). A misreading of a specification can be shared by the design and such a check.
  • Tool check. Static timing, DRC and LVS from the Tiny Tapeout flow, run locally.

Run logs marked "log outside the repository" were produced on the author's machine and are not committed. The runs behind the results on the one-core RTL (the 116-module regression and its controls, the regression of the tree of 31851bb after it, the hardening and its static timing, the gate-level modules, the board self test) are in evidence/ with their SHA-256, as are the summary lines of some earlier runs (evidence/earlier_summaries); python3 tools/evidence_check.py check recomputes the regression summary from the archived results.xml files. Where a log was not found, the text still says "outside the repository" (TODO(final): the remaining ones, or a note that they are lost).

Proved, not proved, and tried to break

Proved by a formal tool:

  • Hart isolation in one direction (C1), unbounded.
  • Power-on and stopped-hart safety of the whole chip: from a chip reset until the host's START no hart effect leaves the core, whatever the program memory holds, a hart that may not act changes nothing, and a soft reset stops the Ethernet transmitter at once. Unbounded (formal/README.md).
  • The predictive launcher's five firing rules and its estimator update (the update of the RTL header on wide integers, so nothing in it wraps), and the Ethernet receiver's buffer rules, unbounded.
  • The USB line unit's line rules (bit stuffing on the line, bit lengths, SE0 width, buffer writes, one direction at a time), unbounded; a packet sent by one copy and received by another arrives unchanged, bounded (135 and 220 clocks).
  • The FIFO against a shift model for 24 clocks after reset, bounded.
  • The capture block against a reference model, both modes (32 entries in flip-flops, 512 in the second SRAM), trigger and pre-trigger ring, unbounded (deep-capture RTL, branch cap2).
  • The synthesis re-encoding of three state machines changes no output, and the hardened netlist is sequentially equivalent to the RTL after reset (C4).

Not proved, only simulated or run on the boards (or not checked at all; section 11 lists the gaps):

  • That each firmware implements its protocol (C2) and that new protocols work (C3): simulation against models, and the FPGA boards for part of them.
  • That a firmware keeps its periods: the static deadline check (section 1) gives a guarantee for the 39 files it passes (and for dly_train.pe, added since); for the others the late flag is read in simulation, in the tests that read it.
  • Timing (C5): static timing, and simulation with the SDF delays of the three corners (no setup or hold checks in the simulator).
  • The SRAM macro itself: simulation uses its functional model, the power-on proof and the gate-level equivalence leave its read data free (the latter cuts it out of both sides), and timing uses its library; nothing checks the macro on silicon (C8).

Tried to break:

  • Planted bugs that every property proof and many tests must catch (section 2): 7 in the 512-word RTL change, 39 in test/controls.sh (per-hart pins, extended instructions, Ethernet soft reset, deep capture, USB line unit, pad rule, waitp2), 15 against the lockstep differential test, 57 in the formal scripts (60 with the launcher's three of branch pelfix), a changed module under the FSM equivalence check, wrong firmware variants per protocol, an always-failing SVA assertion, a wrong block RAM model on the FPGA.
  • One-cell changes of the hardened netlist that the gate-level equivalence proof must reject (section 5), and RTL copies that break hart 1 only, which the hart swap test must catch (section 2).
  • Faults injected into the vendor IP co-simulation: the Linux driver leaving bytes in the RX FIFO, and its interrupt served late (section 8).
  • Edge-of-spec stimulus: the Ethernet receiver with +-9 ns of edge jitter and +-200 ppm clock offset (passes) and +-14 ns (fails, as expected: test_rx_jitter_margin_monte_carlo in test/test_eth_rx.py replays the same 30 frames at +-14 ns and requires that at least one is not received good; 30 of 30 were bad there and 0 of 30 at +-9 ns); speed sweeps up to the first failure (UART, SPI, I2C, JTAG, SWD, CAN, WS2812B); response skew sweeps against the boards' AXI hosts.
  • Predictions written before a board run and kept with the result, including where they missed (fpga/board/predictions/sweep50_20261105.md, English summaryprivate repo file; section 8).

5. Gate-level sequential equivalence

formal/run_equiv_gl.sh builds one miter of the RTL and the hardened netlist (standard cells modelled from the liberty file), holds reset for the first three steps (one step is one clock edge, so the falling-edge flip-flops are timed exactly), then lets every input run free and compares uo_out, uio_out and uio_oe on every step from step 4 on. The SRAM macros are cut out of both sides: each instance (of a (* blackbox *) module of src/, matched by instance name and type) is removed, its input pins (clock, enables, address, write data, bit mask and the BIST pins, 92 bits for a 512x16 macro) become outputs compared on every step from step 0 on, and its read data becomes one free input shared by the RTL and the netlist instance of the same name. Lemmas on the state machines are proved first (PDR: the binary host state machine equals the netlist's, the one-hot Ethernet and USB state machines of the RTL are one-hot), then ABC signal correspondence and dprove close the main property.

Why cutting the macros loses nothing: the proof covers every sequence of read data, the same on both sides, and shows that the two designs then drive the same chip pins and the same macro pins. An instance of the same type is the same PDK cell on both sides, a deterministic machine; with the same content at power-on in both chips and the same pin values on every step it returns the same read data, so a real run of the two chips is one of the runs the proof covers. Nothing about the macro is assumed, not even its synchronous read (the free read data may change on any step; a real macro changes it only after a rising clock), and any memory content is covered. The macro pins are compared from step 0 so that writes while reset is held must match too. The method and the argument are in formal/README.md, Gate-level equivalenceprivate repo file.

Why the method changed: until commit 4574530 both sides got the PDK functional model of the macro, so its 8,192 memory bits became flip-flops on each side. On the int3 netlist (two macros) the miter had 78,357 latches, 84 % of them memory; signal correspondence took 4,854 s for a 21 % reduction and dprove did not end in a 4-hour limit. With the macros cut the miter has 12,709 latches. A second cause on int3: the USB line unit's one-hot state machine stopped the induction the way the one-hot host state machine once did (with the host lemma only, signal correspondence removed 5.5 % of the latches), hence the lemma on it.
