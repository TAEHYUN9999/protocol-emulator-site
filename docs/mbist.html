src/pe_mbist.v lets the chip test its own SRAM macros: it runs March C- or March SS on one macro through the macro's BIST port and keeps the first failing address, the failing bits, the March element and operation, the failure count and the number of clocks the run took, for the host to read. It answers the judging question "what if the SRAM does not work in silicon?" with a measurement made by the chip itself, macro by macro. Branch int6u developed and verified it on its own; branch int6_mbist connects it to the five macros of project.v and to the host SPI link (see In the chip).

Numbers below are labelled [measured] (a run of the tests or tools named next to them), [calculated] (arithmetic on measured or specified values) or [estimate].

BIST port or functional port

The decision was made after reading the three PDK views of the macros (macro/RM_IHPSG13_1P_512x16_c2_bm_bist/, macro/RM_IHPSG13_1P_1024x16_c2_bm_bist/):

View What it says
Functional model (RM_IHPSG13_1P_core_behavioral_bm_bist.v, the same file for both sizes) The BIST port is modelled: with A_BIST_EN = 1 the address, data, mask, MEN, WEN, REN and the clock come from the A_BIST_* pins (ADDR_MUX, ..., CLK_MUX)
Datasheet (*.txt) "All timings are identical for BIST mode." "One cycle before and after A_BIST_EN changes no read, write, or write-through operation is allowed. Set A_MEN and A_BIST_MEN to 0."
Liberty (slow corner) The A_BIST_* inputs have setup and hold against A_BIST_CLK; A_BIST_EN has no timing arc (a static select); A_DOUT has arcs from A_CLK only

Decision: the BIST port. The multiplexer that a functional-port design would put in front of every macro already sits inside the macro, so nothing is added to the functional paths (int5's program SRAM address arrives at 9.79 ns in the slow corner, its output reaches ins at 7.99 ns [measured on int5, docs/int5.md]); the cost is one AND gate on each macro's functional A_MEN (func_hold, for the datasheet rule) and wiring. Consequences:

  • A_BIST_CLK must be the same clock net as A_CLK, so that the liberty's A_DOUT arcs (from A_CLK) also time the BIST reads. A_BIST_BM is tied high.
  • A_BIST_EN changes only in clocks without any operation on either port: the controller holds func_hold[i] from one clock before bist_en[i] rises to one clock after it falls and keeps bist_men low in those clocks (checked in simulation by tb_mbist.v with the functional port reading in every clock, and proved, see Formal).
  • Coverage gap: the macro's functional-side input buffers and its internal multiplexer leg for the functional pins are not exercised by MBIST, nor is the chip logic before them. The host covers that leg with the existing commands: PROG_W/PROG_R, DATA_W/DATA_R and ETH_W/CAP_R patterns (walking ones and zeros, address-in-data) go through the functional ports. MBIST then tells the two cases apart: a macro that passes MBIST but fails the host pattern test points at the functional input leg or the chip logic.

Operation

Algorithms

Elements Operations per word
March C- up(w0) up(r0,w1) up(r1,w0) down(r0,w1) down(r1,w0) up(r0) 10
March SS up(w0) up(r0,r0,w0,r0,w1) up(r1,r1,w1,r1,w0) down(r0,r0,w0,r0,w1) down(r1,r1,w1,r1,w0) up(r0) 22

"0" is the data background and "1" its complement. With allbg the run repeats for the five backgrounds 0x0000, 0x5555, 0x3333, 0x0F0F, 0x00FF: every pair of bits of a 16-bit word holds different values in at least one of them, which is what coupling faults between bits of one word need (with the solid background the two bits are always written together).

March SS (Hamdioui, van de Goor, Rodgers, 2002) adds the double read and the non-transition write: it finds deceptive read-destructive faults (the read returns the right value but flips the cell) and write-disturb faults, which March C- cannot see (Faults). The two algorithms share the hardware: element 0 is w0, element 5 r0, elements 1 to 4 read y first (y = 0 for 1 and 3, 1 for 2 and 4) and end with w ~y; the decode is a few gates.

Sequence and time

One operation per clock. Per run: hold (functional port held, no operation), enter (A_BIST_EN set, no operation), the operations, leave (no operation; the last read is compared here), exit (A_BIST_EN cleared, functional port still held), then done. A run takes 4 + operations clocks [measured, test_pdk_pass_all, equal to the formula in every run]:

Macro March C-, 1 background March C-, 5 March SS, 1 March SS, 5
512 words 5,124 clocks (102 us) 25,604 (512 us) 11,268 (225 us) 56,324 (1.13 ms)
1024 words 10,244 (205 us) 51,204 (1.02 ms) 22,532 (451 us) 112,644 (2.25 ms)

All five macros with March SS and five backgrounds: 394,260 clocks, 7.9 ms [calculated from the measured runs]. A read issued in clock c is compared in clock c + 1 against the expected word (from the background and the complement bit kept with it); the selected macro's A_DOUT goes through one 5:1 multiplexer and an XOR.

The test destroys the contents of the macro. A run must start with every hart stopped, and the host loads the programs and data again afterwards (In the chip).

Verification

Tests (test/test_mbist.py, wrapper test/tb_mbist.v, make -f Makefile.mbist)

The wrapper holds pe_mbist and five macros in int5's order. With MODEL=pdk they are the PDK models (-DFUNCTIONAL); with MODEL=fault they are test/sram_fault_bm_bist.v, a copy of the PDK behavioural core (same BIST multiplexer and timing) whose accesses go through a fault chosen at run time. The functional port of every macro is driven by the test, gated by func_hold as the chip would. The wrapper counts, at every clock edge, violations of the datasheet rule (an operation on either port at the edge before or after an A_BIST_EN change, two A_BIST_EN at once, a BIST address above 511 on a 512-word macro) and BIST reads that return X.

tools/march_model.py implements the same fault semantics and the same algorithms in Python. For every fault the test requires the RTL's result bytes to equal the model's prediction: pass or fail, failing read count, and for the first failure the element, operation, address, syndrome, lowest bit, background, and the clock count.

Fault injection

Fault kinds of test/sram_fault_bm_bist.v (and march_model.Fault): SAF (cell stuck at v), TF (a cell that cannot rise or cannot fall), AF_NA (an address with no cell: writes lost, reads 0), AF_MAP (address a reaches the cell of address b), AF_MULTI (address a reaches its own cell and b's: writes both, reads the AND), AF_BIT (an address line stuck), CFin (an aggressor transition inverts the victim), CFid (an aggressor transition forces the victim), CFst (an aggressor state forces the victim), each coupling between two words or two bits of one word, DRDF (a read returns the right value and flips the cell), RDF (a read flips the cell and returns the flipped value), WDF (a write of the value already held flips the cell), IRF (a read returns the wrong value, the cell keeps it), IO (an output bit stuck for every address). Power-up contents are a fixed pattern ((a x 40503) XOR 0x5A5A) in both models.

Formal

formal/run_formal_mbist.sh with formal/pe_mbist_props.sv (tools as in formal/README.md): the controller and the five collars, chained as in src/project.v. Every input is free: start, cfg, rd_idx and the read data of all five macros in every clock; the only assumption is reset in the first clock. Claims 2 to 5 are on each macro's own BIST pins, as its collar drives them:

  1. A run always ends with done. While busy, a rank built from the state (hold, enter, then the sequencer position {background, element, address progress, operation} counted down, then leave, exit) falls in every clock, and in the run state the position grows in every clock; busy falls only with done. The rank is bounded, so every run ends within its starting rank (a bound; the exact count, 4 + operations, is measured in simulation).
  2. Datasheet rule: when A_BIST_EN of a macro changes between two clocks, neither clock has a BIST access and the macro's functional port is held in both.
  3. Idle: no A_BIST_EN, no hold, no access (the power-on claim for int6); at most one A_BIST_EN; A_BIST_EN only where the functional port is held.
  4. A BIST access only in the run state, with that macro's A_BIST_EN, a read or a write.
  5. No address above 511 on a 512-word macro.
  6. fail is set exactly when a failing read was counted; the first failure's address and syndrome stay until the next start.
  7. In every clock of the run state the macro under test gets the operation of the controller's sequencer: an access, write or read, address and data as the shared bus of the controller before the collars gave (605dee8).
  8. The syndrome the controller gets in a clock is the read data of the macro under test XOR the word expected for the read issued in the clock before, and 0 when there was no read.

Strengthening invariants (also asserted): the configuration matches BIG, element, operation, background and address within their ranges, func_hold and bist_en as a function of the state, and lockstep: the collar of the macro under test (and for one clock after its A_BIST_EN falls) holds the controller's background, element, operation and address and the compare stage of the read before, every other collar holds 0. The collars' internal state is reached by connect after flatten (the mprobe lines of the property file); the RTL has no port for it.

Where the flip-flops go [calculated from the RTL, 130 in all]: state, configuration and done 10, sequencer 19, compare stage 21, first failure 35 (address 10, syndrome 16, element, op, background) and fail 1, failure count 16, clocks 18, bist_en and func_hold 10. A smaller variant [estimate]: without the clock counter (it is 4 + operations, known in advance) and with an 8-bit failure count, about 26 flip-flops and 1,300 um^2 less.

The macros are spread along the die (int5's config.json places them up to x = 1,361 um), so the BIST bus and the five A_DOUT buses are long. At 20 ns there is room: 6.61 ns from A_DOUT with the 4 ns budget for the macro's clock-to-output and the wire. If routing shows otherwise, one register stage on the A_DOUT side (16 flip-flops) moves the compare one clock later without changing the result bytes.

Emergency path when an SRAM fails

What still works when a macro fails [calculated from the int5 structure]:

Failed macro Effect Fallback
core 0 program (0) harts 0 and 1 cannot run run the firmware on core 1 (harts 2, 3); int5 ran 21 of 22 firmware modules on core 1 with PE_CORE=1 (docs/int5.md); the pads of all four harts stay usable
core 0 shared SRAM (1) ld/st, the frame buffer and the line units of core 0 fail firmware without ld/st still runs on core 0 (16 of the 130 files in firmware/ [measured, assembled]); the others move to core 1

both program macros no hart runs the ROM below

Proposal for the last row, a boot ROM on core 0's fetch path: a ROM with a registered output, addressed with the same next-PC as the program SRAM, and a 2:1 multiplexer on ins selected by a host bit (for example CTRL bit 5, "fetch from ROM"). Contents: firmware/uart.pe (23 words, both harts: a UART bridge between the host FIFOs and P0/P1) and firmware/spi_master.pe (20 words at word 32); neither uses ld/st, so a dead shared SRAM does not matter, and the host FIFOs are flip-flops. Host commands

The codes proposed in the plan, 0x48 and 0x49, were free in src/pe_host_spi.v (used there: 0x01 to 0x05, 0x10 to 0x17, 0x20 to 0x23, 0x30 to 0x34, 0x40 to 0x45) and were taken. RTL_REV is still 0x03; the merge of int6 raises it.

Code Command
0x48 MBIST one byte cfg (as Interface); the bytes after it are the result bytes from byte 0, so the first one shows busy (0x80 | cfg) when the run started and the old byte 0 when it did not
0x49 MBIST_R result bytes 0 to 11 with auto increment; bytes 12 to 15 read 0, then byte 0 again (the index is the 4-bit STATUS index)

Rules:

  • MBIST starts nothing while any of the four run bits of CTRL is set, while a test runs, or for macro 5 to 7.
  • While a test runs (busy), a CTRL byte leaves the run bits 0 (its soft reset bit works), and PROG_W and DATA_W of either core are dropped and set wdrop, as if a hart of that core ran. Other host traffic to the macro under test (ETH_W, an armed capture, a line unit) is not refused; it is lost, and the host should wait for done.
  • A soft reset neither stops a run nor clears the result bytes. The chip reset does both.
  • The contents of the tested macro are gone. March with the solid background leaves 0x0000 in every word (the state of the shared SRAM's power-up zero fill); with five backgrounds it leaves 0x00FF, so a run with the solid background last, or a chip reset, restores the zeros of the data memory and the frame buffer. The capture's record of which words hold entries is not changed by a test: arm the capture again before reading it.
  • pe_host_spi state is 6 bits now (two more states, S_MBIST 32 and S_MBIST_R 33).

Limits

  • The sections up to Emergency path are from the standalone wrapper; the chip results are in In the chip. Not done for the chip: hardening, timing of the BIST bus after placement, gate-level simulation, the host library (host/pehost), the FPGA build. The ISS does not model host commands.
  • In RTL simulation a read that returns X is not counted as a failing read (bad is X and the if does not take it). A macro whose output was never driven would so report "pass"; silicon has no X. The chip test therefore also reads the macro's contents after a run.
  • The fault models are behavioural; real defects (resistive opens, weak cells, timing-related faults at speed) are only covered as far as these models represent them. March SS is the strongest of the two for static faults; neither targets dynamic faults (two operations).
  • The BIST write mask is always all ones: the bit-mask logic (A_BM) is not tested.
  • The test runs at the core clock (50 MHz); it says nothing about margin at other speeds.
