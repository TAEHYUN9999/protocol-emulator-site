File Role Words
firmware/sent.pe Hart 0 is a SENT sensor output: calibration pulse, status nibble, six data nibbles, CRC nibble and a pause pulse that keeps every message 284 ticks long, from 4 host bytes per message. Hart 1 is a SENT receiver: it measures each calibration pulse, converts the nibbles with that tick, checks the CRC and the successive calibration pulse rule, and reports each message to the host. 288 of 512 (hart 0 90, hart 1 198)

No RTL change: the firmware uses existing instructions only (twait grid, crc with a left-aligned 4-bit polynomial, the frozen timer waitp.frz + tgeth/tgetl for periods). Checked in simulation only.

Sources. SAE J2716 itself (a paid document) was not read. The numbers come from documents that describe it:

Source Used for
Allegro AN296244, "Using SENT Output Protocol with A17700" (cites J2716 2016) message layout; calibration pulse 56 ticks, falling edge to falling edge; nibble = 12 + value ticks (12 to 27); fixed low part, typically 5 ticks; tick = calibration pulse / 56; CRC-4 x^4 + x^3 + x^2 + 1 seeded with 0101 over the data nibbles only (not the status nibble); pause pulse at least 12 ticks, used for a constant message length
Microchip SENT module, section "CRC Calculation", "Recommended J2716 CRC Implementation" the CRC algorithm: table {0,13,7,10,14,3,9,4,1,12,6,11,15,2,8,5}, checksum 5, one table step per data nibble, then one more step with a zero nibble
TI SPRAB22 (SENT decoder) and Infineon AURIX SENT module documentation transmitter clock tolerance +-20 %; a receiver flags successive calibration pulses that differ by more than 1/64 (1.5625 %)

Pins

Pin Use
uio[0] (P0) TXP: SENT output, push-pull, idle high. Also RXP by default, so the receiver hears the transmitter of the same chip (one-pin loopback)
any other pin RXP when assembled with {"RXP": n}: the receiver reads an external SENT line

Timing

One SENT tick is UT = 75 chip ticks = 3.0 us, the usual tick. Every pulse starts with a falling edge one chip tick after a timer boundary and rises 5 SENT ticks later, so every edge lies on the 150-clock grid and the widths are exact: low part 750 clocks, calibration pulse 8,400 clocks, a nibble of value v (12 + v) x 150 clocks, a message 284 x 150 = 42,600 clocks (852 us). edge_audit.py on the loopback test: 215 edges on P0, every interval a multiple of 150 clocks (750 x 107, 1050 x 23, 1200 x 15, 7650 x 11, ...).

Transmitter (hart 0)

Host to chip (FIFO), 4 bytes per message: status (low nibble), d1 d2, d3 d4, d5 d6 (data 1 is the high nibble of the second byte, the MSB of the data). The bytes are taken one per SENT tick while the line is high, kept in a staging buffer, and used from the next message on; until then the last message is repeated (all zero after the start). While a whole message waits in the staging buffer the FIFO is not read, so every message the host writes is sent at least once and in order.

The CRC unit runs MSB first with the polynomial left aligned (0xD000). Started from 0x3000 it gives the recommended J2716 CRC directly: the recommended method spends its first table step on the seed (0101 times x^4 mod the polynomial is 0011), and its final step with a zero nibble is the multiplication by x^4 that a direct CRC register does on every nibble. test_sent.py checks every CRC nibble on the pin against the table algorithm, and an offline check compared the two for 20,000 random nibble strings.

The pause pulse is PACC - (sum of the 8 nibble values) ticks, PACC = 284 - 56 - 8 x 12 = 132, so a message is always 284 ticks and the pause is 12 to 132 ticks.

Receiver (hart 1)

The receiver measures every falling-edge-to-falling-edge period in chip ticks: waitp.frz stops the timer at the edge, tgeth/tgetl read it and tsetr restarts it 4 ticks after every edge it catches, and the 4 ticks are added back, so the periods are exact to the tick (the edge itself is seen with up to one tick of quantization).

  • A period of 56 x 75 ticks +-20 % (3,360 to 5,040) is a calibration pulse S.
  • Each of the next 8 periods P is converted with that pulse: value = round(56 P / S) - 12, computed as round(14 P / (S >> 2)) by repeated subtraction (no divide instruction). Valid values are 0 to 15 (12 to 27 ticks).
  • After the CRC nibble the CRC of the six data nibbles is computed with the CRC unit and compared.
  • Successive calibration pulses: |S - S_prev| > S_prev / 64 sets flag bit 5. The check runs only between two messages received in a row.
  • With RXPAUSE = 1 (default, matching the transmitter) the pulse after the CRC nibble is skipped as the pause pulse, then a calibration pulse must follow.

Chip to host, 4 bytes per message: {flags, status}, d1 d2, d3 d4, d5 d6. Flags: bit 4 the CRC nibble is wrong, bit 5 the successive calibration check failed. The host must read the FIFO at least once per message (852 us); a full FIFO stalls the receiver, which then loses that message and hunts again.

Errors: a period that is no nibble drops the message, counts RERR and the receiver hunts for the next calibration pulse. A calibration-length pulse inside a message counts RERR and starts a new message, except right after a calibration pulse: while hunting, a pause pulse as long as a calibration pulse is taken for one, and the real calibration pulse then follows; that is not counted.

Data memory (DATA_R): ROK (21) messages reported, RERR (20) errors, RSH:RSL (16, 17) the last calibration pulse in chip ticks. Bytes 0 to 9 belong to the transmitter.

Tests

test/test_sent.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_sent

The model is written from the sources above, not from the firmware: a J2716 decoder that takes tick = calibration pulse / 56 on recorded edges, the Microchip table CRC, and a SENT transmitter model on a test-driven pin with any tick time and jitter. Only the host byte layout and the data memory counters come from the firmware header.

Limits

  • Fixed tick 3 us (UT), 6 data nibbles, pause pulse always on (constant 284 ticks). Other ticks, nibble counts or no pause need other constants (UT, SMIN/SMAX, PACC, RXPAUSE); the nibble count is fixed in the code.
  • No serial messages (short or enhanced serial protocol in bits 2 and 3 of the status nibble): the status nibble is passed through as it is, both ways.
  • The legacy CRC (J2716 before 2008, without the zero-nibble step) is not offered.
  • The receiver does not check the length of the low part (a transmitter must hold it at least 4 ticks).
  • The receiver's FIFO reports need a host that reads at least once per message.
