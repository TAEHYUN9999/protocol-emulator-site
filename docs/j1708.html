firmware/j1708.pe Hart 0: a J1708 transmitter (bus access time 10 + 2 x priority bit times counted from the end of the last character, characters back to back, checksum added, the MID read back and a lost MID finished, then a new bus access; the bus is watched while a host packet is awaited). Hart 1: a receiver (message end after a gap of more than 2 bit times, checksum, 21-byte limit, missing stop bits, the J1587 PID layout). 194 of 512 (hart 1 starts at word 86)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (low/rel, shout.lsb.od, shin, shin.lsb, waitp, waitp.to, tsetr/twait, the host FIFO with rxb.nb, the data memory); the RTL is unchanged. Both harts use the one bus pin, so the transmitter can talk to the receiver on one chip. Checked in simulation only, not on a board.

SAE J1708 and J1587 are sold by SAE and were not read. Everything below is taken from public secondary sources that agree: Kvaser, "Introduction to SAE J1708" and "Introduction to SAE J1587"; Wikipedia, "SAE J1708"; Renesas AN1990 (Rev.0.00, Feb 7, 2018), sections 2 to 5.

Timing

The transmitter counts the bus access time in whole bit times with no fall; a fall is taken as a start bit and the count restarts 10 bit times later, at the end of that character. The count starts when the host packet is complete. While the transmitter waits for a byte of the packet it reads the bus between two looks at the FIFO (getb: rxb.nb, then shin); a low level is the start bit of another node's character, and the transmitter then waits 10 bit times, to the end of that character's stop bit, before it looks at the FIFO again. So no character is in flight when the count starts, and the bus access time is idle time after the last character, also when the packet arrives in the middle of one. It sends on a half-bit grid: each bit is driven at a grid point and, while the MID goes out, read back at the next one (the middle of the bit). The receiver samples each bit in its middle (half a bit after the start bit's fall, then a bit time apart) and ends a message when no start bit comes within 3 bit times of the middle of the last stop bit (2.5 bit times after its end).

Host interface

Transmitter (hart 0): FIFO packet [priority, n, n bytes (MID and data)]; the checksum is added. Receiver (hart 1): [status, n, n bytes with the checksum] per message; status 0 ok, 1 checksum, 2 a stop bit missing, 3 more than 21 bytes (21 kept), 4 the J1587 PID layout does not end at the checksum.

Since 2026-11-13 (a gap of test_gaps.md) test_j1708_tx ends with a busy-bus case: a model node sends 80 54 2D FF and the host packet for a priority 4 message is taken 31.67 bit times into that 40-bit message, inside the last character after its last falling edge. The chip's MID must not start before 18 bit times after the end of that character. This check failed on the firmware as it was until then (181 words): the MID started 9.76 bit times after it. That firmware waited for the host packet without looking at the bus and restarted its idle count only on a falling edge, so the high bits of a character in flight counted as idle time. The firmware was changed for it on branch int5e (getb, Timing; 194 words): the MID now starts 18.06 bit times after the end of that character, and the test passes. The older results of the table are unchanged to the last digit (12.96, 19.62 and 27.12; 16.05; 14.03 and 20.02), and test_j1708_rx and test_j1708_loopback pass as before (one run of the module, 3 of 3, RTL of branch int5e, 2026-11-13).

Limits

  • Secondary sources only (the SAE texts were not read).
  • The transmitter takes any fall as a start bit; if it starts counting inside a character it waits up to 9 bit times longer than needed for that one message. That can happen only for a character that was in flight when the chip left reset: after that the bus is watched whenever the transmitter waits for the host.
  • While the transmitter waits out another node's character it does not take host bytes (up to 10 bit times per character).
  • Collisions are checked against the node model only: on one chip both harts write the same pin register, so two transmitters cannot be overlaid.
  • Simulation only: no board, no gate-level run.
