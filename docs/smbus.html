Both run on hart 0 alone. A setting written by the host (T_TO in particular) no longer skips the CRC polynomial and the T_REP default: before 2026-11-11 the start-up jumped past both when T_TO was not 0, and the PEC was then computed with a zero polynomial (test_smbus_host_settings). The protocols were not part of the design when the RTL was written; they use only existing instructions and the CRC unit as a CRC-8 (polynomial 0x0700 left aligned, MSB first, start 0). The RTL is unchanged. Checked in simulation only, not on a board.

Section numbers are those of the System Management Bus (SMBus) Specification Version 3.2 (SMI Forum, 2022).

Controller (smbus_host.pe)

Everything of docs/i2c.md (master) holds: pins P0 = SCL, P1 = SDA, settings T_LOW, T_HIGH, T_TO at 0x00 to 0x05, commands 0x01 to 0x04, statuses 0xA0 to 0xA5. Added:

Item Meaning
Command 0x81 (0x82 for 10-bit) as 0x01 (0x02) with the PEC. WL > 0 and RL = 0: the PEC goes out after the WL bytes. RL > 0: the RL data bytes are all ACKed, one more byte (the target's PEC) is read with NACK and checked; it is not given to the host. WL = RL = 0 (quick command): no PEC
Command 0x41 (0xC1 with PEC; 0x42, 0xC2 for 10-bit) Block Read: the WL bytes (command code, or for the process call also M and the data) are written, then Sr, address R, and the first byte read is the count N. RL is now the most data bytes the host takes. N <= RL: N bytes follow, the last NACKed (without PEC), or all ACKed and the PEC read with NACK and checked (with PEC); N = 0 without PEC: the count itself is NACKed. N > RL: the count is NACKed, STOP, status 0xA8. Reply: K, K bytes, STATUS, with K = N (0 when the count was not read, or was refused); bytes not read because of an error are sent as 0xFF
Status 0xA8 the block count was larger than RL
Setting 0x06 T_REP the stretching timeout T_TO is waited T_REP times (default 10: 26.2 ms with T_TO = 65535)
Status 0xA6 the target NACKed the PEC the controller sent
Status 0xA7 the PEC read from the target is wrong (the data bytes were given to the host)

On a timeout (status 0xA4) the controller lets go of both lines, as the I2C master does: the target is holding SCL low, so a STOP cannot be made until it lets go.

Target (smbus_target.pe)

Pins P6 = SCL, P7 = SDA, open drain.

Address Use
0x00 ADDR own 7-bit address (0: 0x42, written back)
0x01 REP timeout in units of 65535 ticks (0: 10, 26.2 ms)
0x02 to 0x05 work bytes (own address byte, command, low and high byte received)
0x08 words written
0x09 writes refused for a wrong PEC
0x0A timeouts
0xA0 + 2c, 0xA1 + 2c word register c (command code 0 to 15), low byte, high byte
0xB0 + c byte register c (command code 16 to 31: 0xC0 to 0xCF)
Bus Target
S A+W cmd lo hi P (cmd 0 to 15) Write Word without PEC: the word is written at the STOP
S A+W cmd lo hi PEC P (cmd 0 to 15) Write Word with PEC: the PEC byte is ACKed and the word written when the CRC over the message and the PEC is 0; otherwise the PEC byte is NACKed and nothing is written
S A+W cmd data [PEC] P (cmd 16 to 31) Write Byte, the same with one data byte. A Write Word sent to a byte command has its high byte taken as the PEC: NACKed unless it happens to be right, counted as a wrong PEC
S A+W cmd Sr A+R lo hi [PEC] P Read Word: low byte, high byte; the PEC follows when the controller ACKs the high byte, then 0xFF
S A+W cmd Sr A+R data [PEC] P Read Byte: the byte, then the PEC when the controller ACKs it, then 0xFF
S A+R ... reads the register of the last command
cmd 32 or more NACKed
S A+W cmd data P to a word command (one byte), S A+W cmd P ACKed, nothing written

Any SCL low interval during a transfer longer than REP x 65535 ticks makes the target let go of SDA and wait for the next START.

Tests

test/test_smbus.py (cocotb). The target model and the controller model are written from SMBus 3.2 (PEC by its polynomial, Write/Read Word, Byte and Block layouts with their ACK and NACK rules, the Block Write-Block Read Process Call, tTIMEOUT, Table 2), on the I2C bit rules SMBus builds on; the timing monitor measures SCL low and high between START and STOP, and every interval must fall on the 20 ns clock grid. The target model records every byte it drives and whether the chip ACKed it. Only the firmware's command bytes, statuses, settings and data memory addresses come from this page. Run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T COCOTB_TESTCASE=<test> make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_smbus

Limits

  • Protocols: the controller does any write, read, or write then read with PEC, which covers Send/Receive Byte, Write/Read Byte and Word, Process Call and Block Write, and Block Read and the Block Write-Block Read Process Call (command bit 6), up to 255 data bytes. The host gives the write part of a block as raw bytes (it writes the count itself). The target serves 16 word and 16 byte registers chosen by command code; it has no Block Write or Block Read registers, and a protocol that does not match the command (a word written to a byte command) is handled by the byte rules.
  • No SMBALERT#, Host Notify, ARP or the 32/64-bit protocols of 6.5.10 onward.
  • tLOW:SEXT and tLOW:MEXT (cumulative clock extension, Table 2) are not counted. The controller holds SCL low while the host is late with write bytes; a host that is slower than 10 ms per byte breaks tLOW:MEXT.
  • The target does no clock stretching, so it needs the controller's SCL low phase to be at least about 1 us (its decision on the PEC byte comes within that); the 100 kHz class gives 4.7 us.
  • 16 word and 16 byte registers; the target ignores the general call, has no skew knob and no 10-bit address (i2c_target_gen.pe keeps those).
  • Simulation only: no board, no gate-level run.
