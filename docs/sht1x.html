File Role Words
firmware/sht1x.pe Drives an SHT10, SHT11 or SHT15 over its two-wire interface: Transmission Start, the command byte and its ACK, the wait for the end of a measurement, the two data bytes and the CRC-8 with the sensor's own start value and bit order, status register read and write, soft reset with its 11 ms wait, and the connection reset. 184 of 1024 (one hart)

Written in the flexibility rehearsal of 2026-11-20 (flexibility.md), on the RTL of 4d71a25 (git tree cd2dce2 of src/) without changing it.
It uses only existing instructions: low, high, rel, shout.od, shin, tset/tsetr/twait, tpre, waitp.to, the CRC unit (CRC-8 left aligned, MSB first), shr/rlc for the bit reversals, ld/st and the host FIFO.
Checked in simulation only, not on a board.

Sources

Source Used for
Sensirion, Datasheet SHT1x (SHT10, SHT11, SHT15), Version 4.1, September 2008 Pins (2.2, 2.3); the timing of Table 3 (FSCK at most 1 MHz below VDD 4.5 V, SCK high and low at least 100 ns, TSU at least 100 ns, THO at least 10 ns, TV at most 250 ns); Transmission Start and ACK (3.2); the commands of Table 4; the measurement and its Data Ready signal, the ACK of each byte and the end without ACK (3.3); the connection reset (3.4); the status register bits (Table 5)
Sensirion, application note "CRC Checksum Calculation for Safe Communication of SHT1x and SHT7x Sensors", Version 2, December 2011 Polynomial x^8 + x^5 + x^4 + 1, bit by bit over the command and the response bytes without the ACK bits; start value the low nibble of the status register reversed (s0 s1 s2 s3 0000); the final value reversed before it is sent; examples 1 (humidity 0x0931, CRC 0x1A) and 2 (status 0x01, CRC 0x3D)

The test model was written from these two documents and checks its CRC against both worked examples of the note before it judges the firmware.

Pins

Pin Use
P0 SCK, push-pull (an input only at the sensor), idle low
P1 DATA, open drain: driven low or released; needs the external pull-up of the data sheet (10 k)

Timing

The firmware counts 13 ticks between SCK edges.
A bit that the firmware sends is high 13 ticks and low 13 ticks; a bit that it reads is high 14 ticks and low 12, because the sample (shin) sits at the end of the high phase, just before the falling edge.

THO, DATA after the falling edge at least 10 ns 80 ns inside a byte, 40 ns for the release after the controller's ACK
TV, sensor DATA valid after the falling edge at most 250 ns taken 1.0 us after the falling edge (12 ticks of low phase and 13 of high, less the two-clock input synchronizer); the test reads right up to a TV of 450 ns

tools/petime.py firmware/sht1x.pe: PASS, 18 twaits reached, all in time, least margin 1 tick.
The first run of the tool found a real deadline miss: the host command dispatch took 12 ticks before the first twait of the connection reset, 14 with its two set-up instructions, against a period of 13; a tset after the dispatch fixed it before any simulation ran.

Host interface (FIFO)

Command Bytes Answer
Measure temperature 0x03 code, MSB, LSB
Measure humidity 0x05 code, MSB, LSB
Read status register 0x07 code, status
Write status register 0x06 value code
Soft reset 0x1E code, 11 ms after the ACK
Connection reset 0xFF 0xA0 after nine SCK clocks with DATA released

Codes: 0xA0 done; 0xE1 no ACK to the command or to the status byte; 0xE2 DATA did not go low before the time-out, or stayed low 2 us after the ACK; 0xE3 the CRC does not match (the bytes are still given); 0xE0 an unknown host command.
The firmware keeps the CRC start value in data memory 0x01: the low nibble of the last status byte written, reversed into bits 7 to 4, and 0 at start and after a soft reset.
It computes the CRC in the hart's CRC unit (polynomial 0x3100, register {start, 0}, the high byte is the CRC-8) and compares it with the received CRC byte reversed.

Tests

test/test_sht1x.py, run from test/ or from a private directory:

cd test && make -B COCOTB_TEST_MODULES=test_sht1x

The sensor model takes each command bit at the rising edge of SCK, answers with the ACK and the data bytes TV after each falling edge, holds DATA low as Data Ready when its measurement ends, and checks the rules of Table 3 on every edge: SCK rising edges at least 1 us apart, SCK high and low at least 100 ns, TSU and THO, no DATA change while SCK is high except in a Transmission Start, no SCK edge while it measures, no Transmission Start within 11 ms after a soft reset.
Its measurement takes 300 us instead of 11 to 320 ms, so that a test runs in seconds; the firmware's time-out is tested on its own.

Limits

  • No time-out on SCK: the sensor cannot stretch the clock, so none is needed, but a DATA line held low by something else is seen only as a missing ACK or as 0xE2.
  • The firmware waits for the measurement in a loop on waitp.to; the hart does nothing else meanwhile (the data sheet allows reading later, the firmware does not use it).
  • Status bit 3 ("for testing only") is taken into the CRC start value as written; the data sheet gives no R/W for it, and the model keeps only bits 0 to 2.
  • No power-up wait: the host must not send a command within 11 ms after the sensor's power-up (3.1).
  • Logic levels only; the conversion to %RH and degrees (section 4) is for the host.
  • Not run on a board and not at gate level.
