File Role Words
firmware/witness_i2c.pe I2C witness on hart 1: reads SCL and SDA of a bus without driving them and counts rule violations: START or STOP inside a byte, a second SDA change in one SCL high, tLOW, tHIGH and tSU;DAT below their minimums. Runs alone on an outside bus, or appended to a firmware that uses hart 0 only, to watch that hart's own lines 184 (hart 0: one halt); 438 with i2c_master_gen.pe on hart 0
firmware/witness_uart.pe UART witness on hart 1 (framing error, stop bit short, glitch), with a small 8N1/8N2 transmitter on hart 0 that sends the host's bytes on the pin the witness watches, or the witness on another pin for a line driven from outside 168 (hart 0: 20)

One hart drives a protocol, or an outside device does, and the other hart reads the same pins and checks them. Both only read (rdp, shin, waitp); neither has a low, high, shout or woe. No RTL change. Checked in simulation only.

Reporting

Each violation has a code and a value. The witness adds 1 to the code's counter (they stop at 255) and writes the pair into a log of 8 entries at data memory 0xE0 to 0xEF (0x1D holds the address of the next entry, so the oldest entry is the one there). The host reads both with DATA_R while the harts run. The UART witness also sends each pair to the host FIFO (hart 0 there only reads the FIFO); the I2C witness does so only with 0x1E nonzero, because the I2C master on hart 0 answers the host through the same FIFO. A pair that finds the FIFO full is dropped and counted.

I2C (witness_i2c.pe)

Source: NXP UM10204 Rev. 7.0: 3.1.3 (SDA changes only while SCL is low), 3.1.4 (START and STOP are SDA changes while SCL is high), 3.1.5 (a byte is 8 clocks and the ACK clock), Table 10 (minimums).

Pins: bit masks WSCLM, WSDAM of one rdp and the SCL pin number WSCL (default P0 and P1, the pins of i2c_master_gen.pe); assemble with other values for other pins.

Code Counter Rule Value
1 0x10 tLOW below 0x18 (default 118 ticks, 4.7 us) ticks
2 0x11 tHIGH below 0x19 (default 100, 4.0 us); the high in which a START is made is tHD;STA, not checked ticks
3 0x12 tSU;DAT below 0x1A (default 7, 250 ns): from an SDA change in a low to the SCL rise; 0 when they change in the same sample, 11 when SCL rose before the witness could look (see below) ticks
4 0x13 START or STOP after 1 to 8 clocks of a byte clocks of the byte
5 0x14 a second SDA change in one SCL high (a glitch, or a START and a STOP in one clock) the changes so far in that high (2 or more)
0x15, 0x16, 0x17 FIFO pairs dropped; bytes (nine clocks); STARTs (and repeated STARTs)

The settings are written with DATA_W before the run (0 selects the default, Sm). The timing rules apply between a START and a STOP. SCL and SDA are read together every 4 ticks (160 ns) and the time between changes comes from the hart timer, restarted at each SCL edge and at each SDA change in a low (counting down from 255, so a time of 255 ticks or more reads as 255). A measured time can therefore be up to 4 ticks off the bus; a threshold catches what is clearly shorter than it. tSU;DAT: after an SDA change in a low the witness first looks at SCL 11 ticks after the change was seen (the time it takes to tell an SDA change from an SCL edge), then waits for the rise with waitp.to for 24 more ticks (WTSW). A rise in that window is timed to a tick (11 to 34 ticks) and compared with 0x1A. A rise already there at the first look cannot be timed: the setup was at most about 15 ticks (600 ns, with the 4-tick sampling), and it is counted as short with the value 11, whatever 0x1A says. So a legal Sm setup between 250 and about 600 ns can be reported; Sm devices change SDA long before the rise, near the start of the low. A second SDA change within the window is not seen apart; one after it is. (With polling instead of the window the witness measured about 15 ticks for any rise in its handling time and missed a third of the 30 ns setups of the test.) The witness reacts to a change in at most about 30 ticks, so it is meant for Sm and Fm.

UART (witness_uart.pe)

The frame: a start bit (low), 8 data bits LSB first, 1 or 2 stop bits (high), the line high between frames (as in docs/uart.md).

Address Setting (0: default)
0x00, 0x01 bit time the witness expects, ticks (default 50: 2 us), at least 50
0x02 stop bits it expects, 1 or 2 (default 1)
0x03, 0x04 bit time hart 0 sends (default: the witness's)
0x05 stop bits hart 0 sends (default: the witness's)

WPIN (assembler constant, default P0 = the transmitter's pin TXP) is the pin the witness reads.

From each start edge the witness waits half a bit, then samples in the middle of every bit, one bit time apart; between two samples the line may change once. After the middle of the first stop bit the line must stay high to a quarter bit after the middle of the last stop bit. The sample points use the hart timer: a period ends in a waitp.to time-out and the branch and tsetr after it take two more ticks, so each period is loaded two ticks short (the first, half a bit, three) and the points do not drift.

Code Counter Rule Value
0x10 frames with their stop bits right
1 0x11 framing error: the first stop bit low bit 9
2 0x12 stop bit short: the line falls before a quarter bit after the middle of the last stop bit (the fall is taken as the next start edge) bit 8 + stop bits
3 0x13 glitch: the line high again before the middle of the start bit (a low pulse shorter than half a bit), or two changes between two samples the bit (0 start, 1 to 8 data, 9 stop)
0x14 FIFO pairs dropped

After a framing error or a glitch the witness waits for the line to be high, then for a start edge. After a good frame it takes the first fall after the stop window as the next start edge, also one that comes while it counts the frame (then up to 5 ticks late).

Tests

test/test_witness.py. The references are written from the rules, not from the firmware: an I2C rule checker that walks the recorded SCL/SDA edges with the UM10204 definitions above, and a UART checker that samples the recorded line as this page defines the witness. The witness counters and log must equal the reference. The test traffic keeps every measured time clear of the thresholds by more than the 4-tick sampling.

Controls

Each control is a copy of one witness with one planted bug, run with WIT_I2C_FW or WIT_UART_FW pointing at it. All five fail:

Planted bug Test First failure
I2C: no tLOW report (call wrep after code 1 removed) test_witness_i2c own hart too fast: tLOW counter 0, reference 140
I2C: START or STOP inside a byte not checked (jz wh2 at a byte boundary made jmp wh2) test_witness_i2c rogue pulse: code 4 counter 0, reference 1
UART: no framing check (jnz wsw made jmp wsw) test_witness_uart_other model device: no framing error; the low stop bit is taken as a short stop and the next frame goes wrong: [4, 0, 2, 3] against [4, 1, 1, 2] (frames, framing, short stop, glitch)
UART: after a short stop, wait for a new start edge instead of taking the fall as one (jmp wst2b made jmp widle) test_witness_uart_other model device: the frame after the short stop is lost, 3 frames against 4
UART: sample period one tick longer (bit - 1 and half - 1 instead of bit - 2 and half - 3) test_witness_uart_other model device: the samples drift into the next bit at 100 ticks a bit: [3, 2, 0, 2] against [4, 1, 1, 2]

Limits

  • Pins are assembler constants; one witness per hart, one bus or line each.
  • I2C: the timing resolution is the 4-tick sampling; meant for Sm and Fm. A setup time the witness cannot time (SCL already high 11 ticks after the SDA change was seen) is counted as short, so a legal setup between the minimum and about 600 ns can be reported; a second SDA change within 24 ticks of the first in one low is not seen apart. tHD;STA, tSU;STA, tSU;STO, tHD;DAT and tBUF are not checked; no clock stretching rule (a stretched low is just a long tLOW).
  • UART: 8 data bits, no parity; bit times of 50 ticks or more (the report of a short stop must fit in half a bit); a glitch that falls on a sample point is taken as a data bit, not reported.
  • The log keeps the last 8 violations; counters stop at 255.
  • Simulation only: no board, no gate-level run.
