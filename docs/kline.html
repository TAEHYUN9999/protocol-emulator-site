File Role Words
firmware/kline.pe Hart 0 is a diagnostic tester: ISO 9141-2 5-baud initialization (address at 5 bit/s, sync 55h and key bytes in their W windows, the inverted KB2 after W4, the inverted address checked), ISO 14230 fast initialization (25 ms low, the request 50 ms after the first fall) with StartCommunication, and requests with the checksum, P4 between bytes and the answer read with the P2 and P1 limits. Hart 1 is an ECU: tells a 5-baud start bit and a fast-init low from bytes by their length, answers both inits, and answers requests (service + 40h) with the ISO 9141-2 or ISO 14230 header and the checksum after P2. The two pins sit on the one K-Line. 460 of 512 (hart 0 195, hart 1 237, 28 shared)

No RTL change: existing instructions only (twait grids of a millisecond unit and of a bit, low/rel, shout.lsb.od, shin/shin.lsb, waitp.to, ld/st, host FIFO). Checked in simulation only, not on a board.

Pins

Pin Use
P0 tester, open drain on the K-Line
P1 ECU, open drain on the K-Line

Both pins go on the one K-Line (at logic level: a pull-up; on a vehicle, each through a K-Line transceiver). A node does not check its own echo.

Timing

All slow times are counted in units of MSU ticks (data memory 0x00, 0x01; 0 = 25,000 ticks = 1 ms) and bits are BIT ticks (0x02, 0x03; 0 = 2,404 ticks = 96.16 us, 10,399 baud, -0.01 %). The tests run most cases at 1/50 of real time (MSU 500, BIT 48), which keeps every ratio, and the fast init once at real time.

Time Tester ECU ISO range

5-baud bit 200 units (+0.02 % from code between the waits) read in its middle 5 bit/s +-0.5 %
W1 address to sync accepts 60..255 units 100 units 60..300 ms
W2, W3 accepts up to 20 10, 10 5..20, 0..20 ms
W4 (both) 30 before the inverted KB2; accepts up to 50 for the inverted address 30 25..50 ms
TiniL, TWuP 25 and 50 units 22..28 units taken as a fast init 25 +-1, 50 +-1 ms

P2 request to answer accepts up to 50 20 units of silence end the request, then 10 more: 30 25..50 ms
P1 ECU inter-byte accepts up to 20 2 units 0..20 ms

The ECU waits for a falling edge and reads a byte from it; a byte whose stop bit is 0 means a long low, and the ECU counts the units until the line rises: 22..28 in all is a fast init, 150 or more a 5-baud start bit (whose bits it then reads every 200 units), anything else is counted and ignored.

Host interface

Tester (hart 0):

Command Bytes Answer
5-baud init 01 a status, KB1, KB2; status 0 good, 1 no sync, 2 sync not 55h or too early, 3 no key bytes, 4 no inverted address or a wrong one
Fast init and StartCommunication C1 33 F1 81 66 02 status, n, the n answer bytes
Request 03 n d1..dn (the checksum is added) status (0 good, 1 no answer, 2 wrong checksum), n, the n answer bytes

ECU (hart 1), data memory: 0x06, 0x07 5-baud key bytes (0 = 08h 08h); 0x08 its address (0 = 10h); 0x09, 0x0A two data bytes put after the parameters of every answer; 0x0B header form (set by the init: ISO 14230 after a fast init or KB2 8Fh); counters 0x10 5-baud inits, 0x11 fast inits, 0x12 answers, 0x13 wrong checksums, 0x14 other lows. Answers: StartCommunication (81h) gets C1h E9h 8Fh; any other service s gets s + 40h, the request's parameters and the two data bytes; a request with a wrong checksum gets nothing.

Tests

test/test_kline.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_kline

The models are written from the sources above, not from the firmware: a wired-AND K-Line that records every level and the chip's drives, a byte sender and receiver, a tester model (W5, the address at 5 bit/s, the inversions, requests with P4) and an ECU model that tells a 5-baud start bit, a fast-init low and a byte apart by the low's length and answers with its own W and P times (W1 170, W2 8, W3 5, W4 28, P2 28, P1 3 units). Only pins, host commands and data memory addresses come from the firmware header.

Limits

  • The tester accepts the sync up to 255 units after the address (W1 allows 300).
  • ISO 9141-2 messages are told apart by the 20-unit gap (P1 max), not by a length; the ISO 14230 length byte form (L = 0) and the header without addresses are not decoded by the ECU, which takes the service from the fourth byte.
  • No echo check, no P3 maximum (session time-out), no StopCommunication, no ISO 9141-2 L-line.
  • The answers are a fixed pattern (service + 40h, the parameters, two data bytes), not real OBD data.
  • Most timing checked at 1/50 of real time; at real time only the fast init path.
  • Simulation only: no board, no gate-level run.
