File Role Words
firmware/sgpio.pe Hart 0 is an SGPIO initiator: SClock at 100 kHz (or slower), bit streams of 4 to 16 drives with three SDataOut bits per drive (activity, locate, fail), SLoad with the vendor bits L0..L3 and the end-of-stream mark, SDataIn latched per drive; drive bits changed by host bytes while it runs. Hart 1 is an SGPIO target: syncs on five SLoad 0s and a 1, latches SLoad and SDataOut at the falling edge, applies each whole stream at its end (data memory, gpo pins for drives 0 and 1, host reports), sends three SDataIn bits per drive, turns every indicator off on the reset level. The two harts on the same four pins are a loopback. 240 of 512 (hart 0 84, hart 1 156)

No RTL change: existing instructions only (twait grid, low/rel, shout.lsb.od, shin/shin.lsb, waitp.to, rdp, gpo, ld/st with a register address, host FIFO). Checked in simulation only, not on a board.

Source

SFF-8485 is free from SNIA, so the original was read: "SFF-8485 Specification for Serial GPIO (SGPIO) Bus", Rev 0.7 (published 2006), from the SNIA SFF specification page.

Pins

Pin Initiator (hart 0) Target (hart 1)
P0 SClock, open drain SClock in
P1 SLoad, open drain SLoad in
P2 SDataOut, open drain SDataOut in
P3 SDataIn in SDataIn, open drain
uo[2..7] indicators of drives 0 and 1 (activity, locate, fail each)

Each pin is written by one hart only, so the two harts share the four pins without any outside wire (docs/jtag_tap.md, "Two harts on one chip"). The bus needs pull-ups (2 k in SFF-8485).

Timing

Initiator: one period of the twait grid is half an SClock period (data memory 0x12/0x13, default 125 ticks). Both SClock edges come two ticks after a grid boundary, so the high and low times are exactly the half period (250 clocks at 100 kHz). After the rise it puts out the drive's next SDataOut bit and the SLoad bit; one tick before the fall it latches SDataIn. After the third bit of a drive it compares the drive's SDataIn bits with the last ones and takes one host byte; this fits in the low half period.

Target: it waits for each SClock edge with waitp.to in steps of 25,186 ticks (tsetr 0x62, 0x62, 1.0074 ms). After a rise it puts out the next SDataIn bit; after a fall it reads SDataOut and SLoad. A step that ends with SClock high and SLoad and SDataOut also high counts towards the reset (data memory 0x1A, default 64 steps = 64.5 ms); the count restarts on any other level. At the end of a stream (the bit with SLoad 1) it copies up to 16 drive bytes and drives gpo before the next rise; at 100 kHz with 16 drives this takes most of the 5 us low time.

Host bytes to the initiator: d << 3 | bits sets drive d (0..15), 0x80 | L sets the L bits. One byte is taken after each drive; a drive's bits are read when its turn comes, the L bits at the start of a stream. Chip to host: the initiator sends d << 3 | IDn bits when a drive's SDataIn bits change, the target d << 3 | ODn bits when a drive's indicators change. Both use txb.nb so that SClock never waits for the host: a report that finds the FIFO full is dropped (the data memory always holds the current bits).

Tests

test/test_sgpio.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_sgpio

The models are written from SFF-8485, not from the firmware: a stream encoder (Figure 7 bit numbering, L bits, SLoad 1 in the last bit), a decoder that syncs like a target (five 0s then 1) and returns each whole stream, a target model that latches at falling edges and drives SDataIn right after rising edges, an initiator model with chosen high and low times and change points, and a timing check that measures every SClock period and half and every data line change against the previous and next falling edge (Table 5). Only the pins, the host bytes and the data memory addresses come from the firmware header.

Limits

  • The initiator sends at most 16 drives per stream and the target stores 16 (it counts and releases SDataIn beyond); SFF-8485 allows more with port multipliers.
  • The initiator does not keep L0 at 0 in the first stream after power on (7.3 "should not"); the target does not need it, because it syncs only on five 0s and a 1.
  • The reset time-out was measured with 2 steps; the default of 64 steps (64.5 ms) follows from the measured step and was not simulated in real time.
  • Host reports are dropped when the FIFO is full; SClock never stalls for the host.
  • Simulation only: no board, no gate-level run.
