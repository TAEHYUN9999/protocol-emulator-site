File Role Words
firmware/nmea.pe Hart 0 reads the NMEA 0183 sentences of a GPS receiver from a UART (8N1, 115200 bit/s by default), one character at a time: XOR checksum, RMC (time, status, date) and GGA (time, fix quality, satellites) values, counters for other sentences and errors. Hart 1 measures the PPS pulse: period and high time in 400 ns slots and a pulse count; every accepted RMC or GGA is stored with the PPS count at that moment. 306 of 512 (hart 1 from word 264)

No RTL change. Checked in simulation only.

Pins and data memory

Pin Use
P0 RX: the receiver's TX, idle high
P1 PPS input
Address Content
0x00-0x02 PPS period in slots (low byte first)
0x03-0x05 PPS high time in slots
0x06 PPS rising edges seen (mod 256), stored one slot after the period
0x08-0x0C counters: RMC, GGA, other sentences accepted, checksum errors, format errors (stop bit low, '$' inside a sentence, a bad hex digit)
0x10-0x17 RMC: hour, minute, second, status character, day, month, year, PPS count when accepted
0x18-0x1D GGA: hour, minute, second, fix quality, satellites, PPS count
0x1E-0x1F UART bit time in ticks, high byte first (DATA_W before the run; 0 = 217, 115200 bit/s; 651 = 38400; 2604 = 9600)
0xA0-0xAF work bytes of hart 0

How it works

Hart 0 finds each start bit with waitp, samples the 8 bits in their middles on a tsetr grid and checks the stop bit. Every character is handled before the next start bit can come (at most about 45 ticks after the stop bit sample; half a bit at 115200 bit/s is 108 ticks), so sentences can come back to back: '$' starts a sentence (and clears its work bytes; a '$' inside a sentence counts a format error), the XOR runs over every character up to '*', commas count the fields, the three letters after the talker give the type, and the digits of the wanted fields become binary values as they arrive (two digits per value for hhmmss and ddmmyy, n = 10 n + digit for the satellites). After the second checksum digit a good RMC or GGA is copied to the results with the PPS count; CR and LF are ignored.

Hart 1 samples PPS once per 10-tick slot (twait grid) and counts slots in 24 bits; every path through a slot, including the edge bookkeeping, takes fewer than 10 instructions, so the grid never slips (late flag 0). The period is the number of slots from one rising edge seen to the next, the high time from a rising edge to the falling edge seen: each is exact to the slot when the edges keep their phase, and within one slot otherwise. 24 bits hold 6.7 s; one second is 2,500,000 slots.

Tests

test/test_nmea.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_nmea

The sentence model builds each sentence from the description above with its own XOR; the expected values come from the field strings. The UART sender is 8N1 LSB first. The PPS generator makes pulses with a given period and high time. One second of PPS (25 million ticks) is too long to simulate, so the PPS periods are 1 to 30 ms; the counting is the same.

Limits

  • RMC and GGA values only (no latitude, longitude, speed); other sentences are only counted.
  • Talker IDs are not checked (GP, GN, GL, ... all accepted); upper-case checksum digits only.
  • The PPS resolution is one 400 ns slot.
  • One second of PPS was not simulated.
