firmware/display.pe Hart 0 drives a MAX7219 LED driver (16-bit packets D15 first, data shifted on CLK rising edges, latched by the rising edge of LOAD after the 16th clock); hart 1 drives a TM1637 LED driver on two open-drain lines (START/STOP, bytes LSB first, the ninth clock for the ACK, data command, address command with up to 6 bytes, display control). Hart 0 also reads the host FIFO for hart 1 and hands each TM1637 frame over through the data memory, so both displays run at once on 5 pins. 115 of 512 (hart 1 from word 48)
firmware/hd44780.pe Hart 0 drives an HD44780U character LCD in 4-bit mode (RS, E, DB4..DB7; R/W tied low): the initialization by instruction of Figure 24 with its waits after power on, every instruction followed by its execution time, an E pulse of 480 ns; host characters, line 2 and clear. 95 of 512

No RTL change: tset/twait, shout/shout.lsb.od, low/high/rel, woe, shin, the host FIFO. Checked in simulation only, not on a board.

The 40 us and 1.80 ms waits cover a slower internal oscillator (Table 6 notes that execution times scale with fosc; 37 us at 270 kHz is 40 us at 250 kHz).

Tests

test/test_display.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_display

The device models are written from the data sheets, not from the firmware. MAX7219: the recorded DIN, CLK and LOAD are replayed through a 16-bit shift register clocked on CLK rising edges, latched on LOAD rising edges (exactly 16 rises since the previous latch), into the register file; every timing parameter of the table is measured. TM1637: a live device that decodes START and STOP, takes bits on CLK rising edges, pulls DIO low from the 8th clock's fall to the 9th clock's fall (or not, for a planted missing ACK), keeps the display RAM and the control byte, and the clock and data timing measured. HD44780: the recorded RS, E and DB4..DB7 are replayed on E falling edges through the Figure 24 sequence (8-bit function sets, then pairs of nibbles), with every E pulse timed against the write timing table, every instruction's start timed against the execution time of the one before, and a DDRAM model with the address counter.

Controls

Each control is a copy with one planted bug, run with DISP_FW=<path> or LCD_FW=<path>.

All four fail at the check they aim at.

Limits

  • MAX7219: one device (no daisy chain of several packets per LOAD); the host sends the initialization (shutdown, test, scan limit, decode, intensity).
  • TM1637: write only (no key scan read), auto-increment mode, grids from address 0; the brightness is a data memory byte read for each frame, so changing it needs a stop and DATA_W. The host FIFO has one reader, hart 0, which is why it passes the TM1637 frames on: the two harts cannot both wait on the FIFO.
  • HD44780: R/W tied low, so the busy flag is not read and every instruction waits the longest execution time; no CGRAM, cursor or shift commands from the host.
  • HD44780: until the chip drives E after reset the line floats (high with the pad pull-ups). The firmware drives RS and DB4..DB7 low before E, so that first fall latches 0x0 with RS low, which is no instruction; a pull-down on E avoids the edge.
  • Simulation only: no board, no gate-level run.
