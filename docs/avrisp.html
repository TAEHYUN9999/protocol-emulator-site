firmware/avrisp.pe Hart 0: an ATtiny85 seen by an ISP programmer (Programming Enable with the echo, signature, fuses, lock bits, calibration byte, flash read, Load Program Memory Page, Write Program Memory Page, Chip Erase, fuse and lock writes, RDY/BSY with the tWD times). Hart 1: a programmer run by host commands (power-up RESET sequence, 20 ms, Programming Enable with retries, Chip Erase, page writes and reads, RDY/BSY polling, any four-byte instruction). 435 of 512 (hart 1 starts at word 267)

This protocol was not part of the design when the RTL was written. It uses only existing instructions (shin as a pin test, shout, low/high/rel, tset/tsetr/twait, tgeth/tgetl, the host FIFO, ld/st on the data memory and the frame buffer); the RTL is unchanged. The two harts use the same four pins, so the programmer can program the target on one chip. Checked in simulation only, not on a board.

Section and table numbers are those of the Atmel ATtiny25/45/85 data sheet (2586Q-AVR-08/2013).

Timing

The target polls RESET and SCK with shin (four ticks per poll), so its timer runs the busy times. Busy times longer than the 16-bit timer (65535 ticks, 2.62 ms) are a first period plus whole 65535-tick periods, renewed in the SCK-low wait; a period that ends while SCK is high is renewed up to half an SCK period late. MISO follows the SCK fall within 0.30 us (15 clocks measured; tSLIV is 100 ns), so SCK may go up to about 1 MHz on the pins, more than the 250 kHz an ATtiny85 at 1 MHz accepts.

After Write Program Memory Page the target copies the 64-byte page buffer into flash (AND) and refills it with FFh, and after Chip Erase it fills 128 bytes: it does not watch SCK for about 26 us and 21 us. An instruction that starts within that time is lost and the framing with it; a programmer that polls RDY/BSY must leave that gap (this programmer waits 100 us before the first poll; one that waits tWD_FLASH needs nothing). Instructions other than RDY/BSY that arrive while busy are ignored and counted.

Host interface

Programmer commands (FIFO) and answers: 01h enter [status, echo] (status 0, or 1 when four tries got no echo); 02h a b c d any instruction [fourth byte back]; 03h Chip Erase and polls [status, polls] (status 2 after 255 busy polls); 04h p and 64 bytes, page p written [status, polls]; 05h p page p read [64 bytes, low then high per word]; 06h leave [0].

Controls

Each change was made in a copy of avrisp.pe and run with AVR_FW pointing at it. All fail, each at the check it aims at:

Change Test Caught by
Target never echoes 53h test_avr_target_session Programming Enable answered 00h in the third byte
Target page write replaces instead of AND test_avr_target_rules the second write without erase is not an AND
Target without the busy check test_avr_target_rules the load sent while busy is not counted (and not ignored)
Programmer loads the high byte before the low byte test_avr_programmer the page read back differs (each word took the previous low byte)
Programmer waits 5 ms after the RESET pulse test_avr_programmer RESET to the first SCK rise 250288 clocks, below 20 ms
Programmer tries Programming Enable once test_avr_programmer enter answers [1, FFh] after the model's first, unsynchronized session

Limits

  • Flash words 0 to 63 (pages 0 and 1) are stored; other pages read FFh and their writes only take the busy time. No EEPROM.
  • The target is deaf for about 26 us after a page write and 21 us after a Chip Erase (see Timing).
  • MISO valid about 0.30 us after the SCK fall instead of 100 ns.
  • A busy time keeps running only while the target sees RESET low (its SCK wait renews the timer).
  • Simulation only: no board, no gate-level run.
