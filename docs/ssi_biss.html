File Role Words
firmware/ssi.pe Hart 0 is an SSI master: it clocks NTOT + 1 pulses, samples at the falling edges, checks the monoflop (data low after the frame, high again after tm, which it measures), decodes Gray code and the error bit. Hart 1 is an SSI absolute encoder: it loads its position at the first falling edge, puts out the bits MSB first at the rising edges, holds data low for tm, then moves by a host-set step per frame. 191 of 512 (master 91, encoder 100)
firmware/biss.pe Hart 0 is a BiSS-C master: frame start, LAT, search for ACK (line delay) and the start bit (processing time), CDS, position, nE/nW, CRC6 check, stop, the slave's timeout measured. Hart 1 is a BiSS-C position encoder (BP1-like single-cycle data): ACK, optional busy clocks, start bit, CDS, position, nE/nW, inverted CRC6 (x^6 + x + 1, start 0), stop bit, 20 us timeout. 251 of 512 (master 122, slave 129)

No RTL change: existing instructions only (twait grid for the masters' clocks, waitp.to with the timer for the slaves' edge waits and timeouts, shout/shin, the CRC unit with a left-aligned 6-bit polynomial, waitp.to.frz to time tm and the timeout). Checked in simulation only.

Pins

ssi.pe biss.pe Default Use
CLK MA P0 clock, driven by the master (hart 0), read by the slave (hart 1)
DAT SLO P1 data, driven by the slave, read by the master

With both harts running, one chip reads its own encoder. With one hart, the other end is external (the tests use models on the same pins).

SSI

Frame: NBITS position bits (Gray code with GRAY = 1) and an error bit with EBIT = 1, NTOT bits in all (24 at most). Default 23 bits Gray plus the error bit; {"NBITS": 13, "EBIT": 0, "GRAY": 0, "NTOT": 13, "FIRSTB": 5, "PRESH": 11, "MSK1": 0, "MSK2": 0x1F} is a 13-bit binary encoder. FIRSTB, PRESH and MSK1..3 follow from the other constants (the header says how).

Master (hart 0): any host byte reads one frame with HALF ticks per clock half (25: 500 kHz; 13: 961.5 kHz). It waits up to 50 us for DAT high, clocks NTOT + 1 pulses (both halves exactly HALF ticks), samples DAT a few ticks after each falling edge, checks that DAT is low half a period after the last rising edge, and times DAT going high (tm, data memory MTMH:MTML in ticks). Report: flags (bit 0 error bit, bit 1 DAT not low after the frame, bit 2 not high within 40 us, bit 3 not high before the frame), position (3 bytes, binary).

Encoder (hart 1): position POS (3 bytes), STEP (signed, added after each frame, modulo 2^NBITS), EFLAG (the error bit) in data memory. The frame bits are prepared after each frame (Gray code, error bit, left aligned), loaded at the first falling edge and shifted out with shout one tick after each rising edge is seen; after the last bit DAT is 0. When the clock has been still for 15 us (TMO) the next frame is prepared and DAT goes high: tm 17.7 to 17.8 us with the default format.

BiSS-C

Frame at the slave, rising edges after LAT: ACK 0, BUSY zeros, start 1, CDS, NPOS position bits, nE, nW, the CRC6 of position, nE and nW inverted, stop 0, then 0 at any further edge. NPOS is 24 by default; {"NTOP": 2, "SH1": 6, "MSK1": 3} gives 18 bits (NPOS = 16 + NTOP).

Master (hart 0): any host byte reads one frame with HALF ticks per clock half; both halves are HALF ticks (edges two ticks after each boundary). SLO is sampled one tick before each rising edge, so a bit put out at one rising edge is read just before the next, and a slave delay up to almost one period is taken as it is. After LAT the master clocks up to NACK = 20 periods for ACK (longer line delays shift the frame by whole clocks) and up to NSTART = 40 for the start bit, then CDS, the position, nE, nW and the CRC (fed to the CRC unit bit by bit); the rising edge after the last CRC bit is the stop bit edge and MA then stays high. It times SLO going high (MTOH:MTOL, ticks from the stop bit edge) and reports flags (bit 0 CRC wrong, 1 nE = 0, 2 nW = 0, 3 CDS, 4 no ACK, 5 no start bit, 6 SLO not high within 60 us, 7 SLO low before the frame) and the position. MACK counts the clocks from LAT to the ACK sample (2 with no line delay).

Slave (hart 1): POS, STEP, SFLG (bit 1 error, bit 0 warning), CDSV (bit 0) and BUSY in data memory. Each bit goes out with shout one tick after its rising edge is seen; when MA has been still for 500 ticks (20 us) SLO goes high: 20.6 us measured from the last rising edge. The CDM bit is not read.

Tests

test/test_ssi_biss.py, run from a private directory:

T=<repo>/test; R=$T/sim_build/<name>; mkdir -p $R; cd $R
PYTHONPATH=$T make -B -f $T/Makefile PWD=$T SIM_BUILD=$R/build COCOTB_TEST_MODULES=test_ssi_biss

The models are written from the sources above, not from the firmware: an SSI master that clocks and samples at the falling edges, an SSI encoder that loads at the first falling edge and answers each rising edge after a delay, a BiSS master that samples at the end of every low half and searches ACK and start, a BiSS slave with a line delay, busy clocks, flags and a timeout, Gray code from its definition (checked against SICK table 1) and the CRC6 from its polynomial (a frame plus its CRC leaves remainder 0). Only pins, host bytes and data memory addresses come from the firmware headers.

Limits

  • Clocks up to 961.5 kHz from the masters (HALF 13); the slaves were checked at 1 MHz. Both lines are logic level (RS-422 transceivers are outside).
  • SSI: one error bit at most, 24 bits in all; no multi-turn double transmission; the encoder needs the clock interval to be longer than tm plus about 1 us after a frame.
  • BiSS: point to point, one slave, sensor data only: no CDM/CDS register access (CDS is a constant, CDM is not read), no adaptive timeout, no daisy chain, no actuator data; the master's sample point is fixed one tick before the rising edge (the line delay is handled by whole extra clocks, not by moving the sample point).
  • Positions move by a fixed step per frame; there is no real time motion between frames.
  • Simulation only: no board, no gate-level run.
